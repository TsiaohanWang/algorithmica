意外的是，这个问题能通过略加修改的归并排序解决。保留同样的思路。设我们能在大小为 $n$ 的数组里求逆序数，则学会在大小为 $2n$ 的数组里求。

注意我们已知左半与右半数组里的逆序数。剩下只需数「一个数在左半、另一个在右半」的逆序个数。

仔细看左、右两半的 merge 操作（前面用内置 merge 代替）。第一个指针指向左半的元素，第二个指针指向右半的元素，我们看较小的那个并把对应指针右移。

考虑左半的数 $A$。它参与了多少个跨半逆序？等于右半中比它小的数的个数。我们知道这个数吗？知道！恰好在我们把 $A$ 写入合并数组的那一刻——第二个指针正指向右半中第一个比 $A$ 大的数。

因此在从左半加数 $A$ 的时刻，把第二指针下标（减右半起点）加到答案上。这样我们就统计了所有跨半逆序。

### 函数 Merge

来学习下 <em>合并</em>（merge）两个已排序数组。它是归并排序的核心，也单独用在很多算法中。

最简单的方法是双指针。第一个指针指向第一个数组的开头，第二个指向第二个数组开头。从两个指针所指的当前元素中选较小的，放到新数组对应位置，并移动对应指针。继续直到两个数组都耗尽。

```cpp
void merge(int a[], int n, int b[], int m, int c[]) {
    int i = 0, j = 0, k = 0;
    while (i < n && j < m) {
        if (a[i] < b[j]) {
            c[k++] = a[i++];
        } else {
            c[k++] = b[j++];
        }
    }
    while (i < n)
        c[k++] = a[i++];
    while (j < m)
        c[k++] = b[j++];
}
```

此处用了两个独立指针 $i, j$ 分别遍历两个数组。在合并时只需比较两个指针指向的当前元素，并把较小者写入结果。这种写法简单、且在 $O(n + m)$ 内完成。

双指针法也适用于更一般的「多路归并」——比如有 $k$ 个已排序数组要合并。用最小堆维护当前最小元素，时间 $O(N \log k)$。

如果需要原地合并（不借用额外数组），可用[原地归并](https://neerc.ifmo.ru/wiki/index.php?title=%D0%A1%D0%BB%D0%B8%D1%8F%D0%B0%D0%BD%D0%B8%D0%B5_%D0%B2%D0%BE%D0%B4%D0%B0_%D0%B2_%D0%BC%D0%B5%D1%81%D1%82%D0%B5)，但代码更复杂且常数大。

### 复杂度

计算归并排序的时间复杂度。

**第一种证明 - 直观的**

回顾前面的例子。注意每一层都包含相同数量的元素，每一层发生一系列 merge 操作，但所有层级上所有 merge 的总操作数是 $O(n)$，因为 merge 的时间与层上元素数成正比。现在估计层数。每层待排序块的大小大约减半，因此层数是 $O(\log n)$。总计 $O(n \log n)$。

**第二种证明 - 递归式**

设 $T(n)$ 为排序长度为 $n$ 数组的时间。归并排序有 $T(n) = 2T(n/2) + O(n)$，$O(n)$ 是合并两个长度为 $n$ 的数组所需时间。展开：

$T(n)=2T(n/2)+O(n)=4T(n/4)+2O(n)=\ldots=T(1)+\log(n)O(n)=O(n\log n).$
