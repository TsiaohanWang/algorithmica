Berge 引理指出，没有增广链的匹配是最大匹配。

它的一个重要推论是：最大匹配可以增量地构建——每一步找一条增广链并做交替翻转。

**Kuhn 算法**正是如此——从空匹配开始，只要还能找到就不断找增广链。

要找增广链，可以心算构建一个图：从右部到左部只能走匹配的边，从左部到右部可以走任意边。然后在这个改造后的图中，找一条从左部自由顶点到右部某个自由顶点的路径，这条路径就是增广的。

这可以用任何方式做——为练习，作者建议显式构建这样的图、用喜欢的搜索算法找路径、显式做交替翻转——但一个有效的约 20 行 dfs 实现已成为标准做法，如下。

```c++
const int maxn;

vector<int> g[maxn]; // 只存从左部到右部的边
int mt[maxn]; // 右部顶点与哪个顶点匹配（-1 表示没匹配）
bool used[maxn]; // 用 dfs 找路径的辅助数组

// dfs 返回能否从顶点 v 找到
// 一条到右部某顶点的路径
// 如果可以，还会做交替翻转
bool dfs(int v) {
    if (used[v])
        return false;
    used[v] = true;
    for (int u : g[v]) {
        // 如果顶点空闲，可以直接连它
        // 如果被占，只有在其当前配对能再找到
        // 另一个顶点时才能连
        if (mt[u] == -1 || dfs(mt[u])) {
            mt[u] = v;
            return true;
        }
    }
    return false;
}
```

现在，为求匹配本身，只需对左部所有顶点运行这个搜索，每次回滚辅助数组 `used` 的状态：

```cpp
memset(mt, -1, sizeof mt);
for (int i = 0; i < n; i++) {
    memset(used, 0, sizeof mt);
    if (dfs(i))
        cnt++;
}
```

算法恰好找 $n$ 次增广路，每次至多查看 $m$ 条边，因此总计运行在 $O(nm)$。

### 优化

值得注意的是，在更大的限制下（$n, m \approx 10^4$）也无需害怕运行这个算法，只要做一些非渐近的优化：

- 匹配可以贪心初始化——例如，预先遍历左部顶点，把它们与右部某个空闲顶点匹配（如果存在）。
- 不必每次迭代把 `used` 数组清零，可以用下面的技巧：不用布尔标志，而是存最后一次修改的版本号，具体说是让它变成 `true` 的迭代编号。如果这个编号小于当前迭代编号，就可以把它当作 `false`。某种意义上，这让我们在常数时间内「模拟」数组清零。
- 很多时候图来自某个其他问题，其性质对图的结构有限制。例如，在格点问题里（有二维数组、相邻格子相连），图是二分图，但每个顶点度数很小，图有很特定的结构。在这种图上，Kuhn 算法往往比 $n \times m$ 的公式预期的更快。这类问题的反例几乎总能构造出来，但出题人很少费这个劲。

更多关于优化的讨论见[这里](https://codeforces.com/blog/entry/17023?locale=ru)，但一般而言不必过分追求加速 Kuhn 算法，因为存在渐近更快的算法。最大匹配问题是最大流问题的特例，如果把[Dinic 算法](http://e-maxx.ru/algo/dinic)应用到单位容量的二分图上，运行时间是 $O(m \sqrt n)$。
