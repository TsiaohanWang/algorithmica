## 0-1 背包

背包问题最简单的形式表述如下：

给定 $n$ 件物品，重量分别为 $a_1,\\dots, a_n$。求出在容量为 $W$ 的
背包中最多能装入多大总重量的物品。

用动态规划解决该问题。用 $dp\[i\]\[j\]$ 表示状态：已经考虑前
$i$ 件物品且装入了 $j$ 的重量。若该情形可行，则
$dp\[i\]\[j\]=True$，否则 $dp\[i\]\[j\]=False$。

对于每个可达的状态 $dp\[i\]\[j\]$，我们可以选择取编号 $i$ 的物品，
并尝试从 $dp\[i - 1\]\[j - a\[i\]\]$ 更新答案；或者不取它，从
$dp\[i - 1\]\[j\]$ 更新答案。显然，考虑 0 件物品时我们可以得到 0 重量。

``` C++ numberLines
for (int i = 1; i <= n; i++) {
    for (int j = 0; j <= W; j++) {
        dp[i][j] = dp[i - 1][j];
        if (a[i] <= j) {
            dp[i][j] = (dp[i][j] | dp[i - 1][j - a[i]]);
        }
    }
}
```

问题的答案就是最大的 $j$，使得 $dp\[n\]\[j\]$ 为
$True$。该解法的时间复杂度为 $O(nW)$。

### 降低内存开销

注意，实际上一维数组 $dp\[w\]$ 就够了，它存储能否凑出相应重量。初始时
其中全是 0，然后逐一添加物品并重新计算数组的值：尝试用新物品凑出
重量 w，当然前提是之前没能凑出重量 w。

该算法的时间复杂度仍为 $O(nW)$，因为对每件物品我们都要枚举所有重量，
并尝试用这件物品凑出它。

### 非渐近地降低时间开销

注意，我们没必要每次重新检查已经能凑出的那些重量。预先再维护一个
$unreachable$ 向量，存放尚未能凑出的重量，初始时包含从 $1$ 到 $W$
的所有重量（重量为 0 我们总能凑出）。每一步添加一件新物品，并枚举
$unreachable$ 中的重量，如果某个重量可以被凑出，就把它从向量中删掉：
与最后一个元素交换并执行 pop_back。由于 $unreachable$ 中重量的顺序
无关紧要，可以随意交换其中的元素。

## 带价值的背包

现在每件物品都有价值 $c_i$。目标不再是装尽可能大的重量，而是装尽可能
大的总价值，同时物品的总重量不超过背包容量。

修改 $dp\[i\]\[j\]$ 的含义。令它等于在前 $i$ 件物品中选取、总重量为 $j$
时可获得的最大价值。
动态规划的遍历顺序不变，但状态更新方式改变：如果不取当前物品，那么答案
不差于前 $i-1$ 件物品的答案；如果取，则留给前面物品的空间只剩
$j - a\[i\]$，但要把新物品的价值加到答案上。

``` C++ numberLines
dp[i][j] = dp[i - 1][j];
if (a[i] <= j) {
    dp[i][j] = max(dp[i][j], dp[i - 1][j - a[i]] + c[i]);
}
```

如果重量很大而价值很小，可以把它们互换：改为计算在给定价值下所需的最小
重量。把动态规划的值和参数互换是动态规划中相当常见的技巧。

## 物品数量受限的背包

现在每种物品可能有多件，也就是说不仅给出重量和价值，还给出每种物品的
最大数量 $k_1,\\ldots,k_n$。那么对每个状态
$dp\[i\]\[j\]$ 枚举取了多少件该种物品，并从对应的各个状态进行转移。
显然，每种物品最多取 $\\lfloor\\frac{W}{a_i}\\rfloor$ 件。

``` C++ numberLines
for (int i = 1; i <= n; i++) {
    for (int j = 0; j <= W; j++) {
        dp[i][j] = dp[i - 1][j];
        if (a[i] <= j) {
            for (int cnt = 0; cnt <= k[i]; cnt++) {
                dp[i][j] = max(dp[i][j], dp[i - 1][j - a[i] * cnt] + c[i] * cnt);
            }
        }
    }
}
```

该解法的时间复杂度为 $O(nW^2)$，因为 $k_i$ 可能非常大，而 $a_1=1$。

可以尝试在 $O(nW\\log K)$ 时间内解决该问题，其中 $K$ 是
$k_i$ 的最大值。

## 物品数量无限的背包

现在每种物品的数量不再是 $k_i$，而是无限的。
问题反而变得更简单了。回到普通的带重量和价值的背包，唯一区别是
现在第二次转移不再从前一行进行，而是直接从当前行进行。
同时要注意，对每个状态只需考虑取一件该种物品，因为取两件及以上
会在之后的迭代中一并被考虑到。

``` C++ numberLines
for (int i = 1; i <= n; i++) {
    for (int j = 0; j <= W; j++) {
        dp[i][j] = dp[i - 1][j];
        if (a[i] <= j) {
            dp[i][j] = max(dp[i][j], dp[i][j - a[i]] + c[i]);
        }
    }
}
```

该解法的时间复杂度为 $O(nW)$。

如果 $W$ 很大而 $a_i$ 足够小，可以构造 $O(n + A^3)$ 的解法，其中 $A$ 是
$a_i$ 的最大值。注意到，若 $W$ 足够大，那么背包的大部分空间会被
同一种单件价值密度最高的物品占据。可以证明，同一种物品至少会占据
$W-A^2$ 的重量。于是可以先在 $O(n)$ 时间内选出单位重量价值最高的物品，
对其余物品运行之前的算法，其复杂度为 $O(A^3)$，因为只需考虑至多 $A$ 件物品，
而最大重量为 $A^2$。

## 还原答案

在以上所有问题中，还原答案都按标准方式完成：从最终答案一路回溯到开头。

  - 第一种方法：构造 prev 数组，对每个格子
    $dp\[i\]\[j\]$ 记录我们是否取物品 $i$。
  - 第二种方法：在回溯时现场判断，看 $dp\[i - 1\]\[j\]$ 与
    $dp\[i - 1\]\[j - a\[i\]\] + c\[i\]$ 哪个更大。

如果有 $n$ 件物品，重量分别为 $w_1, w_2, \\ldots, w_n$，
且 $w_1 + w_2 + \\ldots + w_n = S$，那么可以用标准动态规划在 $O(Sn)$
时间内解决背包问题。如何更快？尝试让 $n$ 变为 $O(\\sqrt{S})$。

注意到，$w_1, w_2, \\ldots,
w_n$ 中不同重量的数量为 $O(\\sqrt{S})$，因为如果其中有 $k$ 个不同的
数，那么 $S = w_1 + w_2 + \\ldots + w_n \\geq 1 + 2 + \\ldots +
k = \\frac{k(k + 1)}{2}$，因此 $k \\leq \\sqrt{2S}$。

考虑某个在重量集合中出现的重量 $x$。记 $c$ 为它的出现次数。取最大的
自然数 $t$，使得 $2^t - 1 \\leq c$。那么把重量集合中 $c$ 个 $x$ 替换为
$x, 2x, \\ldots, 2^{t-1}x, (c+1-2^t)x$。容易看出，所有总和 $0, x,
\\ldots, cx$ 仍然可以凑出，且只能凑出这些。

现在已经很容易看出，新的重量数量为
$O(\\sqrt{S}\\log{S})$，因为对每个重量我们保留了 $\\leq
\\log{S}$ 个重量，而不同重量有 $O(\\sqrt{S})$ 个。为了得到所需的估计，
看看哪些 $x$ 被替换成了 $\\geq p$ 个重量（其中 $p \\geq 2$）？我们总是
加入 $t+1$ 个数，即 $p-1 \\leq t$，也就是 $2^{p-1} \\leq 2^t \\leq с+1$。
因此这类 $x$ 中每个的出现次数都 $\\geq 2^{p-1}-1$，它们的总和 $\\leq
\\frac{S}{2^{p-1}-1} \\leq \\frac{4S}{2^p}$，因此数量 $\\leq
\\sqrt{8S} \\frac{1}{\\sqrt{2}^p}$（因为它们都互不相同，如我们所知）。
所以总加入量 $\\leq \\sqrt{8S}
(\\sum\\limits_{p=2}^{\\log{S}}{\\frac{1}{\\sqrt{2}^p}})$ 个数，这是
$O(\\sqrt{S})$。

**Bonus：**如果再用 bitset 来做背包，就能得到
$O(\\frac{S\\sqrt{S}}{64})$ 的解法。
