在编程题目中，图的顶点通常用从 $0$ 到 $(n-1)$ 的数字编号，这样把它们当作各种数组的下标来使用会很方便。

在题目中，图最常见的给出方式是一个包含所有边的列表，需要从输入中读取。用什么格式存储图最优？视题目不同，有几种方式。

### 边列表

有时只需存储输入给出的边列表就够了。不过，对于某些操作，这种作法常常很低效。

例如，如果我们要检查顶点 $a$ 和 $b$ 之间是否存在边，朴素的做法需要遍历整个列表寻找这样的边。

为了避免这一点，可以给这个列表加上某种结构。例如，可以先按第一个元素排序，再按第二个元素排序，这样就能用二分查找在 $O(\log m)$ 时间内完成检查。还可以更进一步，把它包装进某种数据结构，比如二叉搜索树，或者更好的哈希表，但无论如何都会带来一些效率损失。

### 邻接矩阵

*邻接矩阵*是大小为 $n \times n$ 的二维矩阵 $G$，如果存在边 $(i, j)$，则单元格 $G_{ij}$ 中存 1，否则存 0。

实现时通常创建一个普通的 `bool` 类型二维数组。如果对于 $n$ 个顶点中的每一个，我们都存储它与其余各顶点之间是否存在边的信息，那么总共要存储 $n^2$ 个单元格，因此空间复杂度为 $O(n^2)$。

对于含重边的图，有时在邻接矩阵中不存 0 和 1，而是存相应边的重数。

注意，对于简单无向图，邻接矩阵是对称的，且主对角线上全为 0。

邻接矩阵对检查操作非常高效——只需读取并比较一个单元格。但如果我们想对给定顶点 $v$ 快速遍历它的所有邻居呢？这里不可能做到比 $O(n)$ 更快。

### 邻接表

现在，我们对 $n$ 个顶点中的每一个，不再存储布尔数组，而是存储与它相邻的所有顶点的编号。这需要某种动态结构，比如 C++ 中的 `std::vector`。

```c++
// если на вход идет матрица смежности
vector<vector<int>> g(n);
for (int i = 0; i < n; ++i){
    for (int j = 0;j < n;++j){
        cin >> a;
        if (a)
          g[i].push_back(j);
    }
}

// если на вход идет список ребер
cin >> n >> m;
vector<vector<int>> g(n);
for (int i = 0; i < m; ++i){
  cin >> v1 >> v2;
  g[v1].push_back(v2);
  g[v2].push_back(v1);
}
```

这里读取的时间复杂度和空间复杂度都是 $O(n + m)$，因为我们总共要存储 $2m$ 条边和 $n$ 个向量。

边数很多的*稠密*图应该用邻接矩阵存储，而边数很少的*稀疏*图用邻接表存储更优。
