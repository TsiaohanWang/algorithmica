给定一个无向图。桥是这样一条边：删除它会使图变得不连通（或者更准确地说，增加连通分量的数量）。要求在给定图中找出所有的桥。

非正式地讲，这个问题可以这样表述：需要在给定道路图上找出所有「重要」的道路，也就是这样的道路：删除其中任意一条，都会导致某两座城市之间不再有路径。

这里描述的算法是在线的，也就是说输入图并不是预先已知的，而是边一条一条地加入，每次加入之后算法都会重新计算当前图中的所有桥。换言之，该算法旨在高效地处理动态的、不断变化的图。

更严格地说，问题的描述如下。初始时图为空，由 n 个顶点组成。随后不断有请求到来，每个请求是一对顶点 (a,b)，表示要加入图中的一条边。要求在每次请求之后，也就是在每条边加入后，输出当前图中桥的数量。（如果愿意，也可以维护所有桥边的列表，以及显式地维护边双连通分量。）

下面描述的算法以 O (n \log n + m) 的时间运行，其中 m 是请求数。算法基于「并查集」这一数据结构。

这里给出的算法实现实际上以 O (n \log n + m \log n) 的时间运行，因为在某个地方它使用了不带按秩合并优化的简化版并查集。

算法
众所周知，桥边把图的顶点划分成一些分量，称为边双连通分量。如果把每个边双连通分量缩成一个顶点，只保留这些分量之间的桥边，得到的将是一个无环图，也就是森林。

下面描述的算法显式地维护这棵由边双连通分量组成的森林。

显然，初始时图为空，包含 n 个互不关联的边双连通分量。

每加入一条边 (a,b)，可能出现三种情况：

两个端点 a 和 b 位于同一个边双连通分量中——那么这条边不是桥，也不会改变森林的结构，因此直接跳过这条边。
这样一来，在这种情况下桥的数量不变。

顶点 a 和 b 位于不同的连通分量中，也就是连接了两棵树。这种情况下边 (a,b) 成为新的桥，而这两棵树合并成一棵（所有旧的桥仍然保留）。
这样一来，在这种情况下桥的数量加一。

顶点 a 和 b 位于同一个连通分量中，但属于不同的边双连通分量。这种情况下这条边连同一些旧桥一起构成一个环。所有这些桥都不再是桥，而构成的环需要合并成新的边双连通分量。
这样一来，在这种情况下桥的数量减少两个或更多。

因此，整个问题归结为高效地实现对这棵分量森林的各种操作。

存储森林所需的数据结构
数据结构方面，我们只需要并查集。实际上，我们需要两个这样的结构：一个用来维护连通分量，另一个用来维护边双连通分量。

此外，为了存储双连通分量森林中树的结构，我们对每个顶点存储一个指向其树中祖先的指针 {\rm par}[]。

现在依次分析我们需要实现的每个操作：

检查给定的两个顶点是否位于同一个连通分量/双连通分量中。通过普通的并查集查询即可完成。
按某条边 (a,b) 把两棵树合并成一棵。由于顶点 a 和 b 可能都不是各自树的根，合并这两棵树的唯一办法是重新挂接其中一棵。例如，可以把一棵树重新挂接在顶点 a 上，然后把 a 作为 b 的子节点接到另一棵树上。
不过这里存在一个重挂接操作的效率问题：要把以 r 为根的树重挂接在顶点 v 上，需要沿路径从 v 走到 r，把 {\rm par}[] 指针反向设置，同时修改维护连通分量的并查集中指向祖先的引用。

因此，重挂接操作的开销为 O(h)，其中 h 是树的高度。还可以给出更高的估计：这个量是 O({\rm size})，其中 \rm size 是树中的顶点数。

现在应用这样一个标准技巧：两棵树合并时，重挂接顶点数较少的那一棵。直观上可以理解，最坏的情况是两棵大小相近的树合并，但那样得到的是大小翻倍的树，这种情形不可能多次发生。形式化地可以写成一个递推关系：

 T(n) = \max_{k = 1 \ldots n-1} \left\{ ~ T(k) + T[...

其中 T(n) 表示通过重挂接和合并操作得到一棵包含 n 个顶点的树所需的操作数。这是一个著名的递推关系，其解为 T(n) = O(n \log n)。

因此，如果我们总是重挂接两棵树中较小的那棵，那么所有重挂接操作的总时间为 O(n \log n)。

我们需要维护每个连通分量的大小，而并查集这种数据结构可以毫不费力地做到这一点。

查找加入新边 (a,b) 后在某棵树中形成的环。实际上这要求我们求出顶点 a 和 b 的最近公共祖先（LCA）。
注意，之后我们会把找到的环的所有顶点缩成一个顶点，因此任何按环的长度量级运行时间的 LCA 算法都能满足要求。

由于我们掌握的关于树结构的全部信息就是指向祖先的 par[] 引用，唯一可行的 LCA 算法如下：把顶点 a 和 b 标记为已访问，然后转到它们的祖先 {\rm par}[a] 和 {\rm par}[b] 并标记它们，再转到它们的祖先，如此继续，直到当前两个顶点中至少有一个已经被标记。这意味着当前顶点就是所求的 LCA，于是需要重新从顶点 a 和顶点 b 走到它——这样就找到了所求的环。

显然，这个算法的时间与所求环的长度同阶，因为两个指针各自走过的距离不可能超过这个长度。

压缩加入新边 (a,b) 后在某棵树中形成的环。
我们需要创建一个新的边双连通分量，它由找到的环的所有顶点组成（显然，找到的环本身可能由一些双连通分量组成，但这无关紧要）。此外，压缩的方式不能破坏树的结构，所有 {\rm par}[] 指针和两个并查集都必须保持正确。

实现这一点最简单的方法是把找到的环的所有顶点压缩到它们的 LCA 上。确实，LCA 顶点是被压缩顶点中最高的，因此它的 {\rm par} 保持不变。对于其他被压缩的顶点，也无需更新任何东西，因为这些顶点只是不再存在——在维护双连通分量的并查集中，所有这些顶点都只是指向 LCA 顶点。

但这样一来，维护双连通分量的并查集就没有使用按秩合并优化：如果我们总是把环的顶点挂到它们的 LCA 上，这个优化就没有用武之地。此时复杂度中会出现 O(\log n)，因为不带按秩优化的并查集的每个操作恰好需要这么多时间。

要达到每个请求 O(1) 的复杂度，需要按照按秩合并的规则合并环的顶点，然后把新代表元的 {\rm par} 赋为 {\rm par}[{\rm LCA}]。

实现
下面给出整个算法的最终实现。

为简单起见，维护双连通分量的并查集没有使用按秩合并优化，因此最终每个请求平均为 O(\log n)。（如何达到 O(1) 的复杂度详见上文「压缩环」一节。）

此外，该实现并不存储桥边本身，只存储它们的数量——参见变量 \rm bridges。当然，如果需要的话，很容易就能维护一个包含所有桥的 {\rm set}。

初始时应调用函数 {\rm init}()，它初始化两个并查集（把每个顶点单独作为一个集合，并设置大小为 1），并设置祖先 {\rm par}。

主函数是 {\rm add\_edge}(a,b)，它处理加入新边的请求。

常量 \rm MAXN 应设置为输入图中可能的最大顶点数。

本实现更详细的说明见下文。

const int MAXN = ...;
 
int n, bridges, par[MAXN], bl[MAXN], comp[MAXN], size[MAXN];
 
 
void init() {
	for (int i=0; i<n; ++i) {
		bl[i] = comp[i] = i;
		size[i] = 1;
		par[i] = -1;
	}
	bridges = 0;
}
 
 
int get (int v) {
	if (v==-1)  return -1;
	return bl[v]==v ? v : bl[v]=get(bl[v]);
}
 
int get_comp (int v) {
	v = get(v);
	return comp[v]==v ? v : comp[v]=get_comp(comp[v]);
}
 
void make_root (int v) {
	v = get(v);
	int root = v,
		child = -1;
	while (v != -1) {
		int p = get(par[v]);
		par[v] = child;
		comp[v] = root;
		child=v;  v=p;
	}
	size[root] = size[child];
}
 
 
int cu, u[MAXN];
 
void merge_path (int a, int b) {
	++cu;
 
	vector<int> va, vb;
	int lca = -1;
	for(;;) {
		if (a != -1) {
			a = get(a);
			va.pb (a);
 
			if (u[a] == cu) {
				lca = a;
				break;
			}
			u[a] = cu;
 
			a = par[a];
		}
 
		if (b != -1) {
			b = get(b);
			vb.pb (b);
 
			if (u[b] == cu) {
				lca = b;
				break;
			}
			u[b] = cu;
 
			b = par[b];
		}
	}
 
	for (size_t i=0; i<va.size(); ++i) {
		bl[va[i]] = lca;
		if (va[i] == lca)  break;
		--bridges;
	}
	for (size_t i=0; i<vb.size(); ++i) {
		bl[vb[i]] = lca;
		if (vb[i] == lca)  break;
		--bridges;
	}
}
 
 
void add_edge (int a, int b) {
	a = get(a);   b = get(b);
	if (a == b)  return;
 
	int ca = get_comp(a),
		cb = get_comp(b);
	if (ca != cb) {
		++bridges;
		if (size[ca] > size[cb]) {
			swap (a, b);
			swap (ca, cb);
		}
		make_root (a);
		par[a] = comp[a] = b;
		size[cb] += size[a];
	}
	else
		merge_path (a, b);
}
下面更详细地注释这段代码。

维护双连通分量的并查集存储在数组 {\rm bl}[] 中，返回双连通分量代表元的函数是 {\rm get}(v)。这个函数在其余代码中被大量使用，因为需要记住：在把若干顶点压缩成一个之后，这些顶点都不再存在，取而代之的只有它们的代表元，正确数据（祖先 {\rm par}、维护连通分量的并查集中的祖先等）都存储在这个代表元上。

维护连通分量的并查集存储在数组 {\rm comp}[] 中，另外还有一个数组 {\rm size}[] 用来存储分量的大小。函数 {\rm get\_comp}(v) 返回连通分量的代表元（它实际上是树的根）。

重挂接树的函数 {\rm make\_root}(v) 的工作方式与上面描述的一致：它从顶点 v 沿祖先走到根，每次都把祖先 \rm par 反向设置（向下，指向顶点 v 的方向）。同时更新维护连通分量的并查集中的 {\rm comp} 指针，使它指向新的根。重挂接之后，为新根设置连通分量的大小 {\rm size}。注意，在实现中我们每次都调用 {\rm get}() 函数，以确保访问到连通分量的代表元，而不是某个可能已被压缩的顶点。

发现并压缩路径的函数 {\rm merge\_path}(a,b) 与上面描述的一致：它寻找顶点 a 和 b 的 LCA，做法是从它们出发并行向上走，直到某个顶点第二次出现。为了提高效率，走过的顶点用「数值 used」技巧来标记，这只需 O(1) 而不是使用 \rm set。走过的路径保存在向量 \rm va 和 \rm vb 中，以便之后第二次走到 LCA，从而得到环的全部顶点。环的所有顶点都被压缩，方法是把它们挂到 LCA 上（这里出现 O(\log n) 的复杂度，因为压缩时没有使用按秩合并优化）。与此同时统计走过的边的数量，它等于找到的环中桥的数量（这个数量从 \rm bridges 中扣除）。

最后，处理请求的函数 {\rm add\_edge}(a,b) 确定顶点 a 和 b 所在的连通分量，如果它们位于不同的连通分量，就把较小的树重挂接到新根上，然后接到较大的树上。否则，如果顶点 a 和 b 在同一棵树中但属于不同的双连通分量，就调用 {\rm merge\_path}(a,b)，它会发现环并把环压缩成一个双连通分量。
