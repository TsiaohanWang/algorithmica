根号启发式是对各种方法和数据结构的总称，它们依赖这样一个事实：如果把某个 $n$ 元素集合按 $\sqrt{n}$ 个元素一块分组，那么块数本身不超过 $\sqrt{n}$。

本文的中心等式：$\sqrt x = \frac{x}{\sqrt x}$。

## 分成重对象与轻对象

人人皆知的根号因式分解算法依赖这样的事实：数 $n$ 的每个「大」因数 $d \geq \sqrt n$ 都对应某个「小」因数 $\frac{n}{d} \leq n$。

类似的有用性质（小对象小而大对象不多）在其他对象上也能找到。

### 长字符串与短字符串

[题目](https://codeforces.com/contest/710/problem/F)。需要在线处理字符串集合上的三类操作：

1. 把字符串加入集合。
2. 从集合中删除字符串。
3. 对给定字符串，数它在集合所有字符串中作为子串的出现次数。

一个解如下：把所有字符串分成*短*（$|s| < \sqrt l$）与*长*（$|s| \geq \sqrt l$），其中 $l$ 是所有字符串总长。注意长字符串不多——不超过 $\sqrt l$。

这样处理查询：

- 建哈希表，处理加入或删除查询时，按所有短子串的[哈希](/cs/hashing)加一或减一。总计 $O(l \sqrt l)$：对每个字符串要枚举 $O(\sqrt l)$ 种不同长度，用窗口遍历整个字符串。
- 对短字符串的第三类查询，只需算它的哈希，看哈希表里的值。
- 对长字符串的第三类查询，我们可以允许自己看所有未删除的字符串，因为这种情况不多；若我们能在线性时间内找新串的所有出现，总代价也是 $O(l \sqrt l)$。例如可以对所有 `s#t` 型字符串算 [z 函数](/cs/string-searching/z-function)，其中 $s$ 是查询串、$t$ 是集合中的串；但这里有个细节：$s$ 可能很大、而小的 $t$ 很多——需要先只对 $s$ 算 z 函数，再「虚拟」地逐个追加 $t$ 补算。

有时不必单独处理重、轻对象，但这一思想本身能帮助我们看出某些简单解比想象中快。

### 图中的三角形

**题目。** 给 $n$ 个顶点、$m \approx n$ 条边的图。求其中长度为三的环的个数。

如果顶点与超过 $\sqrt n$ 个其他顶点相连，称它*重*，否则*轻*。

尝试估计连在一起的三元组个数，考虑全部 4 种情况：

0. 环中没有重顶点。考虑环的某条边 $(a, b)$。第三个顶点 $c$ 必须位于 $g_a$ 与 $g_b$ 的邻接表并集中；而两个顶点都轻，这样的顶点至多 $\sqrt n$ 个。因此这类环总数至多 $O(m \sqrt n)$。
1. 环中有一个重顶点。类似——有一条「轻」边，因此这类环也是 $O(m \sqrt n)$。
2. 环中有两个重顶点——记为 $a$ 和 $b$，轻的记为 $c$。固定对 $(a, c)$——有 $O(m)$ 种，因为边总数就这么多。对这个边至多有 $O(\sqrt n)$ 条边 $(a, b)$，因为重顶点总共就这么多。于是这类环总数至多 $O(m \sqrt n)$。
3. 所有顶点都重。类似——上一情形中第三个顶点的类型哪里都没用到；重要的是重顶点 $b$ 不多。

于是图中长度为 3 的环其实不多——至多 $O(m \sqrt n)$。

解本身极简单：按度数给顶点排序，枚举所有形如 $v \rightarrow u \rightarrow w, v \le u \le w$ 的路径，检查边 $v \rightarrow w$ 是否存在。

```c++
vector<int> g[maxn], p(n); // 原图和顶点编号列表
iota(p.begin(), p.end(), 0); // 0, 1, 2, 3, ...

// 避免复制比较代码：
auto cmp = [&](int a, int b) {
    return g[a].size() < g[b].size() || (g[a].size() == g[b].size() && a < b);
};

// 按这个顺序枚举顶点
sort(p.begin(), p.end(), cmp);

// 现在对每个顶点排序邻接表
for (int v = 0; v < n; ++v)
    sort(g[v].begin(), g[v].end(), cmp);

// 每个顶点旁存之前看过的入边数 (v -> w)
vector<int> cnt(n, 0);
int ans = 0;

for (int v : p) {
    for (int w : g[v])
        cnt[w]++;
    for (int u : g[v]) {
        if (cmp(v, u))
            break;
        for (int w : g[u]) {
            if (cmp(u, w))
                break; // 如果边不好 -- 不取这个三角形
            ans += cnt[w]; // 若图中无环，则 cnt[w] = {0, 1}
        }
    }
    // 转到下一个 v 前要清零数组
    for (int w : g[v])
        cnt[w]--;
}
```

### 在 $O(S \sqrt S)$ 内解背包

如果有 $n$ 个物品，权重 $w_1$, $w_2$, $\ldots$, $w_n$，且 $\sum w_i = S$，那么可以用标准动态规划在 $O(S \cdot n)$ 内解背包。要更快，试着让物品数变为 $O(\sqrt S)$。

注意不同权重的个数是 $O(\sqrt S)$，因为对任意 $k$ 个和为 $S$ 的不同数

$$
S = w_1 + w_2 + \ldots + w_n \geq 1 + 2 + \ldots + k = \frac{k \cdot (k+1)}{2}
$$

由此 $k \leq 2\sqrt S = O(\sqrt S)$。

现在考虑权重集中出现 $k$ 次的某个权重 $x$。把 $k$ 按 2 的幂「分解」，不再放这 $k$ 个 $x$，而放权重 $x$、$2 \cdot x$、$4 \cdot x$、$\ldots$、$(k - 1 - 2^t) \cdot x$，其中 $t$ 是满足 $2^t − 1 \leq k$ 的最大整数。容易看出，形如 $q \cdot x$（$q \leq k$）的和，且只有它们，仍然能拼出。

算法本质如此：对所有不同权重做该操作，然后运行标准解。立刻看出新物品数是 $O(\sqrt S \log S)$，因为对每个权重我们至多留 $\log S$ 个权重，而不同权重有 $O(\sqrt S)$ 个。

**练习。** 证明物品数实际是 $O(\sqrt S)$。

*注。* 经典背包解可以用 [bitset](/cs/set-structures/bitset) 加速几个数量级。
