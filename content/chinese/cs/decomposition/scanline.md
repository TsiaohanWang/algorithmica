扫描线方法（英文 *scanline*）在于把坐标轴上的点或某些抽象「事件」按某个特征排序，然后遍历它们。

它常用于所有查询预先已知的数据结构题，也用于几何中求图形并集。

### 被最多线段覆盖的点

**题目**。 给 $n$ 个线段，由起点终点坐标 $[l_i, r_i]$ 给出。求直线上被最多线段覆盖的任意点。

考虑函数 $f(x)$，等于覆盖点 $x$ 的线段数。显然不能检查它的每个点。

把发生覆盖数变化的点叫*关键点*。因为答案只在关键点变化，所以最大值也在某个关键点取得。由此立得 $O(n^2)$ 解法：枚举所有关键点（即给定线段的端点）、逐一检查答案。

可以改进。按坐标升序排序关键点，从左到右遍历，维护覆盖当前点的线段数 `cnt`。若某点处线段开始，把 `cnt` 加一；结束则减一。之后尝试用当前 `cnt` 更新答案。

写法：把关键点表示成带「坐标」和「类型」（开始/结束）字段的结构，按自定义比较排序。方便地把线段开始记 +1、结束记 -1，直接加到 `cnt` 而不分情况。

唯一细节——若两点坐标相同，为得正确结果要先处理所有线段开始、再处理结束（这样在该坐标更新答案时左右边界线段都计入）。

```cpp
struct event {
    int x, type;
};

int scanline(vector<pair<int, int>> segments) {
    vector<event> events;

    for (auto [l, r] : segments) {
        events.push_back({l, 1});
        events.push_back({r, -1});
    }

    sort(events.begin(), events.end(), [](event a, event b) {
        return (a.x < b.x || (a.x == b.x && a.type > b.type)); 
    });
    
    int cnt = 0, res = 0;

    for (event e : events) {
        cnt += e.type;
        res = max(res, cnt);
    }

    return res;
}
```

这个解在 $O(n \log n)$ 内排序。若坐标不大，可以去掉对数：为每个不同坐标建一个事件 `vector`，直接遍历所有整数坐标及其事件。也总是好主意[压缩坐标](/cs/sequences/compression)。

再看几个相关题。

### 线段并的长度

**题目**。 给 $n$ 个线段，由 $[l_i, r_i]$ 给出。求它们并的总长度。

与上题一样，排序所有关键点，遍历时维护覆盖当前点的线段数。若它大于 0，则从上个考察点到当前点经过的线段属于并集，应把其长度加入答案：

```cpp
int cnt = 0, res = 0, prev = -inf;

for (event e : events) {
    if (prev != -inf && cnt > 0)
        res += e.x - prev; // 整个区间 [prev, e.x] 被 cnt 个线段覆盖
    cnt += e.type;
    prev = e.x;
}
```

运行时间 $O(n \log n)$。

### 点属于多少线段

现在要求对 $q$ 个点（不必是线段端点）回答：它属于多少线段？

用下面的技巧：先全部读入查询并保存，之后一次回答。把查询点作为类型为 0 的事件加入，表示该点要回答查询，并带一个存查询编号的字段。

然后类似地排序关键点、从左到右遍历、维护 `cnt`，遇到查询时回答。

```cpp
struct event {
    int x, type, idx;
};

void scanline(vector<pair<int, int>> segments, vector<int> queries) {
    int q = (int) queries.size();
    
    vector<int> ans(q)
    vector<event> events;

    for (auto [l, r] : segments) {
        events.push_back({l, 1});
        events.push_back({r, -1});
    }

    for (int i = 0; i < q; i++)
        events.push_back({queries[i], 0, i});

    // 坐标相等时先加、再查询、最后删除
    sort(events.begin(), events.end(), [](event a, event b) {
        return (a.x < b.x || (a.x == b.x && a.type > b.type)); 
    });
    
    int cnt = 0;

    for (event e : events) {
        cnt += e.type;
        if (e.type == 0)
            ans[e.idx] = cnt;
    }
}
```

复杂度 $O((n+q)\log(n+q))$。

### 相交线段数

**题目**。 给 $n$ 个线段 $[l_i, r_i]$。对每个线段说它与多少线段相交（特别地，可有公共点或被包含）。

不逐个数相交线段，而数*不*相交的，再从 $(n-1)$ 减。

线段 $[l_1, r_1]$ 与另一线段 $[l_2, r_2]$ 不相交当且仅当 $r_2 < l_1$ 或 $r_1 < l_2$。为每种情况数线段。不一般性地看第一种：对每个线段找严格在它左侧的线段数。为此引入两类事件：

1. 某线段在坐标 $r_i$ 结束。
2. 某线段（带下标）在坐标 $l_j$ 开始。

从左到右遍历这些事件，维护遇到的第一类事件数，对第二类事件把它从答案单元中减去。

类似从右到左遍历，找严格在右侧的线段。总运行时间 $O(n \log n)$ 排序。

### 矩形求和

转向二维扫描线。

**题目**。 给平面上 $n$ 个点。回答 $m$ 个「矩形内点数」查询。

先压缩所有坐标（点和查询的）：认为它们量级都是 $O(n + m)$。

然后把每个查询拆成两个前缀求和查询：矩形 $[x_1, x_2] \times [y_1, y_2]$ 的和等于矩形 $[0, x_2] \times [y_1, y_2]$ 的和减矩形 $[0, x_1] \times [y_1, y_2]$ 的和。

建求和线段树和存查询答案的数组 `ans`。现在按所有关键 $x$——点坐标与前缀查询右边界——递增遍历，处理三类事件：

1. 遇到点，向线段树的 $y$ 单元加一。
2. 遇到「左」前缀和查询，用线段树算区间 $[y_1, y_2]$ 的和并*减*到答案单元。
3. 遇到「右」查询，类似地*加* $[y_1, y_2]$ 的和到答案单元。

于是在 $O(n \log n)$ 内离线解决：坐标压缩/排序加上 $O(n)$ 次线段树（或任何动态和结构）查询。

矩形求和作为辅助子问题也常用于排列逆序与子树查询题。

### 矩形并的面积

**题目**。 给 $n$ 个矩形，求它们并的面积。

受上一方法启发，可建两类事件：

1. $y$ 坐标从 $y_1$ 到 $y_2$ 的矩形在点 $x_1$ 开始；
2. $y$ 坐标从 $y_1$ 到 $y_2$ 的矩形在点 $x_2$ 结束；

然后按 $x$ 递增遍历这些事件，像一维线段那样算总面积。

![](../img/2d-scanline.jpg)

若直接推广，需建大小 $Y$（最大 $y$ 坐标）的数组，为每条 $y$ 平行线维护覆盖它的矩形数，且每当 $x$ 坐标变化，把新旧 $x$ 坐标差乘以数组非零元素数（即被至少一个矩形覆盖的竖直扫描线上的点数）加到答案。

但最坏 $O(nY)$，很慢。为得更好复杂度，用线段树代替数组，其节点存最小值和具有该最小值的元素数（初始最小值 0、整个 $Y$ 数组都是）。

更新答案时，把相邻事件 $x$ 坐标差乘以非零元素数——可从 $Y$ 减整棵树的最小值-零的个数得到。区间加时重算这个信息的一维问题留作[读者练习](/cs/segment-tree/lazy-propagation)。

这种算法在小心压缩坐标时 $O(n \log n)$，不压缩则 $O(n \log Y)$。此方法也可推广到求其他几何图形的面积。
