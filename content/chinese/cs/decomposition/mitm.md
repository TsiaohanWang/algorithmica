考虑某个子集枚举问题：我们已经会以 $O(2^n \cdot poly(n))$ 求解它，其中 $poly(n)$ 是问题规模 $n$ 的某个多项式。*meet-in-the-middle*（直译就是「在中间相遇」）方法可以在很大一类此类问题中把枚举优化到 $O(2^{n/2} \cdot poly(n))$。

作为具体例子，我们来考虑背包问题——需要选择一个子集 $a_i$，使其总重量为 $w$：

```cpp
bool find_subset(int *a, int n, int w)
    for (int mask = 0; mask < (1 << n); mask++) {
        int s = 0;
        for (int i = 0; i < n; i++)
            if (mask >> i & 1)
                s += a[i];
        if (s == w)
            return true;
    }
    return false;
}
```

这里我们枚举所有子集，并用 $O(n)$ 逐一检查，因此渐近复杂度为 $O(2^n \cdot n)$。

理论上可以去掉这 $O(n)$ 的检查：只要递归地枚举掩码，并维护前缀上的当前和，在递归下降过程中每次只添加一个元素即可。不过我们要追求一种更强大的优化。

### 解法

把数组分成两部分。注意，所求子集包含左半部分的一定数量的元素，以及右半部分的一定数量的元素（可能为零）。我们分别计算左、右两半的所有子集和，再找出一对和为目标总和的组合。

先计算前 $l = \lfloor \frac{n}{2} \rfloor$ 个元素的所有子集和，并放入哈希表：

```cpp
unordered_set<int> t;

int l = n / 2;

for (int mask = 0; mask < (1 << l); mask++) {
    int s = 0;
    for (int i = 0; i < n; i++)
        if (mask >> i & 1)
            s += a[i];
    t.insert(s);
}
```

然后枚举剩余 $r = n - l = \lceil \frac{n}{2} \rceil$ 个元素的所有子集和，对每一个和，通过预计算的哈希表尝试找到合适的另一半（和为 $s_l = w - s_r$）：

```cpp
int r = n - l;

for (int mask = 0; mask < (1 << r); mask++) {
    int s = 0;
    for (int i = 0; i < r; i++)
        if (mask >> i & 1)
            s += a[l + i];
    if (t.count(w - s))
        return true;
}
```

两个阶段（因此整个算法）都是 $O(2^{n/2} \cdot n)$：我们枚举 $2^{n/2}$ 个子集，对每个子集用 $O(n)$ 计算和，并用 $O(1)$ 对哈希表执行插入 / 查询操作。

注意，两个枚举都可以用递归的技巧再优化 $O(n)$ 倍。

### 其他例子

**题目.** 求不超过 $10^{14}$ 且数字和为 $s$ 的数的个数。

把数分成左半部分（高 7 位）和右半部分（低 7 位）。对左半部分的所有数，预计算其中数字和为 $s$ 的个数，写入预计算数组（大小为 $7 \times 9 + 1 = 64$）。然后枚举右半部分：对于「左」和为 $s$，需要求出数字和为 $(w - s)$ 的右半部分有多少个，只需用 $O(1)$ 查询预计算数组。

在更大数据范围下，这个问题可以用数位 DP 求解。

**题目.** 给定一个 $n$ 个顶点的图，求*团（clique*）的数量——团是其中所有顶点两两相连的子图。

![](../img/cliques.png)

先学会用暴力枚举解决：假设我们有图的邻接矩阵。如何快速判断顶点子集 $m$ 是否是一个团？

用 $O(n^2)$ 遍历所有被包含顶点的配对，逐一检查邻接矩阵中对应位置是否为 1。可以把检查优化到 $O(n)$：计算掩码 $m'$，它等于 $m$ 中各顶点对应邻接矩阵行的按位「与」。现在如果 $m$ 是 $m'$ 的子集，即

$$
m \; \& \; m' = m
$$

那么子图 $m$ 就是一个团：它的每个顶点都与其余所有顶点有边相连。

利用这个技巧在 meet-in-the-middle 中合并答案。把图分成两部分：找出左半部分的所有团，把它们的掩码在大小为 $2^{n/2}$ 的专用数组 `is_clique[mask]` 中标记为 1。

现在枚举后一半的子图：对每个团，求出左半部分中有多少个团是右半部分邻接表交集（即上面检查中的 $m'$）的子图。

为了快速完成这一点，在 `is_clique` 数组之上预计算一个 DP：「给定掩码有多少个子掩码是团」。这个 DP 可以用 $O(2^{n/2})$ 计算：对每个掩码 $m$ 考虑两种情况——第一个顶点 $v$ 是否包含在团中：

$$
f[m] = f[m \; \& \; g_v \oplus 2^v] + f[m \oplus 2^v] + is\_clique[m]
$$

算法的最终复杂度为 $O(2^{n/2} \cdot n)$。

**题目.** 隐式给出一个非常大的无权图，其中每个顶点最多有 $k$ 条出边。已知 $s$ 到 $t$ 的距离不超过 $n$，求该距离。

从两个顶点同时进行宽度优先搜索，在顶点旁记录由对应搜索求得的到 $s$ 或 $t$ 的距离。当某一侧的搜索进入另一个搜索已访问过的顶点时，恢复长度为 $(d_s + d_t)$ 的路径并结束。

由于距离不超过 $n$，算法保证在 $O(\frac{n}{2})$ 次「波」内结束。又因为每个顶点最多与 $k$ 个其他顶点相连，且算法不会进入「父节点」，下一波中的顶点数最多是上一波的 $(k-1)$ 倍。

因此总共会访问 $O((k-1)^{n/2})$ 个顶点，这就是算法的复杂度。
