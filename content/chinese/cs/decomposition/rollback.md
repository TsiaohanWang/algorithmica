有时解题并不需要完全的持久性，但需要能好歹回滚到更早的状态。

本文看几种通用做法及其常见应用。

### 按查询的根号启发式

考虑标准题目：有大小为 $n$ 的数组，需要执行 $q$ 个区间加与区间和查询。（暂时忘掉[线段树](/cs/segment-tree)和[其他树](/cs/range-queries)。）

如果没有更新查询，我们只需用[前缀和](/cs/range-queries/prefix-sum)数组解决：

```c++
int s[maxn]; // [0, r)
s[0] = 0

for (int i = 0; i < n; i++)
    s[i+1] = s[i] + a[i];
```

回到原题。把所有修改查询分成大小约 $\sqrt q$ 的块，每 $\sqrt q$ 个查询如实地在 $O(n)$ 内用之前所有查询重建前缀和数组。

现在对每个求和查询，可以用 $O(1)$ 时间查询前一个检查点的前缀和，再加 $O(\sqrt q)$ 时间「修正」——只需线性遍历所有尚未计入的查询。

```c++
const int c = 300; // ~= sqrt(q)

struct query { int l, r, x; };
vector<query> buffer; // 未计入前缀和的查询

int sum(int l, int r) {
    int res = s[r + 1] - s[l];
    for (query q : buffer)
        // 把求和查询与所有缓冲查询相交
        res += q.x * max(0, min(r, q.r) - max(l, q.l));
    return res;
}

void rebuild() {
    vector<int> d(n, 0); // 差分数组

    for (query q : buffer) {
        d[q.l] += x;
        d[q.r + 1] -= x;
    }
    buffer.clear();

    int delta = 0, running_sum = 0;
    for (int i = 1; i <= n; i++) {
        p[i] += running_sum;
        delta += d[i];
        running_sum += delta;
    }
}

void upd(int l, int r, int x) {
    buffer.push_back({l, r, x});
    if (buffer.size() == c)
        // 缓冲太大；需要重算前缀和并清空它
        rebuild();
}
```

这个解法运行在 $O(n \sqrt q + q \sqrt q)$：每 $\sqrt q$ 个查询用 $O(n)$ 重建前缀和，每个求和查询查看 $O(\sqrt q)$ 个之前的查询。

### 把静态结构变成动态

前面方法不仅适用于前缀和数组，也适用于任何静态数据结构。

**题目**。 需要向凸包加点，并求切线（即找使点积 $a_i x + b_i y$ 最大的点）。

我们可以同样每 $\sqrt n$ 个查询[重建](/cs/convex-hulls)凸包，回答[切线查询](/cs/convex-hulls/hull-applications)时，除了建好的凸包候选外，再额外考虑缓冲中点的 $\sqrt n$ 个点积。

这在维护有序点列表、从而线性重建凸包时，运行在 $O(n \cdot (\sqrt n + \log n) + \sqrt n \cdot n) = O(n \sqrt n)$。

**题目**。 需要*按预先已知的顺序*向凸包加点*和删点*，并求切线。

这稍难。显式把查询分成块，逐块处理。在每个块上，只对*整个块中都存在*的点构建凸包，其余查询存进缓冲——要找出这些点，需要向前看 $O(\sqrt n)$ 个查询，并在某个数组或哈希表里标记被删除的边。

那么回答切线查询时，除了建好凸包的候选外，还要考虑该查询时刻存在的所有点——用 $O(\sqrt n)$ 分析当前块历史，可以类似地找到所有这些点。

### 2 的幂大小的结构

如果题目没有删除、或删除可以某种方式模拟，往往可以应用一种相似但更强大的技术：维护 $O(\log n)$ 个大小为 2 的幂的结构（例如凸包），且保证没有两个结构大小相同。

为此，加入新点时

- 为它建一个大小为 1 的结构，其中只有这个新点；
- 然后，如果大小为 1 的结构已存在，就把它与新结构合并，建一个大小为 2 的结构；
- 然后，如果大小为 2 的结构已存在，就把它与新结构合并，建一个大小为 4 的结构

……依此类推，直到找到某个不存在相应大小结构的 2 的幂。

总元素数 $n$ 唯一决定这个合并中会出现哪些大小的结构：它们对应 $n$ 的二进制表示中的 1，因此基本结构总数至多为 $O(\log n)$。

对凸包而言，如果合并排序好的点数组，就能按结构大小线性构建每个结构。大小为 1 的结构每次操作都建；大小为 2 的每 2 次操作建一次；大小为 4 的每 4 次操作建一次，依此类推。维护这种静态结构合并，均摊要花 $O(n \log n)$ 次操作：每个大小各 $O(n)$。

回答查询时，把它传给所有 $O(\log n)$ 个基本结构并合并答案。对凸包来说总计 $O(\log^2 n)$。

除了凸包和包络线，这种方法也适用于例如更新字符串自动机，以及动态构建搜索索引。
