**定义**。 正整数如果恰好有两个不同的自然因数——1 和它本身，则称为**质数**。1 不算质数。

**埃拉托斯特尼筛法**（英文 *sieve of Eratosthenes*）是求出从 $1$ 到 $n$ 的所有质数的算法。

核心思想与算法名字相符：写出数列 $1, 2,\ldots, n$，然后不断划掉

- 先划掉被 $2$ 整除的数，除 $2$ 本身外，
- 再划掉被 $3$ 整除的数，除 $3$ 本身外，
- 对能被 $4$ 整除的数什么也不做——它们已经划掉了，
- 接着划掉被 $5$ 整除的数，除 $5$ 本身外，

……依此类推。

最简单的实现可能长这样：

```c++
vector<bool> sieve(int n) {
    vector<bool> is_prime(n + 1, true);
    for (int i = 2; i <= n; i++)
        if (is_prime[i])
            for (int j = 2 * i; j <= n; j += i)
                is_prime[j] = false;
    return is_prime;            
}
```

这段代码先把除 0 和 1 外的所有数标记为质数，然后开始筛除合数。为此我们在循环里枚举从 $2$ 到 $n$ 的所有数，如果当前数是质数，就把所有它的倍数标记为合数。

如果内存允许，为加快速度最好不用 `bool` 向量而用 `char` 向量——但它会占 8 倍空间。计算机不能直接操作位，因此索引 `vector<bool>` 时它先取出所需的字节，再用位运算得到所需的值，这会花不少时间。

### 运行时间

很容易证明算法的渐近运行时间至少不比 $O(n \log n)$ 差：即使对每个数都进入划掉循环、不先检查是否为质数，总迭代次数也是

$$
\sum_k \frac{n}{k} = \frac{n}{2} + \frac{n}{3} + \frac{n}{4} + \ldots + \frac{n}{n} = O(n \log n)
$$

这里我们用了[调和级数](https://ru.wikipedia.org/wiki/%D0%93%D0%B0%D1%80%D0%BC%D0%BE%D0%BD%D0%B8%D1%87%D0%B5%D1%81%D0%BA%D0%B8%D0%B9_%D1%80%D1%8F%D0%B4)的复杂度。

原算法的复杂度应该更好。要更精确地求它，需要关于质数的两个事实：

1. 从 $1$ 到 $n$ 的质数大约有 $\frac{n}{\ln n}$ 个。
2. 质数分布没有大的「间隙」和「堆积」，即第 $k$ 个质数大约等于 $k \ln k$。

我们可以简化地认为数 $k$ 以「概率」$\frac{1}{\ln n}$ 是质数。那么算法运行时间可以更精确地估计为

$$
\sum_k \frac{1}{\ln k} \frac{n}{k}
\approx n \int \frac{1}{k \ln k}
= n \ln \ln k \Big |_2^n 
= O(n \log \log n)
$$

算法的复杂度还可以进一步改进到 $O(n)$。

## 线性筛

埃拉托斯特尼筛法的主要问题在于，有些数会被标记为合数多次——次数等于它不同质因数的个数。要达到线性时间，需要想出办法让每个合数恰好被考虑一次。

记 $d(k)$ 为数 $k$ 的最小质因数，注意如下事实：合数 $k$ 有唯一表示 $k = d(k) \cdot r$，且数 $r$ 没有小于 $d(k)$ 的质因数。

优化的思路是枚举这个 $r$，对每个 $r$ 只枚举需要的因数——即从 $2$ 到 $d(r)$（含）的所有数。

### 算法

稍微推广问题——现在我们要对区间 $[2, n]$ 上的每个数 $k$ 求它的最小质因数 $d_k$，而不仅是判断它是否质数。

初始数组 $d$ 全填零，表示所有数都被认为是质数。算法运行中这个数组逐渐被填满。此外，维护当前已找到质数的列表 $p$。

现在枚举 $k$ 从 $2$ 到 $n$。如果这个数是质数，即 $d_k = 0$，则令 $d_k = k$ 并把 $k$ 加入列表 $p$。

接下来，无论 $k$ 是否质数，开始往数组 $d$ 填值的过程——枚举不超过 $d_k$ 的已找到质数 $p_i$，做赋值 $d_{p_i k} = p_i$。

```c++
const int n = 1e6;

int d[n + 1];
vector<int> p;
 
for (int k = 2; k <= n; k++) {
    if (p[k] == 0) {
        d[k] = k;
        p.push_back(k);
    }
    for (int x : p) {
        if (x > d[k] || x * d[k] > n)
            break;
        d[k * x] = x;
    }
}
```

算法需要至少比普通筛法多 32 倍的内存，因为对每个数要存因数（`int`，4 字节）而不是一个位。线性筛尽管有更好的复杂度，但实践中在速度上也输给优化过的埃拉托斯特尼筛法。

### 应用

数组 $d$ 可以按该因式分解大小的量级在 $O$ 内求出任意数 $k$ 的分解：

$$
factor(k) = \{d(k)\} \cup factor(k / d(k))
$$

知道所有数的因式分解，对某些题目是非常有用的信息。线性筛有意思的地方不在于运行时间，而正是这个最小质因数数组。
