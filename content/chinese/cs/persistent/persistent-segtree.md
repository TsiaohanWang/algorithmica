几乎所有引用结构可持久化的一般方法，就是复制一切有变化的顶点，在副本中修改，绝不改动已存在的顶点。

可持久化线段树也不例外。只需在下潜前创建顶点副本，再修改它本身或其后代。操作复杂度不变，只是总内存增至 $O(m \log n)$。

最方便的是仿照延迟操作里的 `push`，定义复制当前顶点子节点的 `copy` 函数，并在所有可能有变化的顶点里一律调用它。

```cpp
struct Segtree {
    int lb, rb;
    int s = 0;
    Segtree *l = 0, *r = 0;
    Segtree(int lb, int rb) : lb(lb), rb(rb) {
        if (lb != rb) {
            int t = (lb + rb) / 2;
            l = new Segtree(lb, t);
            r = new Segtree(t, rb);
        }
    }
    void copy() {
        if (l) {
            l = new Segtree(*l);
            r = new Segtree(*r);
        }
    }
    void add(int k, int x) {
        copy();
        s += x;
        if (l) {
            if (k < l->rb)
                l->add(k, x);
            else
                r->add(k, x);
        }
    }
    int sum(int lq, int rq) {
        // 这个方法不改任何东西——它本来就很好
        if (lq <= lb && rb <= rq)
            return s;
        if (max(lb, lq) >= min(rb, rq))
            return 0;
        return l->sum(lq, rq) + r->sum(lq, rq);
    }
};
```

现在只需建一个版本列表，每次操作后把新根复制进去：

```cpp
vector<Segtree*> roots;

roots.push_back(new Segtree(0, n));

void add(int k, int x, int v) {
    Segtree *root = new Segtree(*roots[v]);
    root->add(k, x);
    roots.push_back(root);
}
```

另一种做法是复制当前顶点而非子节点，从递归返回它、挂到父节点下。这计算上更高效，但要大幅改实现。

## 应用

在数据结构题语境下，可持久化线段树尤其常用于那些若查询已知就能用扫描线的题。

### 矩形求和

**题目**。 给平面上的 $n$ 个点。需要*在线*回答 $q$ 个「矩形内点数」查询。

如果能在离线回答，就把查询拆成两个前缀查询，从左到右扫一遍，把点的 $y$ 坐标加入线段树、回答子段求和——但这里不能这么做。

但*点*在离线时已知。按同样顺序把它们加入*可持久化*线段树（而非普通），并按 $x$ 递增保存不同 $x$ 坐标对应的树根。

现在可以回答查询：同样把它拆成两个，分别导向对应较大和较小 $x$ 坐标的两个线段树版本。于是能在 $O(q \log n)$ 时间和内存内在线回答。

### 序统计量

**题目**。 给 $n$ 个整数的数组和 $q$ 个「子段上的第 $k$ 个序统计量」查询。

先把所有数压缩到 1 到 $n$。

然后带着求和的可持久化线段树从左到右遍历数组，处理元素 $a_k$ 时在树中 $a_k$ 位置加一。注意，这种树中从 $l$ 到 $r$ 的和等于当前前缀上位于 $l$ 和 $r$ 之间的元素个数。

接着定义*树的差*：仿佛在相应数组之差上构建出的线段树。

第 $r$ 棵与第 $l$ 棵树（$r > l$）之差中有什么？有数组从 $l$ 到 $r$ 区间上各数出现次数——某个非负整数数组。若在这种差分树上做「找到前缀和不超过 $k$ 的最后位置」的下降，那个位置就是查询答案。

不必显式构建差分树来下降——可以同时在两棵树中下降，处处用 $(s_r - s_l)$ 代替和 $s$：

```cpp
int kth(Segtree *l, Segtree *r, int k) {
    if (k == 0)
        return l->lb;
    int s = r->l->s - l->l->s;
    if (s <= k)
        return kth(l->l, r->l, k);
    else
        return kth(l->r, r->l, k - s);
}
```

注意，这道与上一题也可以用 mergesort tree 在 $O(n \log^2 n)$ 内解决，或用二维结构达到同样复杂度。

### 支配元素

**题目**。 给 $n$ 个元素的数组。回答 $m$ 个查询：区间 $[l, r)$ 上是否存在*支配*元素——即出现至少 $\frac{r-l}{2}$ 次的元素。

这道题有惊人简单的解法——对每个查询取约 100 个随机元素，逐个检查是否支配。检查可以在 $O(\log n)$ 内完成：为每个值维护它出现位置的有序列表，在其中做两次二分查找。最坏情形错误概率是 $\frac{1}{2^{100}}$，实践中可以忽略。

但检查 100 个样本很慢。构建上一题那样的线段树，把问题「在总和不超过 $n$ 的 $n$ 个非负整数数组中找大于 $\frac{n}{2}$ 的数」相对于差分树求解。这也是沿树下降：每次都走向和更大的那个儿子（因为和小儿子肯定不是支配的）。如果到达的叶子中值大于所需，返回 `true`，否则 `false`。

**练习**。 想出一个办法修改下降，用于[这道题](https://codeforces.com/problemset/problem/840/D?locale=ru)，其中对小的 $k$（2 到 5）支配指出现至少 $\frac{r-l}{k}$ 次。

### 作可持久化数组

完全可持久化数组通常正是用线段树实现——一般每次查询 $O(\log n)$ 已是极限。可持久化数组又能用来让非引用结构可持久化——例如并查集。

在并查集中，所有状态存在数组里，可以让它们通过线段树可持久化。这种结构的复杂度是 $O(n \log n)$ 时间和内存——对数既来自并查集本身（要沿 $O(\log n)$ 个祖先走——不能用路径压缩启发式），也来自可持久化线段树（要更新某个 $p_v$ 与 $s_v$ / $h_v$ 的值）。
