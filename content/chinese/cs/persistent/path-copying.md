广义上讲，数据结构是一组用链接关联起来的节点，节点中存着数据。

普通数组也符合这个定义：它只有一个节点，其中存着 $n$ 个单元。

考虑更窄的一类结构：其中每个节点存 $O(1)$ 个字段和链接。例如，后面要看的线段树和 treap（笛卡尔树）就满足这个性质。

对这类结构，存在一个简单通用的方法让它们完全可持久化——路径复制法（path copying）。

![](../img/path-copy.png)

以平衡树为例。设需要做某个更新——例如加入新元素——但同时不能丢失关于旧树的任何信息。

取需要添加新子节点的那个顶点。不直接往它加新子节点，而是把从根到这个顶点的整条路径连同所有数据和指针一起复制，然后把子节点加到复制路径中对应的顶点上。其他从被修改节点不可达的顶点，我们都不动。

于是新根可达所有更新后树的顶点，而旧根以及所有先前存在的顶点可达的仍是与之前完全相同、未修改的顶点——我们什么都没删改，只是创建了大约对数个新顶点。

如果每次操作后把树根存进某个数组，就能访问任意先前的版本，并可以自由地从中「分叉」。

### 复杂度

多数操作本来就需要做对数级工作，所以时间复杂度不变，但内存开销增至 $O(n \log n)$。

实践中，可持久化结构可能明显（2–5 倍）更慢，因为数据不再复用，CPU 缓存的收益几乎消失。

可持久化结构中，均摊分析在最坏情况下也不成立：如果存在某个重操作（例如「压缩竹竿」），可以多次回退到它并重复。因此像并查集和 splay 树这类结构会有更差的复杂度。

### 可持久化栈

可持久化树的实现与应用将在后面文章里讨论，这里出于教学目的把方法应用到栈上。

除了用数组加指向末尾元素的指针，栈也可以用链接实现。此时栈的「根」就是它的栈顶元素。

```cpp
struct Node {
    int val;
    Node *prev;
};

Node *head;

void add(int x) {
    head = new Node(x, head);
}

int top() {
    return head.val;
}

void pop() {
    Node *old = head;
    head = head->prev; // 如果不在乎内存，可以只留这一行
    delete old;
}
```

现在，要让栈可持久化，不需要额外字段，但需要一个全局版本数组，并给所有方法加一个额外参数：

```cpp
vector<Node*> versions;

void add(int x, int v);
int top(int v);
void pop(int v);
```

要让链接结构可持久化，只需修改那些改变它状态的操作——这里就是 `add` 和 `pop`。

对 `add`，用同样的过程，但创建新顶点而不是重写 `head`：

```cpp
void add(int x, int v) {
    versions.push_back(new Node(x, versions[v]));
}
```

对 `pop`，可以同样做，但也可以耍个巧，直接在版本列表末尾加一个指向已存在节点的引用：

```cpp
void pop(int v) {
    versions.push_back(versions[v]->prev);
}
```

两个操作都运行在 $O(1)$ 时间和额外内存。

用可持久化栈可以轻松实现可持久化队列（通过两个可持久化栈），但靠均摊它最坏情况下每次操作 $O(n)$。也有复杂的办法用[五个或六个栈](https://neerc.ifmo.ru/wiki/index.php?title=%D0%9F%D0%B5%D1%80%D1%81%D0%B8%D1%81%D1%82%D0%B5%D0%BD%D1%82%D0%BD%D0%B0%D1%8F_%D0%BE%D1%87%D0%B5%D1%80%D0%B5%D0%B4%D1%8C)实现每次操作干净的 $O(1)$。
