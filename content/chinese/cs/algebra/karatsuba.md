1960 年，[安德烈·柯尔莫哥洛夫](https://ru.wikipedia.org/wiki/Колмогоров,_Андрей_Николаевич)与其他苏联计算机科学的先驱们在一场学术研讨会上提出了「$n^2$ 猜想」：不可能以快于 $O(n^2)$ 的方式相乘两个 $n$ 位数。这意味着，由苏美尔人至少四千年前发明、并且当时无人超越的「列竖式」乘法，就是相乘两个数的渐近最优算法。

一周后，23 岁的研究生阿纳托利·卡拉楚巴提出了时间复杂度为 $O(n^{\log_2 3})$ 的乘法方法，从而推翻了这一猜想。本文就来讨论这个方法。

## 算法

算法的核心思想非常简单：用一个小的代数技巧，把两个长度为 $n$ 的数的相乘化为三个长度为 $\frac{n}{2}$ 的数的相乘。递归每一层的元素数量会增长，但最底层总共只有 $O(n^{\log_2 3})$ 个元素，正是这奇怪的渐近复杂度的由来。

在我们这个版本的算法里，我们相乘的不是数，而是多项式。这是等价的——只要把 $x$ 换成进制基数，就可以用数的各位数字作为系数：

$$
\begin{aligned}
A(x) &= a_0 + a_1\cdot x + a_2 \cdot x^2  + \dots + a_n \cdot x^n
\\   &= a_0 + a_1\cdot 10 + a_2 \cdot 10^2 + \dots + a_n \cdot 10^n
\end{aligned}
$$

设有两个等长（$n = 2k$）的多项式 $a(x)$ 和 $b(x)$，我们想求它们的乘积。把它们的系数分成相等的两半，表示成

$$
a(x) = a_1 (x) + x^k a_2(x)
\\b(x) = b_1 (x) + x^k b_2(x)
$$

现在递归地计算乘积多项式 $p_1$ 和 $p_2$：

$$
p_1(x) = a_1(x) \cdot b_1(x)
\\
p_2(x) = a_2(x) \cdot b_2(x)
$$

以及多项式 $t$：

$$
t(x) = ( a_1(x) + a_2(x) ) \cdot (b_1(x) + b_2(x))
$$

原多项式的乘积（规模为 $2n$ 的多项式）现在可以用下面的公式计算——注意，见证代数魔术的时刻：

$$
c(x) = a(x) \cdot b(x) = p_1(x) + x^k \cdot (t(x) - p_1(x) - p_2(x)) + x^{2k} \cdot p_2(x)
$$

公式的正确性只需代入验证即可。

### 复杂度分析

数一下所需的运算就会发现，为了相乘两个规模为 $n$ 的多项式，我们需要计算三个规模为 $\frac{n}{2}$ 的乘积——$p_1$、$p_2$ 和 $t$——以及常数次加法、减法和移位（即乘以 $x^k$），这些总共可以在 $O(n)$ 时间内完成。

[主定理](/cs/complexity/master-theorem/)指出，在这种情况下整个算法的渐近复杂度为 $\Theta (n^{\log_2 3}) \approx \Theta (n^{1.58})$：我们的问题被分成 $a = 3$ 个规模缩小 $b = 2$ 倍的子问题，合并需要 $O(n)$ 时间。

### 实现

为简单起见，假设 $n$ 是 2 的幂。如果不是，可以根据情况用下面两种权宜之计之一来补救：

1. 可以把多项式的系数补零到最近的 2 的幂——最坏情况下运行时间会变为原来的 $2^{1.58} \approx 3$ 倍。
2. 可以把多项式的最后一个系数「剥离」出来，把规模为 $(2k + 1)$ 的问题化归为规模 $2k$ 的问题加上常数次加法。

我们采用第一种方法，因为它实现起来更简单。

关于高效实现的主要考虑：

- 尽量少分配额外内存，为此要复用已有的数组。
- 所有算术运算都要实现为对数组的简单线性扫描，这样编译器才能[向量化](/cs/arithmetic/simd)。
- 与其使用 `if (n == 1) c[0] = a[0] * b[0]` 这样的递归基，不如当问题规模小于某个阈值时，改用更高效的平方级朴素乘法。

先给出核心递归过程的代码，再解释它为什么正确：

```cpp
void karatsuba(int *a, int *b, int *c, int n) {
    if (n <= 64) {
        for (int i = 0; i < n; i++)
            for (int j = 0; j < n; j++)
                c[i + j] += a[i] * b[j];
    } else {
        int k = n / 2;
        int l[k], r[k], t[n] = {0};
        for (int i = 0; i < k; i++) {
            l[i] = a[i] + a[k + i];
            r[i] = b[i] + b[k + i];
        }
        karatsuba(l, r, t, k); // считает t
        karatsuba(a, b, c, k); // считает p1
        karatsuba(a + k, b + k, c + n, k); // считает p2
        int *t1 = t, *t2 = t + k;
        int *s1 = c, *s2 = c + k, *s3 = c + 2 * k, *s4 = c + 3 * k;
        for (int i = 0; i < k; i++) {
            int c1 = s2[i] + t1[i] - s1[i] - s3[i];
            int c2 = s3[i] + t2[i] - s2[i] - s4[i];
            c[k + i] = c1;
            c[n + i] = c2;
        }
    }
}
```

三次递归调用之后，数组 $c$ 就是 $p_1$ 与 $p_2$ 的拼接。

之后，为了算出最终的多项式 $c$，最直观的做法是把它在脑中分成四等份，把多项式 $t$ 分成两半 $t_1$ 和 $t_2$，然后对照公式思考每一部分该如何变化：

- $s_1$：保持不变——它是 $p_1$ 的前一半。
- $s_2$：等于 $s_2 + t_1 - s_1 - s_3$，即加上 $t - p_1 - p_2$ 的「前」一半。
- $s_3$：等于 $s_3 + t_2 - s_2 - s_4$，即加上 $t - p_1 - p_2$ 的「后」一半。
- $s_4$：保持不变——它是 $p_2$ 的后一半。

由于[向量化](/cs/arithmetic/simd)的存在，使用尽量「轻」的数据类型很重要，并且尽可能用 AVX 编译：

```cpp
#pragma GCC optimize("O3")
#pragma GCC target("avx2")
```

这个实现相当高效：它能在 1 秒内相乘两个规模为 $4 \cdot 10^5$ 的多项式。

### 思想的推广

类似的方法可以应用于矩阵乘法——这就是[施特拉森算法](https://ru.wikipedia.org/wiki/Алгоритм_Штрассена)。它把两个矩阵分成 $8 = 4 + 4$ 块进行分块相乘，并用巧妙的代数消去 8 次乘法中的 1 次，从而得到 $O(n^{\log_2 7}) \approx O(n^{2.81})$ 的渐近复杂度。

在施特拉森算法和卡拉楚巴算法中，如果把对象分成更多块，都能达到更好的渐近复杂度。不过在现实中并不这么用，因为这类算法的渐近复杂度里藏着不切实际的大常数。
