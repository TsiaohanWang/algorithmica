## 题目

给定一个有向图，图中可能有环，博弈由两名玩家进行，每回合玩家可以沿一条边从当前顶点走到另一个顶点，无法行动的一方输。要求判断：如果游戏从该顶点开始，图中每个顶点对应谁将获胜。这里的一个重要条件是公平性，即在该局面下双方玩家拥有相同的行动集合。

## 思路

我们知道，如果从某顶点存在一条通向必败顶点的转移，那它就是必胜顶点。

如果从某顶点出发的所有边都只通向必胜顶点，那它就是必败顶点。

## 解法

在算法的每一步，我们都尝试为每个顶点计算答案，检查与它相邻的所有顶点；如果没有任何一个顶点的答案被更新，那么所有答案就都已经知道了（如果顶点被标记为必败/必胜——那它就是必败/必胜；否则它就是和局，因为如果我们无法为任何顶点更新答案，那么剩下的就只有那些可以无限玩下去的顶点）。

这样的解法复杂度已经是 $O(mn)$，也存在更简单的同渐近解法。让我们想想如何改进。

我们有一些一开始就知道是必败的顶点（即叶子）。从每个这样的顶点出发，沿反向边做深度优先搜索。对每个顶点可能有三种情况：

1) 它已经被标记为必败或必胜，那么我们就可以直接不再进入它，因为从它出发的 DFS 已经启动过了。

2) 如果我们想进入的顶点尚未被标记，并且此刻我们是从必败顶点进入的，就直接把该顶点标记为必胜。

3) 如果我们想进入的顶点尚未被标记，并且此刻我们是从必胜顶点进入的，就检查该顶点的所有边是否都已经被查看过。（检查某顶点的所有边是否都已查看过，可以借助辅助数组 $degree_{u}$ 完成，其中存储着从顶点 $u$ 出发的未查看边的数量）。

于是在算法结束时会有三种类型的顶点：必败/必胜/度数 $degree_{u} \> 0$ 的顶点；但正如我们所说，如果某个顶点在 $n$ 步之后仍无法判断它是哪种，那它就是和局。

## 代码

``` C++ numberLines
vector<int> g[N];
bool W[N], L[N], used[N];
int degree[N];

void dfs(int v) {
    used[v] = 1;
    for (auto to : g[u]) {
        if (!used[to]) {
            --degree[to];
            if (L[v]) {
                W[to] = 1;
            }
            else if (degree[to] == 0) {
                L[to] = 1;
            }
            else {
                continue;
            }
            dfs(to);
        }
    }
}
```

## 把博弈归约为图博弈

任何公平博弈，只要我们知道所有顶点上的全部可能行动，并且行动只取决于当前玩家，都可以归约为图上的博弈，因为我们可以把所有游戏状态做成顶点，并从每个状态向所有能够到达的状态连边。
