先从我们能想到的最经典的数学博弈例子说起：

> 桌上有一堆 $n$ 根火柴。两名玩家轮流从堆中取火柴，每次可取一根、两根或三根。取走最后一根火柴的人获胜。要求在双方都最优的情况下判断谁获胜。

所有这类问题都用同一种方法解决：先看小规模情形的答案，再用动态规划。这里的动态规划状态是 $f_k$——表示当火柴数为 $n$ 且轮到第一个玩家行动时他能否获胜。它的递推如下：

$$ f_k = \lnot f_{k-1} \lor \lnot f_{k-2} \lor \lnot f_{k-3} = \lnot (f_{k-1} \land f_{k-2} \land f_{k-3}) $$

也就是说，必须存在一条通向某个必败动态规划状态的转移（或者等价地说，不应存在通向必胜状态的转移——动态规划的所有转移都应通向必败状态）。

**注记。** 当然，这里其实并不需要动态规划，答案只取决于 $n$ 是否能被 4 整除，但出于教学目的，我们还是来分析这个例子。

## 图上的博弈

一般情况下，博弈的状态可能构成远比「$n$ 根火柴」复杂得多的结构。

任何博弈都可以描述为一个（可能是无限的）*博弈状态*图，状态之间存在转移。玩家轮流选择沿哪条转移前进。这个图中的某些状态被标记为*终止态*

一个状态被称为*必胜态*，如果在它上面开始的玩家获胜；否则称为*必败态*。图中可能存在环，有时双方都愿意沿着环走。例如在国际象棋中，有时重复走子是有利的（不过对局本身仍然不能无限进行下去，因为三次重复同一局面会导致和棋——大多数策略游戏中都有类似规则）。我们把那些最优策略就是沿着环走的顶点称为*和棋态*。

这类博弈——其中要想让一个玩家变好，就必须让另一个玩家变差同样多——被称为*零和博弈*（为什么叫这个名字，以及什么是非零和博弈——下文会读到）。它们几乎总是用图上一类特殊的动态规划来求解，这类动态规划叫做*逆向分析*。

## 逆向分析

我们把火柴的例子推广一下，并给出必胜与必败的判定标准：

* 顶点是*必败*的——如果它的所有转移都通向必胜顶点。
* 顶点是*必胜*的——如果从它出发存在通向必败顶点的转移。
* 顶点是*和棋*的——如果它既不是必胜也不是必败（它至少有一条转移通向另一个和棋顶点，并且可能还有一些转移通向必胜顶点）。

利用这些判定标准，可以设计一个通用算法：检查所有顶点是否满足这些标准并更新它们的状态，直到没有状态未知的顶点为止。

**正确性。** 先考虑无环博弈的情形。这种情况更简单：既然没有环，自然也就没有和棋顶点。

考虑由未知顶点组成的图 $U$。作为原图的子图，它也是无环的，因此必然存在一个顶点 $v$，它没有通向 $U$ 中顶点的出边——如果它有边，那么这些边通向状态已知的顶点。于是这一步我们就能确定顶点 $v$ 的胜负性，它只取决于这些边是否通向某个必败状态。

回到一般情形——图中可能有环。我们的算法不会把和棋顶点标记为和棋，因为这里出现了先有鸡还是先有蛋的问题——初始时不存在和棋的终止顶点，而且按定义我们无法把顶点标记为和棋。但事实证明，算法并不需要修改——只需把那些无法确定胜负的顶点都宣布为和棋顶点即可。

为什么？假设算法运行了若干轮后停下来时，图中还剩下一些状态未知的顶点，它们构成子图 $U$。在这个子图中，没有任何顶点通向必败顶点——否则它会被标记为必胜，算法会继续运行。同样，也不存在没有出边通向 $U$ 中顶点的顶点——否则这样的顶点会被标记为必败。于是，在这个子图中的最优策略就是始终留在子图内部——出口只通向必胜顶点——因此其中的所有顶点都是和棋顶点。

**复杂度。** 可以把所有终止顶点加入队列，并在队列中维护那些已经确定胜负但尚未处理的顶点。

* 处理必败顶点时，要把所有存在指向当前顶点的边的顶点标记为必胜（为此需要保存反向图）。
* 处理必胜顶点时，要删除反向图中的所有边，并把那些已经没有通向未知顶点的边、且此前未被标记过的顶点标记为必败。

复杂度为 $O(n + m)$，与任何 BFS 相同。


```c++
vector<int> g[maxn], t[maxn]; // списки смежности прямого и обратного графа
int cnt[maxn]; // счётчик исходящих рёбер

enum StatusType { win, loss, unknown };
StatusType status[maxn]; // выигрышность вершины;
// по умолчанию все кроме терминальных считаются unknown
// те, кто в итоге остаются unknown -- ничейные

queue<int> q = {/* нужно заранее добавить сюда все терминальные вершины*/};

while (!q.empty()) {
    int v = q.front();
    q.pop();
    for (int u : t[v]) {
        cnt[u]--; // удаляем это ребро
        if (status[v] == unknown) {
            // из u есть ребро в проигрышную -- значит она выигрышная
            if (status[v] == loss)
                status[u] = win;
            // все ребра u ведут в выигрышные вершины -- значит она проигрышная
            if (status[v] == win && cnt[u] == 0)
                status[u] = loss;
            // если после проверок у вершины определилась выигрышность, то её можно добавить в очередь
            if (status[v] != unknown)
                q.push(u);
        }
    }
}
```

和动态规划常见的情况一样，有时写递归式的动态规划计算比迭代式更简单。不过这只适用于无环的动态规划，而一般图中可能有环。尽管如此，我们仍把逆向分析的递归实现视为标准写法，因为它在后续可以做一些剪枝和优化：

StatusType dfs(int v) {
    if (status[v] != unknown)
        return status[v];
    status[v] = loss;
    // изменим статус, когда найдём переход в проигрышную вершину

## 极小极大博弈

有时终止状态的等级比单纯的必败/必胜更丰富。这类博弈在一般情况下被称为*极小极大（minimax）*博弈——终止顶点中可以写任意数字，第一个玩家的目标是最到最大的数，第二个玩家则是走到最小的数。我们分别称这两个玩家为 Max 和 Min。

这类问题的解法与逆向分析没有本质区别，只不过现在顶点的「优劣」变成了所有转移到子节点中的最小值/最大值。

## 大图的逆向分析

有时博弈很复杂，它的全部状态无法放入内存——例如国际象棋或围棋。它们是有限的无环博弈，在最优对弈下胜者唯一确定，理论上可以用逆向分析求出。但问题在于：算法运行时间太长。

对某些博弈，人们以巨大的努力算出了所有可能状态下的结局（如国际跳棋；至于国际象棋——目前只有残局库）。

逆向分析需要优化。

### 限制搜索深度

为此需要用 BFS 而不是 DFS 遍历图的状态，并在走完 $K$ 步时停止。这时只有一个问题：如何判断 $K$ 步之后当前棋盘上的对局结果，毕竟游戏还没有结束。为此需要设计一个近似函数，它能**数值化地评估第一个玩家领先多少**。

对国际象棋，可以简单地给每个棋子赋一定分值，为每个玩家计算这个总和，再把两个玩家的分数之差作为函数值。这样，如果第一个玩家有策略能在 $K$ 步内稳吃掉对方的皇后而自身损失不大，逆向分析就能发现这一点。

显然这能显著加快速度：可以选取足够小的 $K$ 来控制时间。如果规定了时限，也可以在时限耗尽时停止搜索。不过，经过这种优化的逆向分析所给出的走法当然不再是最优的。话虽如此，国际象棋的最优策略至今也没能找到（而国际跳棋的，顺便一提，已经找到了）。

### Alpha–Beta 剪枝

<img width='500px' src="https://upload.wikimedia.org/wikipedia/commons/thumb/9/91/AB_pruning.svg/400px-AB_pruning.svg.png">

考虑标准的极小极大。图中非叶顶点里写的是从该顶点先手行动的玩家的收益。

图中所示是一个零和博弈：其中第一个玩家与第二个玩家的收益之和为零，因此图上每个顶点只写了从该顶点先手行动的玩家的收益。

我们用一个具体例子来说明优化思路：假设我们要从状态 $X$（比如根节点）决定往哪里走。我们已经考察了第一个和第二个儿子，发现如果走第一个，第二个玩家的收益是 -3；如果走第二个，收益是 -6。我们的目标是让他的收益最小，因为这样我们的收益就最大。目前根节点处的最佳走法是第二个儿子，收益为 6。

我们再进入第三个儿子，称它为 $Y$，说不定第二个玩家在那里能拿到比 -6 更多的收益。进入 $Y$ 的第一个儿子并完整处理它，我们发现走这条路时，第二个玩家在最优对弈下能拿到 -5。可以断言，$Y$ 的第二个儿子就完全不用检查了。为什么？因为已经清楚，如果从根 $X$ 走进顶点 $Y$，第二个玩家的收益至少是 -5（甚至可能更多），因此第一个玩家的收益至多为 5。而走 $X$ 的第二个儿子已经能拿到 6，更大，所以再考虑顶点 $Y$ 已经没有意义——我们肯定不会走它。

剪掉这些多余分支的做法就叫 alpha–beta 剪枝。显然它能大幅加速搜索，因为我们直接丢弃了整棵搜索子树，而且与上一种优化不同，这种优化仍然能找出最优走法。

任意图上的博弈
设两名玩家在某个图 G 上进行博弈。也就是说，当前游戏状态就是图的某个顶点，从每个顶点出发的边通向下一步可以到达的顶点。

我们考虑最一般的情形——带环的任意有向图。要求对给定的初始位置判断在双方都最优对弈下谁将获胜（或判断结果是否为和棋）。

我们会非常高效地解决这个问题——在线性于边数的时间内求出图中所有顶点的答案——O(M)。

算法描述
关于图的某些顶点，事先已知它们是必胜或必败的；显然，这样的顶点没有出边。

我们有以下事实：

如果从某个顶点存在一条通向必败顶点的边，则该顶点是必胜的；
如果从某个顶点出发的所有边都通向必胜顶点，则该顶点是必败的；
如果在某一时刻仍有未确定的顶点，但它们都不符合第一条或第二条规则，那么所有这些顶点都是和棋的。
于是，复杂度为 O(NM) 的算法已经清楚了——我们枚举所有顶点，尝试对每个顶点应用第一条或第二条规则，如果产生了任何变化就重新来过。

然而，这一查找与更新过程可以大幅加速，把复杂度降到线性。

枚举所有事先已知必胜或必败的顶点。从每个这样的顶点出发执行如下深度优先搜索。这个深度优先搜索将沿着反向边移动。首先，它不会进入那些已经被确定为必胜或必败的顶点。其次，如果深度优先搜索试图从必败顶点走到某个顶点，它就把该顶点标记为必胜并进入它。而如果深度优先搜索试图从必胜顶点走到某个顶点，它必须检查该顶点是否所有边都通向必胜顶点。如果在每个顶点中维护一个指向必胜顶点的边数计数器，这个检查可以在 O(1) 内完成。于是，如果深度优先搜索试图从必胜顶点走到某个顶点，它就增加该顶点的计数器；当计数器与该顶点的出边数相等时，就把该顶点标记为必败，并进入它。否则，如果目标顶点始终没有被确定为必胜或必败，深度优先搜索就不进入它。

总之，我们的算法恰好访问每个必胜顶点和每个必败顶点一次，而和棋顶点根本不会被访问。因此，复杂度确实是 O(M)。

实现
考虑深度优先搜索的实现，假设博弈图已构建在内存中、出度已计算并存入 degree（它就是那个计数器，当存在通向必胜顶点的边时它会被递减），并且初始必胜/必败顶点已经标记好。

vector<int> g [100];
bool win [100];
bool loose [100];
bool used[100];
int degree[100];

void dfs (int v) {
	used[v] = true;
	for (vector<int>::iterator i = g[v].begin(); i != g[v].end(); ++i)
		if (!used[*i]) {
			if (loose[v])
				win[*i] = true;
			else if (--degree[*i] == 0)
				loose[*i] = true;
			else
				continue;
			dfs (*i);
		}
}
示例题目：「警察与小偷」
为了让算法更清晰，我们在一个具体例子上看它。

题目描述。有一个 M×N 格的场地，某些格子不能进入。已知警察和小偷的初始坐标。地图上还可能有出口。如果警察和小偷处于同一格，则警察获胜。如果小偷到达出口所在的格子（且该格没有警察），则小偷获胜。警察可以朝 8 个方向移动，小偷只能朝 4 个方向移动（沿坐标轴）。警察和小偷都可以选择跳过一回合。警察先行动。

建图。我们来构建博弈图。我们需要形式化游戏规则。当前游戏状态由警察的坐标 P、小偷的坐标 T，以及决定下一步由谁行动的布尔变量 Pstep 确定。因此，图的顶点由三元组 (P,T,Pstep) 定义。建图很容易，按条件对应即可。

接下来需要确定哪些顶点初始就是必胜或必败的。这里有个微妙的点。顶点的胜负性除了坐标之外还取决于 Pstep——当前轮到谁走。如果轮到警察走，那么当警察与小偷坐标重合时该顶点必胜；如果该顶点不是必胜且小偷在出口处，则该顶点必败。如果轮到小偷走，那么当小偷在出口处时该顶点必胜；如果该顶点不是必胜且警察与小偷坐标重合，则该顶点必败。

唯一需要决定的问题是：是显式地建图，还是在深度优先搜索中「边走边建」（即动态生成）。一方面，预先建图出错的可能性更小。另一方面，这会增加代码量，运行时间也会比边走边建慢几倍。

整个程序的实现：

struct state {
	char p, t;
	bool pstep;
};

vector<state> g [100][100][2];
// 1 = policeman coords; 2 = thief coords; 3 = 1 if policeman's step or 0 if thief's.
bool win [100][100][2];
bool loose [100][100][2];
bool used[100][100][2];
int degree[100][100][2];

void dfs (char p, char t, bool pstep) {
	used[p][t][pstep] = true;
	for (vector<state>::iterator i = g[p][t][pstep].begin(); i != g[p][t][pstep].end(); ++i)
		if (!used[i->p][i->t][i->pstep]) {
			if (loose[p][t][pstep])
				win[i->p][i->t][i->pstep] = true;
			else if (--degree[i->p][i->t][i->pstep] == 0)
				loose[i->p][i->t][i->pstep] = true;
			else
				continue;
			dfs (i->p, i->t, i->pstep);
		}
}


int main() {

	int n, m;
	cin >> n >> m;
	vector<string> a (n);
	for (int i=0; i<n; ++i)
		cin >> a[i];

	for (int p=0; p<n*m; ++p)
		for (int t=0; t<n*m; ++t)
			for (char pstep=0; pstep<=1; ++pstep) {
				int px = p/m, py = p%m, tx=t/m, ty=t%m;
				if (a[px][py]=='*' || a[tx][ty]=='*')  continue;
				
				bool & wwin = win[p][t][pstep];
				bool & lloose = loose[p][t][pstep];
				if (pstep)
					wwin = px==tx && py==ty,   lloose = !wwin && a[tx][ty] == 'E';
				else
					wwin = a[tx][ty] == 'E',   lloose = !wwin && px==tx && py==ty;
				if (wwin || lloose)  continue;

				state st = { p, t, !pstep };
				g[p][t][pstep].push_back (st);
				st.pstep = pstep != 0;
				degree[p][t][pstep] = 1;
				
				const int dx[] = { -1, 0, 1, 0,   -1, -1, 1, 1 };
				const int dy[] = { 0, 1, 0, -1,   -1, 1, -1, 1 };
				for (int d=0; d<(pstep?8:4); ++d) {
					int ppx=px, ppy=py, ttx=tx, tty=ty;
					if (pstep)
						ppx += dx[d],  ppy += dy[d];
					else
						ttx += dx[d],  tty += dy[d];
					if (ppx>=0 && ppx<n && ppy>=0 && ppy<m && a[ppx][ppy]!='*' &&
						ttx>=0 && ttx<n && tty>=0 && tty<m && a[ttx][tty]!='*')
					{
						g[ppx*m+ppy][ttx*m+tty][!pstep].push_back (st);
						++degree[p][t][pstep];
					}
				}
			}

	for (int p=0; p<n*m; ++p)
		for (int t=0; t<n*m; ++t)
			for (char pstep=0; pstep<=1; ++pstep)
				if ((win[p][t][pstep] || loose[p][t][pstep]) && !used[p][t][pstep])
					dfs (p, t, pstep!=0);

	int p_st, t_st;
	for (int i=0; i<n; ++i)
		for (int j=0; j<m; ++j)
			if (a[i][j] == 'C')
				p_st = i*m+j;
			else if (a[i][j] == 'T')
				t_st = i*m+j;

	cout << (win[p_st][t_st][true] ? "WIN" : loose[p_st][t_st][true] ? "LOSS" : "DRAW");

}
