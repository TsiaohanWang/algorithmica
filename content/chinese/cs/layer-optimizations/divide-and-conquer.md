看基础解法中动态规划的转移公式：

$$
f[i, j] = \min_{k < i} \{f[k, j-1] + (x_{i-1}-x_k)^2 \}
$$

记 $opt[i, j]$ 为该状态的最优 $k$——即上面表达式取到 argmin 的位置。为保证唯一性，若最优下标不唯一，则取其中最右的。

具体在线段覆盖点的问题里可以注意到：

$$
opt[i + 1, j] \leq opt[i, j]
$$

直觉是这样的：如果需要覆盖更大的点前缀，那么最后一段的起点肯定不会更早。

### 算法

设我们已经知道 $opt[l, k]$ 和 $opt[r, k]$，想为介于 $l$ 和 $r$ 之间的某个 $i$ 算 $opt[i, k]$。利用上面的不等式，可以把 $i$ 的最优下标搜索区间从整个 $[0, i - 1]$ 缩小到 $[opt[l, k], opt[r, k]]$。

我们这样做：写一个递归函数，它在知道第 $k$ 层动态值的 $opt$ 落在 $l'$ 和 $r'$ 之间的情况下，计算区间 $[l, r]$ 上的动态值。这个函数取区间 $[l, r]$ 的中点，用线性遍历为它算答案，然后递归处理两半，分别把边界设为 $[l', opt]$ 和 $[opt, r']$：

```c++
// [ l,  r] -- 在第 k 层要算哪些动态值
// [_l, _r] -- 它们的答案可能落在哪里
void solve(int l, int r, int _l, int _r, int k) {
    if (l > r)
        return; // 区间为空 -- 退出
    int opt = _l, t = (l + r) / 2;
    // 计算 f[t][k] 的答案
    for (int i = _l; i <= min(_r, t); i++) { 
        int val = f[i + 1][k - 1] + cost(i, t - 1);
        if (val < f[t][k])
            f[t][k] = val, opt = i;
    }
    solve(l,     t - 1, _l,  opt, k);
    solve(t + 1, r,     opt, _r,  k);
}
```

然后对每一层依次调用这个函数：

```c++
for (int k = 1; k <= m; k++)
    solve(0, n - 1, 0, n - 1, k);
```

由于每次调用区间 $[l, r]$ 大约减半，递归深度为 $O(\log n)$。由于同一「层」上所有元素的搜索区间至多在边界处相交，每层搜索总共检查 $O(n)$ 个不同下标。因此重算整个一层需要 $O(n \log n)$ 次操作，而不是基础解法的 $O(n^2)$。

于是我们把复杂度改进到 $O(n \cdot m \cdot \log n)$。
