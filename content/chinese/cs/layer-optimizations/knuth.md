前一种优化方法依赖这样的事实：$opt[i, j] \leq opt[i, j + 1]$。

注意到 $opt$ 对第二个参数也是单调的，可以进一步改进复杂度：

$$
opt[i - 1, j] \leq opt[i, j] \leq opt[i, j + 1]
$$

在线段覆盖问题中，这一点成立的原因大体相同：如果可用的线段更多，那么最优解中最后一段肯定不会比以前更长。

### 算法

用最直接的方式利用得到的这些不等式：对每个状态，只从 $opt[i - 1, j]$ 到 $opt[i, j + 1]$ 枚举所有元素。

为了在我们到达状态 $(i, j)$ 时，$opt[i - 1, j]$ 和 $opt[i, j + 1]$ 这两个边界已经算好，我们按 $i$ 递增、$j$ 递减的顺序遍历。

```c++
for (int i = 1; i <= n; i++) {
    for (int j = m; j >= 1; j--) {
        for (int k = opt[i - 1][j]; k <= opt[i][j + 1]; k++) {
            int val = f[i + 1][k-1] + cost(i, j);
            if (val < f[t][k])
                f[t][k] = val, opt[i][j] = i;
        }
    }
}
```

实现非常简洁：它只比基础解法多 3 行。

### 复杂度

事实证明这运行得很快。要理解为什么，把每个状态我们查看的元素个数写出来并求和：

$$
\sum_{i, j} (opt[i, j+1] - opt[i-1, j] + 1) = nm + \sum_{ij} (opt[i, j+1] - opt[i-1, j])
$$

注意，除边界外的所有元素在和中恰好出现两次——一次带加号、一次带减号——因此可以约掉。边界元素有 $O(n)$ 个，每个量级为 $O(n)$。因此总复杂度为 $O(n \cdot m + n \cdot n) = O(n^2)$。
