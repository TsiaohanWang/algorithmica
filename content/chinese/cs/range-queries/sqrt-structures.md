根号优化可以用于很多地方，尤其是数据结构语境。

## 数组上的根号分解

假装我们不知道[线段树](/cs/segment-tree)，看下面这道题。

**题目。** 给长度 $n$ 的数组 $a$。需要回答 $q$ 个查询，两类之一：

1. 求区间 $[l, r]$ 的和。
2. 把区间 [l, r] 上所有元素加 $x$。

把整个数组按 $c \approx \sqrt{n}$ 个元素一块分成若干块，并算每块的和。由于块互不相交，总计在 $O(n)$ 内完成。

```c++
// c 既是块数也是块大小；它应略大于根号
const int maxn = 1e5, c = 330;
int a[maxn], b[c], add[c];

for (int i = 0; i < n; i++)
    b[i / c] += a[i];
```

再建一个大小为 $\sqrt n$ 的数组 `add`，用于块上的延迟加操作：认为第 $i$ 个元素的实际值为 `a[i] + add[i / c]`。

现在可以在每次查询 $O(\sqrt n)$ 次操作内回答第一类查询：

1. 对完全落在查询内的所有块，直接取已算好的和相加。
2. 对只部分与查询相交的块（最多两个——右块和左块），遍历所需元素逐个加入答案。

实现风格很多，作者偏好这种：

```c++
int sum(int l, int r) {
    int res = 0;
    while (l <= r) {
        // 如果我们在块首且块完全在查询内
        if (l % c == 0 && l + c - 1 <= r) {
            res += b[l / c];
            l += c; // 可以一次跳过一个块
        }
        else {
            res += a[l] + add[l / c];
            l += 1;
        }
    }
    return res;
}
```

更新写起来差不多——对完全覆盖的块更新 `add` 和和，对其余更新单个元素：

```c++
void upd(int l, int r, int x) {
    while (l <= r) {
        if (l % c == 0 && l + c - 1 <= r) {
            b[l / c] += c * x;
            add[l / c] += x;
            l += c;
        }
        else {
            b[l / c] += x;
            a[l] += x;
            l++;
        }
    }
 }
```

两个操作都运行在 $O(\sqrt n)$，因为所需的「中间」块总不超过 $\sqrt n$ 个，而边界块中元素总计不超过 $2 \sqrt n$ 个。

### 内部结构

根号分解的块里不仅能存某个子段函数的值，还能存各种结构。

例如，每块内放一个哈希表，就能回答「区间上等于 $x$ 的元素个数」；放排序数组就能解决「区间上小于 $x$ 的数的个数」或「矩形和」之类的题。

这些情形下块大小对速度影响很大。前面为简单起见，块数与块大小用同一个常数，但实践里往往需要调整。

为此甚至不应看「整块」与「逐项」部分的复杂度，而应看它们实际的相对运行时间——要知道访问某个 treap 绝不止比线性、[好向量化](/cs/arithmetic/simd)的数组遍历慢对数倍。也正因如此，根号启发式里根号常「小于」对数。

## 移动元素

**题目。** 给长度 $n$ 的数组 $a$。需要回答 $q$ 个查询，三类之一：

1. 把元素 $x$ 插入位置 $k$（它左边恰好有 $k$ 个元素）。
2. 删除位置 $k$ 的元素。
3. 求区间 $[l, r]$ 的最小值。

这里不能直接套前面方法，原因同不能套线段树一样——插入、删除元素会改变所有右侧邻居的下标。需要把元素存在某种更灵活、不依赖静态下标的结构里。

把所有元素分成根号块，每块里存它所有元素的列表（`vector` 或任何类似容器），以及该块的最小值。

现在来插入查询时，遍历所有块，找到所需块（它之前的元素少于 $k$ 个、连同它则多于），把元素插进去，只需按其大小从零重建整个块。

删除类似——找到块、找到元素并删除。求最小值——取所有被完全覆盖块的最小值，在两个边界块上线性遍历取前缀或后缀的最小值。

注意，为找边界块，现在不能再简单地把边界除以常数——块大小是动态的，要找到某块的起始下标，需要把之前所有块的大小加起来。

```cpp
vector< vector<int> > blocks;

// 返回块下标与块内元素下标
pair<int, int> find_block(int pos) {
    int idx = 0;
    while (blocks[idx].size() <= pos)
        pos -= blocks[idx++].size();
    return {idx, pos};
}
```

这种形式的解只在最初运行良好——每个操作至多查看 $O(\sqrt n)$ 个块和 $O(\sqrt n)$ 个单独元素，但随时间可能块过多或出现太大块。有两种解决办法：

1. 每次插入或删除后看受影响的块，若大小超过 $2 \cdot \sqrt n$ 就分成两个；若它与其邻居之和小于 $n$ 就把它们合并成一个。
2. 建全局操作计数器，每 $\sqrt q$ 次查询就整体重建结构（写回数组、重新分成等块）。

第一种情形我们可能花 $O(\sqrt n)$ 次操作在 split 和 merge 上，但保证不变量；第二种恰好是 $\sqrt n$ 乘构建代价。

第二种更易编码（反正结构无论如何都要初始构建）。值得注意的是，有时重建结构不如维持平衡状态划算——当 merge 比从零重建便宜时。

更现实的例子：IOI 2011「[Dancing Elephants](https://wcipeg.com/problem/ioi1122)」。
