如果题目是在 2d 空间中给出的，我们可以对结构做很多奇奇怪怪的事情。本质上，我们想把它们组合在一起，在每一时刻使用更高效、更方便的那个。

怎么计算这种结构的时间和内存？设有结构 $A, B$，时间与内存开销分别为 $time_A, time_B, memory_A, memory_B$。那么在每个单元里存一个结构 B 的结构 A，总时间和内存复杂度为 $O(time_A \\cdot time_B), O(memory_A \\cdot memory_B)$。

#### 二维线段树

在线段树的顶点里不仅可以存一个数，还可以再存一棵线段树。把它推广到多维情形不太舒服，但用于 2d 题目大概长这样：

``` c++ numberLines
int get_inside(int v, int tl, int tr, int l, int r, segtree_outside &root) {
    if (tl >= r || l >= tr) {
        return INT32_MAX;
    }
    if (l <= tl && tr <= r) {
        return root.t[v].val;
    }
    int tm = (tl + tr) / 2;
    return min(get_inside(2 * v, tl, tm, l, r, root), get_inside(2 * v + 1, tm, tr, l, r, root));
}

int get_outside(int v, int tl, int tr, int l, int r, int a, int b) {
    if (tl >= r || l >= tr) {
        return INT32_MAX;
    }
    if (l <= tl && tr <= r) {
        return get_inside(1, 0, n - 1, a, b, t[v]);
    }
    int tm = (tl + tr) / 2;
    return min(get_outside(2 * v, tl, tm, l, r, a, b), get_outside(2 * v + 1, tm, tr, l, r, a, b));
}
```

#### 动态 merge sort tree

如果我们想在每个线段树顶点维护排序好的子段、同时支持修改值的查询，可以写类似 [merge sort tree](merge_sort_tree "wikilink") 的东西，但每个顶点里存[treap](декартово_дерево "wikilink") 而不是数组。

#### 树状数组

在很多可怕的二维结构里，可以用[树状数组](дерево_Фенвика "wikilink")实现外部结构。这种方法会大大简化题目代码，还显著加快运行时间。例如，对动态 merge sort tree，我们完全可以用 [treap](Декартово_дерево "wikilink") 的树状数组。你会同意，写这样的代码要简单得多。
