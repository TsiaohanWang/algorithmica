---
title: 上包络线与下包络线
weight: 5
---

对大量应用而言，我们真正需要的其实不是凸包，而只是它的一半（右侧/左侧或上侧/下侧），称为*包络线*（英文 *envelope*）。

包络线构建起来稍简单些：可以按 $x$ 排序点，然后按这个顺序遍历，在栈上维护当前前缀的上包络线。加入新的点时，需要类似地检查并删除栈上的若干上侧点：

```c++
vector<r> upper_envelope(vector<r> points) {
    sort(points.begin(), points.end(), [](r a, r b){
        return a.x < b.x;
    });

    vector<r> s = {p0};
    for (r p : points) {
        while (...) {
            s[s.size()-2] = s[s.size()-1];
            s.pop_back();
        }
        s.push_back(p);
    }

    return s;
}
```

与整条凸包相比，包络线更好处理：容易求交、合并和二分查找（例如找切线）。顺便一提，合并可以线性完成——用双指针同时遍历两条包络线——这让我们也能用「分治」法在 $O(n \log n)$ 内构建包络线。

有时值得把凸包拆成两条包络线分别处理。这种做法的主要缺点是：要么多写一倍的代码，要么把代码写得让所有内部过程不区分「上」和「下」——这样下包络线的点可以传给与上包络线相同的例程，只需把 $y_i$ 换成 $-y_i$。

构建凸包也可以这样做：先构建上包络线，再构建下包络线，然后把其中一条翻转过来拼到另一条末尾。如果点已按 $x$、$y$ 或任意一条直线排序，算法运行在 $O(n)$。这种方法称为*Andrew 算法*。

### 动态凸包

把凸包当作两条包络线来操作，可以相对简单地处理加点查询：把包络线包进 `std::set` 或任意其他树中，使它们按 $x$ 排序。加入点时，找到它在树中的位置，检查它是否在包络线之上，然后可能删除它的一些左右邻居。

处理从集合*删除*点更麻烦。如果查询预先已知，用根号启发式或 dynamic connectivity 问题的思路更简单：只维护在当前整个块中始终存在的点，把删除归结为添加。

如果删除查询必须在线处理（fully dynamic convex hull），那就有一个[非常麻烦的算法](https://neerc.ifmo.ru/wiki/index.php?title=%D0%94%D0%B8%D0%BD%D0%B0%D0%BC%D0%B8%D1%87%D0%B5%D1%81%D0%BA%D0%B0%D1%8F_%D0%B2%D1%8B%D0%BF%D1%83%D0%BA%D0%BB%D0%B0%D1%8F_%D0%BE%D0%B1%D0%BE%D0%BB%D0%BE%D1%87%D0%BA%D0%B0_%28%D0%B4%D0%BE%D1%81%D1%82%D0%B0%D1%82%D0%BE%D1%87%D0%BD%D0%BE_log%5E2_%D0%BD%D0%B0_%D0%B4%D0%BE%D0%B1%D0%B0%D0%B2%D0%BB%D0%B5%D0%BD%D0%B8%D0%B5/%D1%83%D0%B4%D0%B0%D0%BB%D0%B5%D0%BD%D0%B8%D0%B5%20)，约 250–300 行代码：它要为搜索树中所有子树维护包络线，并在重建树时快速合并包络线。算法每次查询 $O(\log^2 n)$：合并顶点的包络线时，用二分查找并分 7 种情况讨论。
