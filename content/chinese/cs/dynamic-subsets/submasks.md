给一个位掩码 m。要求高效地枚举它的所有子掩码，即只含 m 中已置位比特的掩码 s。

直接看基于位运算技巧的实现：

int s = m;
while (s > 0) {
	... 可以使用 s ...
	s = (s-1) & m;
}
或者用更紧凑的 for：

for (int s=m; s; s=(s-1)&m)
	... 可以使用 s ...
两个版本代码唯一的例外是：等于零的子掩码不会被处理。它的处理要移出循环，或用不太优雅的结构，例如：

for (int s=m; ; s=(s-1)&m) {
	... 可以使用 s ...
	if (s==0)  break;
}
分析为什么上面的代码确实找到给定掩码的所有子掩码，不重复，在 O (它们数量) 内，且按递减顺序。

设当前子掩码是 s，要转到下一个子掩码。给 s 减一，这样就移除了最右的置位位，而它右边的所有位都置 1。然后删除所有不属于掩码 m、因此也不能属于子掩码的「多余」置位位。删除用位运算 \& m。结果我们把 s-1 「截断」到它能取的最大值，即 s 之后按递减顺序的下一个子掩码。

于是这个算法按严格递减顺序生成给定掩码的所有子掩码，每次转移用两次基本操作。

特别看 s = 0 的时刻。执行 s-1 后得到所有位都置位的掩码（-1 的二进制表示），用 (s-1) \& m 删除多余位后，得到的正是掩码 m。因此对 s = 0 要小心——如果不及时在零掩码处停下，算法可能进入死循环。

枚举所有掩码及其子掩码。复杂度 3^n
许多题目，尤其是掩码动态规划，要求枚举所有掩码，并对每个掩码枚举所有子掩码：

for (int m=0; m<(1<<n); ++m)
	for (int s=m; s; s=(s-1)&m)
		... 使用 s 和 m ...
证明内层循环总共执行 O (3^n) 次迭代。

证明：方法 1。考虑第 i 位。一般而言它有三种情况：它不在掩码 m 中（因此也不在子掩码 s 中）；它在 m 中但不在 s 中；它同时位于 m 和 s。共有 n 位，因此不同组合共 3^n 个，证毕。

证明：方法 2。注意如果掩码 m 有 k 个置位位，它就有 2^k 个子掩码。由于长度为 n、有 k 个置位位的掩码有 C_n^k 个（见「二项式系数」），总组合数为：

 \sum_{k=0}^n C_n^k 2^k. 

算这个和。注意它正是 (1+2)^n 的二项式展开，即 3^n，证毕。

来解这样的题：有 $n$ 个元素的集合，要把每个元素归到某个类，最小化类的总成本。类的成本是所有元素集合的成本，集合成本作为 $cost_{subset},\\ 0 \\le subset \\le 2^n$ 输入。可以用动态规划 $dp_{mask} = \\displaystyle \\max_{subset\\ \\subset\\ mask} cost_{subset} + dp_{mask \\setminus subset}$。「在直」解枚举所有二进制掩码对，运行在 $O(4^n)$。

## 思路

如果作为 $subset$ 不枚举所有掩码，而只枚举 $mask$ 的子掩码，总运行时间会显著减少。为什么？看动态规划的一次转移——我们有 $subset,\\ mask \\setminus subset$。于是集合分成三部分：$subset$ 中的元素、$mask \\setminus subset$ 中的元素、以及没落到任何地方的元素。每个划分恰好对应一次动态规划转移。而把集合分成三个类的方式数是 $3^n$。因此这个算法运行在 $O(3^n)$。

## 实现

还需弄清如何高效枚举给定掩码的所有子掩码。想这样一个算法。先取完整子集。然后不断把对应的二进制数减 1，之后清零所有不属于掩码的位。这种情况会发生什么？

如果 $subset$ 二进制中最后一个 1 在位置 $x$，那么 $(subset - 1) \\& mask$ 将包含 $subset$ 在 $x$ 左侧的所有 1，以及 $mask$ 在 $x$ 右侧的所有 1。于是对每个子掩码，我们从左到右逐渐删除那些不属于掩码的元素。

``` c++ numberLines
dp[0] = 0;
for (int mask = 1; mask < (1 << n); mask++) {
    for (int submask = mask; submask > 0; submask = (submask - 1) & mask) {
        dp[mask] = max(dp[mask], dp[mask ^ submask] + cost[submask];
    }
}
```
