所有整数都可以用二进制记数法来表示：

$$
\begin{aligned}
   5_{10}   &= 101_2 = 4 + 1
\\ 42_{10}  &= 101010_2 = 32 + 8 + 2
\\ 256_{10} &= 100000000_2 = 2^8
\end{aligned}
$$

由于在电路层面几乎所有的逻辑都是二进制的，计算机正是用这种表示来存储数字：每个整型变量指向一个 8 位（`char`）、16 位（`short`）、32 位（`int`）或 64 位（`long long`）的存储单元。

### 字节序

这种格式唯一的歧义在于位的存储顺序——也被称为*端序（endianness*）。根据架构的不同，它可能有所差异：

- 在 *little-endian* 方案下，先存储*低位*。例如，数字 $42_{10}$ 会存储为 $010101$。
- 在 *big-endian* 格式下，先存储*高位*。文章开头所有例子都是用 *big-endian* 格式给出的。

虽然 big-endian 更符合直觉——在纸上我们通常就是按这种方式书写二进制数——但由于种种原因，大多数现代处理器默认采用 little-endian。

换句话说，「第 $i$ 位」指的是「从低位起第 $i$ 位」或「从右数第 $i$ 位」，但在纸面上我们不会做任何反转，仍以标准方式书写二进制数。

## 位运算

除了算术运算，还可以对数字进行位运算，位运算将数字简单视为位序列。

### 移位

数字的二进制表示可以向左（`x << y`）或向右（`x >> y`）「移位」，这等价于乘以或除以 2 的幂（除法向下取整）。

普通的乘法和除法并不是最快的运算，但所有的位移位操作始终只需一个时钟周期。因此，乘以或除以某个固定的 2 的幂总是很快——即使你没有显式使用移位，编译器也大概率会进行类似的优化。

### 按位运算

除了 `&&`、`||` 和 `!`，它们还有按位版本，即将相应的逻辑运算作用到整条位序列上：`&`、`|`、`~`。

此外还有一个异或（XOR）运算，写作 `^`。

例如：

- $13$ & $7$ = $1101_2$ & $0111_2$ = $0101_2$ = $5$
- $17$ | $10$ = $10001_2$ | $01010_2$ = $11011_2$ = $27$
- $17$ ^ $9$ = $10001_2$ ^ $01001_2$ = $11000_2$ = $24$

所有按位运算同样只需一个时钟周期，与数据类型无关。对于无法放入单个寄存器的长位序列，可以使用[位集（bitset）](/cs/set-structures/bitset/)。

## 掩码

可以将二进制序列与某个固定集合的子集对应起来：如果第 $i$ 位是 1，就说明第 $i$ 个元素属于该集合，否则不属于。

因此，位运算经常被用来处理以位掩码（bitmask）表示的集合操作——例如在暴力枚举或动态规划问题中。

### 取出数字的第 i 位

`(x >> i) & 1` 或 `x & (1 << i)`。第二种写法结果要么是 0，要么是 $2^i$。

这常用于检查第 $i$ 个元素是否属于集合：

```cpp
if ((num >> i) & 1)
    cout << "YES";
else
    cout << "NO";
```

提醒一下，位的编号从低位开始，从 0 计数。

### 构造由 k 个 1 组成的数

`(1 << k) - 1`，也即 $(2^k-1)$，对应全集掩码。

### 翻转数字的所有位

`x = ~x`

### 向集合中添加第 i 个元素

`x |= (1 << i)`

### 从集合中删除第 $i$ 个元素

`x &= ~(1 << i)`

### 如果第 i 个元素存在，则将其删除

`x ^= (1 << i)`

如果该元素不存在，此操作也会将其加入。

## 有符号数

整型变量分为两类——有符号（signed）和无符号（unsigned）。

如果将两个 `unsigned int` 变量相加，且它们的和超过 $2^{32}$，就会发生*溢出（overflow*）：这个和无法被精确表示，因此结果只会保留低 32 位。所有无符号数运算都相当于对 2 的某个幂取模。

而有符号类型用来存储可能为负的值。为此需要拿出一个位来存储符号——即这个数是负还是非负——这会略微牺牲可表示数的上限：现在最大的可表示数是 $2^{31}-1$，而不是 $2^{32}-1$。

设计处理器的工程师比程序员还要懒——这不仅是为了简化设计，也是为了节省晶体管。因此，当 `signed` 类型发生溢出时，其位的计算结果与 `unsigned` 数完全一致。如果我们不想改变 `unsigned` 数的行为，那么负数的表示就应该像是从 2 的大幂次中减去 $x$ 一样：

$$
\begin{aligned}
-x = 2^{32} - x
\end{aligned}
$$

由此可得几个推论：

- 所有非负数仍按原来的方式表示。
- 所有负数的最高位都是 1。
- 若给 $2^{31}-1$ 加上 1，结果将是 $-2^{31}$，表示为 `10000000`（为便于说明，我们这里只写 8 位，而 `int` 中实际上是 32 位）。
- 已知正数 `x` 的二进制表示，`-x` 的表示可以用 `~x + 1` 得到。
- `-1` 写作 `~1 + 1 = 11111110 + 00000001 = 11111111`。
- `-42` 写作 `~42 + 1 = 11010101 + 00000001 = 11010110`。
- 在 `-1 = 11111111` 之后是 `0 = -1 + 1 = 11111111 + 00000001 = 00000000`。

**练习题**。正数和负数，哪种数量更多？

**注意**。C/C++ 标准明确规定，有符号变量溢出会导致未定义行为（undefined behavior），因此不能依赖上述溢出逻辑，尽管实际上几乎肯定会发生这种情况。

### 128 位整数

处理器没有超过 64 位的通用寄存器，但乘法及若干相关指令可以把两个相邻的寄存器当作一个大的寄存器使用。这样就可以快速将两个 64 位数相乘，得到 128 位的结果，并分为高位部分和低位部分。

这是一项相当特殊的操作，因此编程语言中并没有对 128 位变量的完整支持。不过在 C++ 中有一个权宜之计——`__int128_t` 类型——它实际上只是把两个 64 位寄存器封装在一起，并支持对其进行算术运算。

```c++
__int128_t x = 1;
int64_t hi = x >> 64; // получить верхние 64 бит
int64_t lo = (int64_t) x; // получить нижние 64 бит
```

对它进行基本的算术运算会稍慢一些，不能直接输出，除法等复杂操作会调用单独的库函数，因此运行得非常慢，但在某些情况下它非常有用。
