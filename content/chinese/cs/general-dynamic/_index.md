> 动态规划就是：我们有一个不知道怎么解的问题，把它拆成若干更小的、同样不知道怎么解的子问题。

考虑这样一个问题：要求第 $n$ 个斐波那契数 $f_n$，其定义为

$$
\begin{aligned}
    f_0 &= 0
\\  f_1 &= 1
\\  f_n &= f_{n-2} + f_{n-1}
\end{aligned}
$$

把上面的定义写成函数，就可以递归地解决这个问题：

```cpp
int f(int n) {
    if (n == 0)
        return 0;
    if (n == 1)
        return 1;
    return f(n - 2) + f(n - 1);
}
```

然而，当 $n$ 超过 ~40 时，这种解法会运行*非常*久。我们来粗略估计一下运行时间 $T(n)$。


要计算 $f_n$，我们需要递归地计算 $f_{n-1}$ 和 $f_{n-2}$：

$$T(n) = T(n-2) + T(n-1) + \Theta(1)$$

计算 $f_{n-1}$ 所需的操作次数不少于计算 $f_{n-2}$ 的。结合前面的式子，这意味着计算 $f_n$ 需要的操作次数至少是计算 $f_{n-2}$ 的两倍：

$$
T(n) \ge 2 \cdot T(n-2)
$$


因此运行时间呈指数级增长：

$$
T(n) \ge \Omega(2^{n/2})
$$

**练习题。** 计算 $f_n$ 时，总共会进行多少次递归调用？

### 记忆结果

把问题不断化简为更小的子问题、最终归结到基础情形的思路本身完全正确。

但需要注意，不能让子问题的数量呈指数级增长。为此最简单的做法是避免任何多余的计算：如果某次已经算出了 $f_n$，就把它记住，下次需要时直接使用。

最方便的做法是开辟一个数组存放所有需要的 $f_n$ 值，不再使用递归函数：先初始化其基础值，然后循环遍历所有其余的 $f_i$，利用前面迭代中已经算出的 $f_{i-2}$ 和 $f_{i-1}$ 来计算它们：

```cpp
const int n = 100;
int f[n];

f[0] = 0;
f[1] = 1;

for (int i = 2; i < n; i++)
    f[i] = f[i - 2] + f[i - 1]; 
```

（对于较大的 $n$，最后一行会发生溢出，因此[通常](/cs/modular)在这类问题中所有值都会取模处理。）

---

*动态规划*（英文 *dynamic programming*，简称 DP、动态）指的正是上面这种思路，通常包括以下几个一般步骤：

- 把规模为 $n$ 的问题化为规模小于 $n$ 的问题——也就是找到某个递归公式。
- 创建一个数组（或其他数据结构）来存储子问题的答案。
- 手动填充数组开头（公式不适用的基础情形）。
- 从已知值开始遍历数组，按公式填出答案。
- 输出答案——通常就是写在数组最后一个单元里的值。

要用动态规划解题，你必须回答 5 个问题：

- 数组里存的是什么？（通常是最关键的问题）
- 如何初始化数组开头？
- 如何遍历数组？（通常是从左到右，但不总是）
- 用什么公式计算数组元素？
- 答案在数组的哪个位置？

借助这种方法可以解决大量重要的问题，本节的内容将充分说明这一点。
