动态规划的标准做法是：为子问题的答案开一个数组，然后用循环遍历它，用已知值递推出未知值。然而，有时候很难甚至根本无法设计出这样一种遍历顺序，使得所有需要的值都已经算好。

这种情况下，可以用一种叫做*记忆化*的方法取代循环：把动态规划写成递归函数，函数会记住已经算出的结果，下次用相同的输入参数调用时直接返回。

### 简单例子

用这种方式来解求第 $n$ 个斐波那契数的问题。

先把所有 $f[i]$ 初始化为 $-1$：这表示对应状态的值还没有被计算。然后，把 $f[0] = 0$ 和 $f[1] = 1$ 作为基础值。

现在编写转移函数，它在最开头先检查目标值是否已经算过——如果没有，就递归地计算它。

```cpp
int f[n] = {-1};
f[0] = 0;
f[1] = 1;

int g(int k) {
    if (f[k] == -1)
        f[k] = g(k - 2) + g(k - 1);
    return f[k];
}
```

运行时间同样是 $O(n)$，因为每个值我们只计算一次；但实际运行时间会慢几倍，因为函数调用的常数远高于简单循环。

另外可以注意到，这种动态规划保证只会访问真正需要的状态，这在某些问题中会带来更优的渐近复杂度。

### 缓存

更一般地，我们做的这件事叫做*缓存*——记住并复用中间结果。这是编程中非常普遍的概念，现代编程语言通常把记忆化作为内置优化来支持。

例如，Python 中的 `cache` 装饰器做的事情正是这个：

```python
from functools import cache

@cache
def f(n):
    if n == 0:
        return 0
    if n == 1:
        return 1
    return f(n - 2) + f(n - 1)
```

而且这个装饰器不需要知道对 $n$ 的任何限制：它会为任意输入记住对应的结果，这些输入可以以元组的形式放进哈希表。

我们来试着在 C++ 中实现类似的东西。

### 复杂例子

考虑题目《[金融家游戏](https://codeforces.com/contest/729/problem/F)》。

有一个包含 $n \le 4000$ 个数的数组 $a_i$，两名玩家轮流从中取数，尽量最大化自己的和与对手的和之差。每回合，玩家可以从一侧取走若干个端部元素——第一名玩家从左边取，第二名从右边取。此外，如果某玩家上一回合取了 $k$ 个数，那么对手下一回合只能取 $k$ 或 $(k + 1)$ 个数（第一回合可以取 1 或 2 个）。

当某位玩家无法行动时，游戏结束。

我们引入如下动态规划：如果只剩下从 $l$ 到 $r$ 的元素，且上一回合取了 $k$ 个数，$f[l, r, k, p]$ 等于玩家 $p$ 与其对手之间能达到的最大分数差。由于我们总共只有两种选择——取 $k$ 或 $(k+1)$ 个数——转移不过是这两种可能中的最大值：

$$
f[l, r, k, 0] = \max \begin{cases}
    \sum_{i=l}^{k} a_i + f[l + k, r, k, 1]
\\  \sum_{i=l}^{k + 1} a_i + f[l + k + 1, r, k + 1, 1]
\end{cases}
$$

（对另一位玩家 $p=1$ 同理。）

来估计一下它的复杂度。利用原数组一次算好的[前缀和](/cs/range-queries/prefix-sum)，转移可以在 $O(1)$ 内完成，因此渐近复杂度等于状态数。但这里似乎出现了一个问题：

$$
l \in [1, n]
\\ r \in [1, n]
\\ k \in [1, n]
\\ p \in \{ 0, 1 \}
$$

如果天真地把所有状态存进四维数组，需要 $O(n^3)$ 个单元，这不可接受，因为 $n=4000$。事实证明，*可达*的状态要少得多。

**命题 1.** $k = O(\sqrt n)$。

要得到这样的 $k$，需要在之前的某些步骤中依次取过 $k, (k-1), \ldots, 2, 1$ 个数，这就要求数组大小 $n$ 至少为

$$
n \ge \sum_{i=1}^x i \approx \frac{k^2}{2}
$$

由此得出 $k = O(\sqrt n)$。

**命题 2.** 对于给定的左边界 $l$，可能的右边界 $r$ 不超过 $O(\sqrt n)$ 个。

考虑第一名玩家与第二名玩家取走的数的数量之差 $d$：

$$
d = l - (n - r)
$$

由于一名玩家取走若干元素后，另一名玩家要么取同样多、要么多取一个，因此经过任意连续两步，$d$ 的变化至多为 1。而且，$d$ 每变化 1，都要求 $k$ 也增大。我们已经确定 $k = O(\sqrt n)$，因此 $d = O(\sqrt n)$。由于根据上面的定义，由二元组 $(l, d)$ 可以还原出 $r$，所以对于每个 $l$，不同的 $r$ 也至多有 $O(\sqrt n)$ 个。

这样看来，实际可达状态数不是 $O(n^3)$，而是 $O(n \cdot \sqrt n \cdot \sqrt n \cdot 2) = O(n^2)$。因此，要么设计更巧妙的状态存储格式和遍历方式，要么就使用记忆化。

由于简单开一个四维数组放不进内存（哪怕它只有 $O(n^{2.5})$ 个元素），我们改用哈希表。最简单的做法是把它定义为从 `int` 到 `int` 的 `unordered_map`，然后找到一种把四元组 $(l, r, k, p)$ 编号到某个能放进 `int` 的范围内的方式，用这个编号代替原来的 4 元组。

```cpp
const int N = 4000, K = 80;
 
int n;
int s[N + 1];
 
unordered_map<int, int> dp;
 
long f(int l, int r, int k, bool p) {
    if ((r - l + 1) < k)
        return 0;
    int key = l * N * K * 2 + r * K * 2 + k * 2 + p;
    if (dp.count(key))
        return dp[key];
    return dp[key] = (p ?
        max(
            s[l + k] - s[l] - f(l + k, r, k, 0),
            s[l + k + 1] - s[l] - f(l + k + 1, r, k + 1, 0)
        )
        :
        max(
            s[r + 1] - s[r - k + 1] - f(l, r - k, k, 1),
            s[r + 1] - s[r - k] - f(l, r - k - 1, k + 1, 1)
        )
    );
}
 
int main(){
    dp.rehash(6.2e7);
 
    cin >> n;
 
    for (int i = 0; i < n; i++) {
        cin >> s[i + 1];
        s[i + 1] += s[i];
    }
 
    cout << f(0, n - 1, 1, 1); 
 
    return 0;
}
```

如果能够预先估计哈希表中的元素数量，最好在开始时就用 `dp.rehash` 为它预留空间：这通常能把程序加快 2–3 倍。如果自己实现哈希表，还能再快 3–4 倍。
