考虑一个有向图 $G = (V, E)$，其中有源点 $s$ 和汇点 $t$，每条边 $(u, v)$ 都带整数成本 $w_{uv}$ 和正整数容量 $c_{uv}$。要求找出成本最小的最大流：

$$ \sum_{(u, v) \in E} f_{uv} \to \max $$
$$ \sum_{(u, v) \in E} f_{uv} w_{uv} \to \min $$

注意，按题意允许存在负成本的边。我们额外地假设不存在负权环。

按标准方式修改网络，加入允许“取消”操作的反向边：对每条边 $(u, v)$ 加入 $(v, u)$，其 $c_{vu} = 0$ 且 $w_{vu} = -w_{uv}$。回忆一下，残量网络指的是由残量容量非零（$c_{uv}-f_{uv} > 0$）的边组成的图。

## 最优性判据

**命题**。 如果残量网络中没有负权环，则流是最优的（反之亦然）。

**证明**：

$\rightarrow$ 考虑任意一个非最优的流 $f$ 和一个最优的流 $f^\ast$。考虑差 $f^\ast-f$。它是一个循环流，而任何循环流都可以分解为若干简单环之和。其中至少有一个环的成本为负，因为 $f^\ast$ 的成本小于 $f$ 的成本，这与假设矛盾。

$\leftarrow$ 假设存在这样的环，那么我们可以沿这个环推送流，得到成本更小的流。

### 消环

这个判据立刻给出一个相对简单的算法：先找到某个最大流，然后不断“取消”残量网络中的负权环，直到不存在这样的环为止。找环的次数不超过 $mUC$ 次，其中 $U$ 是流量大小，$C$ 是边的最大容量。答案的最小成本绝对值以这个量为界，而每取消一个环至少使答案减少 1。

如果用 Bellman–Ford 算法找环，则算法的渐近复杂度为 $O(m^2nUC)$（假设我们已经找到了某个最大流）。

## 增广路

回忆基于 Ford–Fulkerson 定理的求最大流的一般算法：找一条增广路，沿它推送流并修改网络，再找增广路，如此继续，直到从源点到汇点不存在路径为止。如果我们每次寻找的不是任意路径，而是成本最小的路径，会怎样？可以断言，这样的算法会找到成本最小的最大流。

**命题**。 算法不会在残量网络中产生负权环。

初始时残量网络中没有负权环。我们找到了从 $s$ 到 $t$ 的最小路径并修改了网络，可能添加了一些反向边。这些边会不会导致负权环出现？假设某条反向边 $(v, u)$ 位于某个负权环中。那么存在一条从 $u$ 到 $v$ 的成本小于 $w_{uv}$ 的路径。但这不可能发生：如果这样的路径存在，那么在寻找增广路的阶段，我们就会选择它而不是边 $(u, v)$。

寻找增广路可以使用 Bellman–Ford 算法。在这种情况下渐近复杂度为 $O(nmU)$——每条增广路我们最多寻找 $U$ 次。

为什么我们不使用 Dijkstra 算法？问题出在负权边上。即使原图中没有负权边，它们在算法过程中也会作为反向边出现。下面说明如何修改边的权值，使它们变为非负，同时不丢失最短路径的信息：这可以做到，只需给每个顶点赋予一个所谓的“势”，在重新计算边的成本时把势考虑进去。

## Johnson 势

把顶点 $v$ 的势定义为它到顶点 $s$ 的距离 $d_v$。考虑由所有可达顶点和同样的边组成的图，只是权值被修改为：

$$ w_{uv}' = w_{uv} + d_u - d_v $$

**命题 1**。图中所有边的权值都是非负的。

**证明**。 假设某条边 $(u, v)$ 的权值为负，即 $w_{uv}' = w_{uv} + d_u - d_v < 0$。那么 $d_u + w_{uv} < d_v$，三角不等式被破坏：为什么我们当初没有使用边 $(u, v)$ 来寻找通往 $v$ 的最短路径呢？

类似地可以证明，从 $s$ 出发的最短路径上的边成本为零。注意，最短路径上 *反向* 边的成本也为零：
$$ w_{vu}' = w_{vu} + d_v - d_u = -w_{uv} - d_u + d_v = -(w_{uv}) = 0 $$

**命题 2**。任意顶点之间的最短路径仍然是最短路径。

**证明**。写出从 $a$ 到 $z$ 的路径的新成本。

$$
\begin{aligned}
w_{ab}' + \ldots + w_{yz}'
&= (w_{ab} + \ldots + w_{yz}) + (d_a + \ldots + d_y) - (d_b + \ldots + d_z)
\\&= (w_{ab} + \ldots + w_{yz}) + d_a - d_z
\end{aligned}
$$

得到：从 $a$ 到 $z$ 的所有路径的成本只是改变了一个常数。

此外，即使我们从图中添加或删除一些边，势也不会对最短路径产生任何影响。

注意，在证明中我们并没有用到 $d_v$ 是最短距离这一点。它们完全可以是一些任意数。

**命题 3**。当我们沿最短路径推送流时，会删除边并可能添加反向边，修改后的图中的权值仍然保持正确（所有边权非负，且所有最短路径仍然是最短的）。

**证明**。最短路径上新添加的反向边成本为零（命题 1），而添加或删除边不会影响最短路径（命题 2）。

## 最终算法

- 修改网络，加入反向边。
- 如果原图中有负权边（但没有负权环），则用 Bellman–Ford 算法计算初始势（距离）。否则只需把势初始化为零。
- 在最大流找到之前：
    1. 用 Dijkstra 算法计算从 $s$ 出发的最短距离，权值使用带势的公式，把结果写入 $d$。
    2. 沿最短路径 $s \leadsto t$ 推送尽可能多的流，并更新残量网络。

### 实现

下面给出指派问题（最小权匹配）的解法。寻找增广路使用针对稠密图的 Dijkstra 算法（不用优先队列——每轮迭代在 $O(n)$ 时间内寻找最小值）。

* `cost`、`cap` ——网络的参数
* `pot` ——势
* `par` ——Dijkstra 算法中顶点的前驱（用于推送流）
* `d` ——Dijkstra 算法的临时数组，新的距离将写入其中

```c++
const int maxn = 305, inf = 1e9;

int n;
int cost[maxn][maxn], cap[maxn][maxn];
int d[maxn], pot[maxn], par[maxn];

bool dijkstra(int s, int t) {
    used[maxn] = {0};

    fill(d, d+n, inf);
    d[s] = 0;

    while (1) {
        int v = -1;
        for (int u = 0; u < n; u++)
            if (!used[u] && (v == -1 && d[u] < d[v]))
                v = u;
        if (v == -1 || d[v] == inf)
            break;
        used[v] = 1;
        for (int u = 0; u < n; u++) {
            int w = cost[v][u] + pot[v] - pot[u];
            if (cap[v][u] && d[u] > d[v] + w) {
                d[u] = d[v] + w;
                par[u] = v;
            }
        }
    }

    return d[t] < inf;
}

int mincost_maxflow(int s, int t) {
    int ans = 0;
    while (dijkstra(s, t)) {
        memcpy(pot, d, sizeof(d));
        int delta = inf;
        for (int v = t; v != s; v = par[v])
            delta = min(delta, cap[par[v]][v]);
        for (int v = t; v != s; v = par[v]) {
            cap[par[v]][v] -= delta;
            cap[v][par[v]] += delta;
            ans += cost[par[v]][v]*delta;
        }
    }
    return ans;
}
```

### 渐近复杂度

一般情况下，算法运行时间为 $O(U m \log n)$，稠密图的情况下为 $O(U n^2)$。

在大多数常见问题中，边通常具有单位容量，且 $U \leq n$ 或 $U \leq m$。例如，在指派问题中 $U = n$，算法运行时间为 $O(n^3)$，这与[匈牙利算法](http://e-maxx.ru/algo/assignment_hungary)的渐近复杂度一致。
