问题陈述
给定一个网络，即一个有向图 G，其中每条边 (u,v) 都被赋予容量 c_{uv}，并且标出了两个顶点——源点 s 和汇点 t。

需要在该网络中找到从源点 s 到汇点 t 的流量 f_{uv}，使其大小达到最大。

一点历史
这个算法由苏联（以色列）学者叶菲姆·迪尼茨（Yefim Dinic，有时写作 "Dinitz"）于 1970 年发表，甚至比 Edmonds–Karp 算法的发表还早两年（不过，两个算法都是于 1968 年独立发现的）。

此外应当指出，算法的一些简化是由希蒙·伊文（Shimon Even）和他的学生阿隆·伊泰（Alon Itai）于 1979 年完成的。正是得益于他们，算法才获得了今天的面貌：他们把亚历山大·卡尔扎诺夫（Alexander Karzanov，1974 年）的阻塞流概念应用到迪尼茨的想法上，并把算法重新表述为广度优先与深度优先遍历相结合的形态，如今这个算法到处都是以这种形态被讲述的。

结合当年分隔苏联与西方的“铁幕”来审视流算法思想的发展，是非常有趣的。可以看到，有时相似的思想几乎同时出现（如迪尼茨算法和 Edmonds–Karp 算法的情况），只不过效率有所不同（迪尼茨算法要快一个数量级）；而有时则相反，某个思想在“铁幕”一侧的出现领先于另一侧的同类进展十多年（如卡尔扎诺夫 1974 年的推进算法与戈德堡（Goldberg）1985 年的推进算法）。

必要的定义
引入三个必要的定义（每一个都独立于其余两个），它们随后将用于迪尼茨算法。

相对于网络 G 及其中的某个流 f，残量网络 G^R 是这样一种网络：其中每条边 (u,v) \in G（容量为 c_{uv}，流量为 f_{uv}）对应两条边：

(u,v) 的容量为 c_{uv}^R = c_{uv} - f_{uv}
(v,u) 的容量为 c_{vu}^R = f_{uv}
值得注意的是，按此定义，残量网络中出现多重边：如果原网络中既有边 (u,v) 又有边 (v,u)。

残量边可以直观地理解为：沿某条边还能再增加多少流量。事实上，如果容量为 c_{uv} 的边 (u,v) 上流经流量 f_{uv}，那么它还能再容纳 c_{uv}-f_{uv} 个单位的流量，而反方向最多可以容纳 f_{uv} 个单位的流量，这相当于取消原先方向上的流量。

给定网络中的阻塞流是这样一种流：从源点 s 到汇点 t 的任何路径都包含被该流饱和的边。换句话说，在该网络中不存在这样的路径，可以沿它毫无阻碍地增加流量。

阻塞流不一定是最大流。Ford–Fulkerson 定理说的是：当且仅当残量网络中不存在 s-t 路径时，流才是最大流；而阻塞流对残量网络中新出现边所构成的路径是否存在，没有任何断言。

分层网络按如下方式为给定网络构建。首先求出从源点 s 到其余所有顶点的最短路径长度；把顶点到源点的距离称为它的层 {\rm level}[v]。然后把原网络中所有从某一层通向更晚层的边 (u,v) 纳入分层网络，即满足 {\rm level}[u] + 1 = {\rm level}[v]（为什么此时距离差不可能超过一，可由最短距离的性质得出）。这样一来，所有完全位于同一层内部的边，以及指回前面各层的边，都被删除。

显然，分层网络是无环的。此外，分层网络中的任何 s-t 路径都是原网络中的最短路径。

根据给定网络构建分层网络非常容易：只需沿该网络的边做广度优先遍历，从而为每个顶点算出 {\rm level}[] 的值，然后把所有符合条件的边纳入分层网络即可。

注：俄语文献中不使用“分层网络”这一术语；这种结构通常被称为“辅助图”。不过在英语中通常使用术语 “layered network”。

算法
算法流程
该算法由若干阶段组成。每个阶段首先构建残量网络，然后相对于它构建分层网络（用广度优先遍历），并在其中寻找任意一个阻塞流。找到的阻塞流累加到当前流上，这一轮迭代到此结束。

该算法与 Edmonds–Karp 算法相似，但主要区别可以这样理解：每轮迭代中流不是沿一条最短 s-t 路径增加的，而是沿一整组这样的路径增加的（因为分层网络阻塞流中的路径正是这样的路径）。

算法的正确性
证明：如果算法结束，那么它输出的就是大小达到最大值的流。

事实上，假设在某个时刻，针对残量网络构建的分层网络中找不到阻塞流。这意味着汇点 t 在分层网络中从源点 s 完全不可达。但由于分层网络包含残量网络中从源点出发的全部最短路径，这又意味着残量网络中不存在从源点到汇点的路径。于是应用 Ford–Fulkerson 定理，得到当前流确实达到了最大值。

阶段数估计
证明迪尼茨算法总是执行少于 n 个阶段。为此证明两个引理：

引理 1. 源点到每个顶点的最短距离不会随着每轮迭代的执行而减小，即

 {\rm level}_{i+1}[v] \ge {\rm level}_i[v] 

其中下标表示取值时所在阶段的编号。

证明。固定任意一个阶段 i 和任意一个顶点 v，考虑网络 G^R_{i+1} 中任意一条最短 s-v 路径 P（回忆一下，我们用这个记号表示在第 i+1 阶段开始前取的残量网络）。显然，路径 P 的长度等于 {\rm level}_{i+1}[v]。

注意，残量网络 G^R_{i+1} 只能包含 G^R 中的边，以及 G^R 中边的反向边（这由残量网络的定义得出）。考虑两种情况：

路径 P 只包含 G^R 中的边。那么显然路径 P 的长度大于或等于 {\rm level}_i[v]（因为按定义 {\rm level}_i[v] 是最短路径的长度），这正说明不等式成立。
路径 P 至少包含一条不在 G^R 中的边（但它是 G^R 中某条边的反向边）。考虑第一条这样的边；设它为边 (u,w)。
 s \Longrightarrow u \rightarrow w \Longrightarrow[...]

我们可以对顶点 u 应用引理，因为它属于第一种情况；于是得到不等式 {\rm level}_{i+1}[u] \ge {\rm level}_i[u]。

现在注意，由于边 (u,w) 只在第 i 个阶段执行完之后才出现在残量网络中，由此可知沿边 (w,u) 曾被额外推送过一些流量；因此，边 (w,u) 在第 i 个阶段之前属于分层网络，于是 {\rm level}_i[u] = {\rm level}_i[w] + 1。再考虑到由最短路径性质有 {\rm level}_{i+1}[w] = {\rm level}_{i+1}[u] + 1，把这个等式与前两个不等式合并，得到：

 {\rm level}_{i+1}[w] \ge {\rm level}_i[w] + 2. 

现在可以对通往 v 的整个剩余路径应用同样的推理（即每条反向边至少给 \rm level 增加 2），最终得到所需的不等式。

引理 2. 源点与汇点之间的距离在算法的每一阶段之后严格增加，即：

 {\rm level}^\prime[t] > {\rm level}[t], 

其中带撇的值表示算法的下一阶段所得到的值。

证明：反证法。假设当前阶段执行完之后得到  {\rm level}^\prime[t] = {\rm level}[t] 。考虑从源点到汇点的最短路径；按假设，它的长度应当保持不变。然而，下一阶段的残量网络只包含当前阶段执行前残量网络的边，或者它们的反向边。于是得出矛盾：找到了一条 s-t 路径，它不包含被饱和的边，并且与最短路径等长。这条路径本应被阻塞流“阻塞”，却没有，这就是矛盾所在，证毕。

这个引理可以直观地理解为：在第 i 个阶段，迪尼茨算法找出并饱和所有长度为 i 的 s-t 路径。

由于从 s 到 t 的最短路径长度不可能超过 n-1，因此迪尼茨算法执行的阶段数不超过 n-1。

寻找阻塞流
为了完成迪尼茨算法的构建，需要描述在分层网络中寻找阻塞流的算法——这是算法的关键部位。

我们将考察寻找阻塞流的三种可能的实现方案：

1. 逐一寻找 s-t 路径，直到再也找不到为止。一条路径可以通过深度优先遍历在 O(m) 时间内找到，而这样的路径共有 O(m) 条（因为每条路径至少饱和一条边）。寻找单个阻塞流的总渐近复杂度为 O(m^2)。
2. 与前一方案类似，不过在深度优先遍历的过程中从图中删除所有“多余”的边，即那些沿它们无法到达汇点的边。
这非常容易实现：只需在深度优先遍历中查看一条边之后把它删除即可（沿边走下去并找到通往汇点路径的情况除外）。从实现角度看，只需在每个顶点的邻接表中维护一个指向第一条未删除边的指针，并在深度优先遍历内部的循环中递增这个指针。

估计这个方案的渐近复杂度。每次深度优先遍历要么以至少饱和一条边结束（如果这次遍历到达了汇点），要么以至少推进一个指针结束（否则）。可以想见，主程序中的一次深度优先遍历运行时间为 O (k + n)，其中 k 是指针推进的次数。考虑到在寻找单个阻塞流的框架内，深度优先遍历总共启动 O (p) 次，其中 p 是被该阻塞流饱和的边数，那么整个寻找阻塞流的算法将运行 O (p k + p n) 时间，再考虑到所有指针总共推进了 O (m) 的距离，得到渐近复杂度 O (m + pn)。在最坏情况下，即阻塞流饱和所有边时，渐近复杂度为 O (n m)；下文将使用这个渐近复杂度。

可以说，这种寻找阻塞流的方法极为高效：平均而言，寻找一条增广路只需 O (n) 次操作。正是这一点造就了迪尼茨算法与 Edmonds–Karp 算法（后者寻找一条增广路需要 O (m)）之间整整一个数量级的效率差距。

这种方法实现起来依然简单，但又足够高效，因此实践中用得最多。

可以应用特殊的数据结构——斯莱特（Sleator）和塔里安（Tarjan)的动态树）。这样每个阻塞流都可以在 O (m \log n) 时间内找到。
渐近复杂度
因此，如果按上述 O (n m) 的方法寻找阻塞流，整个迪尼茨算法在 O (n^2 m) 内完成。而使用斯莱特–塔里安动态树的实现，运行时间为 O (n m \log n)。

单位网络
单位网络（"unit network"）是这样一种网络：其中所有现存边的容量都等于 1，并且除源点和汇点外的任何顶点，要么入边唯一，要么出边唯一。

这一情形相当重要，因为在最大匹配问题中构建的网络正是单位网络。

证明：在单位网络上，即使是最简单的迪尼茨算法实现（在任意图上需要 O (n^2 m)）也能在 O (m \sqrt{n}) 内运行，在最大匹配问题上达到已知最佳算法之一——Hopcroft–Karp 算法。

首先指出，上述寻找阻塞流的算法（在任意网络上需要 O (n m)）在单位容量网络上只需要 O (m)：因为每条边最多被查看一次。

其次，估计单位网络情况下可能发生的阶段总数。

假设已经执行了 \sqrt{n} 个迪尼茨阶段；那么所有长度不超过 \sqrt{n} 的增广路都已被发现。设 f 为当前找到的流，f^* 为所求的最大流；考虑它们的差：f^* - f。它是残量网络 G^R 中的一个流。这个流的大小为 |f^*| - |f|，沿每条边等于 0 或 1。它可以分解为 |f^*| - |f| 条从 s 到 t 的路径，可能还有一些环。由于网络是单位的，所有这些路径不可能有公共顶点，因此，考虑到上述内容，它们的顶点总数 cnt 可以估计为：

 cnt \ge (|f^*| - |f|) \cdot \sqrt{n}. 

另一方面，由于 cnt \le n，由此得到：

 |f^*| - |f| \le \sqrt{n}, 

这意味着再过 \sqrt{n} 个迪尼茨阶段就一定能找到最大流。

于是，单位网络上迪尼茨算法执行的总阶段数可以估计为 2 \sqrt{n}，证毕。

实现
下面给出两个 O (n^2 m) 的算法实现，分别运行在邻接矩阵和邻接表表示的网络上。

邻接矩阵表示的图的实现
const int MAXN = ...; // число вершин
const int INF = 1000000000; // константа-бесконечность
 
int n, c[MAXN][MAXN], f[MAXN][MAXN], s, t, d[MAXN], ptr[MAXN], q[MAXN];
 
bool bfs() {
	int qh=0, qt=0;
	q[qt++] = s;
	memset (d, -1, n * sizeof d[0]);
	d[s] = 0;
	while (qh < qt) {
		int v = q[qh++];
		for (int to=0; to<n; ++to)
			if (d[to] == -1 && f[v][to] < c[v][to]) {
				q[qt++] = to;
				d[to] = d[v] + 1;
			}
	}
	return d[t] != -1;
}
 
int dfs (int v, int flow) {
	if (!flow)  return 0;
	if (v == t)  return flow;
	for (int & to=ptr[v]; to<n; ++to) {
		if (d[to] != d[v] + 1)  continue;
		int pushed = dfs (to, min (flow, c[v][to] - f[v][to]));
		if (pushed) {
			f[v][to] += pushed;
			f[to][v] -= pushed;
			return pushed;
		}
	}
	return 0;
}
 
int dinic() {
	int flow = 0;
	for (;;) {
		if (!bfs())  break;
		memset (ptr, 0, n * sizeof ptr[0]);
		while (int pushed = dfs (s, INF))
			flow += pushed;
	}
	return flow;
}
网络需要预先读入：必须设定变量 n、s、t，并读入容量矩阵 c[][]。主要的求解函数是 \rm dinic()，它返回所找到的最大流的大小。

邻接表表示的图的实现
const int MAXN = ...; // число вершин
const int INF = 1000000000; // константа-бесконечность
 
struct edge {
	int a, b, cap, flow;
};
 
int n, s, t, d[MAXN], ptr[MAXN], q[MAXN];
vector<edge> e;
vector<int> g[MAXN];
 
void add_edge (int a, int b, int cap) {
	edge e1 = { a, b, cap, 0 };
	edge e2 = { b, a, 0, 0 };
	g[a].push_back ((int) e.size());
	e.push_back (e1);
	g[b].push_back ((int) e.size());
	e.push_back (e2);
}
 
bool bfs() {
	int qh=0, qt=0;
	q[qt++] = s;
	memset (d, -1, n * sizeof d[0]);
	d[s] = 0;
	while (qh < qt && d[t] == -1) {
		int v = q[qh++];
		for (size_t i=0; i<g[v].size(); ++i) {
			int id = g[v][i],
				to = e[id].b;
			if (d[to] == -1 && e[id].flow < e[id].cap) {
				q[qt++] = to;
				d[to] = d[v] + 1;
			}
		}
	}
	return d[t] != -1;
}
 
int dfs (int v, int flow) {
	if (!flow)  return 0;
	if (v == t)  return flow;
	for (; ptr[v]<(int)g[v].size(); ++ptr[v]) {
		int id = g[v][ptr[v]],
			to = e[id].b;
		if (d[to] != d[v] + 1)  continue;
		int pushed = dfs (to, min (flow, e[id].cap - e[id].flow));
		if (pushed) {
			e[id].flow += pushed;
			e[id^1].flow -= pushed;
			return pushed;
		}
	}
	return 0;
}
 
int dinic() {
	int flow = 0;
	for (;;) {
		if (!bfs())  break;
		memset (ptr, 0, n * sizeof ptr[0]);
		while (int pushed = dfs (s, INF))
			flow += pushed;
	}
	return flow;
}
网络需要预先读入：必须设定变量 n、s、t，并用 \rm add\_edge 函数调用加入所有（有向）边。主要的求解函数是 \rm dinic()，它返回所找到的最大流的大小。
