在无环网络中寻找阻塞流的需求相当常见（例如 [Dinic 算法](алгоритм_Диница "wikilink")），下面将给出几种完成这一任务的算法。

## 贪心算法

顾名思义，我们将贪心地沿网络 $G$ 中任意一条增广路推送流。该算法与 [Ford–Fulkerson 算法](Алгоритм_Форда-Фалкерсона "wikilink") 有些相似，但与之不同的是，我们不构建残量网络，而是总是在原始网络 $G$ 中寻找增广路。

当沿网络 $G$ 中任意一条路径推送流时，至少会有一条边消失（被流饱和），并且不会出现新边（新边只会出现在残量网络 $G_f$ 中，而不是 $G$ 中），因此在至多 $E$ 次迭代之后，$t$ 将变得从 $s$ 不可达，也就是说我们的流 $f$ 是阻塞流。我们用 $dfs$ 寻找一条路径，耗时 $O(E)$，因此该算法的运行时间为 $O(E^2)$。

## 删边遍历

在贪心算法中我们做了很多多余的操作。现在我们做同样的事情，但如果沿某条边没能找到增广路，就可以删除这条边，因为任何包含这条边的路径上必定有一条被流饱和的边。

让我们估计运行时间。当我们查看一条边时，要么稍后删除它，要么会找到一条包含这条边的增广路。每条边至多被删除一次，因此删除操作共 $O(E)$ 次。如贪心算法所述，需要找到 $O(E)$ 条路径，而由于我们寻找的是简单路径，其长度为 $O(V)$，因此我们查看的边数为 $O(VE + E) = O(VE)$。执行的操作数等于查看的边数，因此算法的运行时间为 $O(VE)$。

### 删边遍历的实现

``` c++ numberLines

// ptr[v] - номер первого не удалённого ребра
// dist[v] - расстояние от истока

int dfs(int v, int min_capacity) {
    if (v == T) {
        return min_c;
    }
    for (int i = ptr[v]; i < (int)g[v].size(); ++i) {
        int u = g[v][i];
        if (edges[u].get_capacity() == 0) {
            ++ptr[v]; // ребро отсутствует в остаточной сети, так что удалим его
            continue;
        }
        if (dist[edges[u].v] != dist[v] + 1) {
            ++ptr[v]; // ребро отсутствует в слоистой сети, так что удалим его
            continue;
        }
        int x = dfs(edges[u].v, min(min_c, edges[u].get_capacity()));
        if (x) { // нашли увеличивающий путь, по которому можно пустить x потока
            edges[u].flow += x;
            edges[u ^ 1].flow -= x;
            return x;
        }
        ++ptr[v]; // перейдя по ребру увеличивающий путь не был найден, так что удалим его
    }
    return 0;
}

void find_blocked_flow() {
    fill(ptr, ptr + N, 0);
    while (dfs(S, INF)) {}
}
```

## Malhotra–Kumar–Maheshwari 算法

这个算法大概不会有人去实现，它只是很优美，而且有了它，[Dinic 算法](Алгоритм_Диница "wikilink") 简直飞起来。

对每个顶点 $v$ 引入：

  - 入势：$p_{in}(v) = \\sum\\limits_{u \\in V}{c(u, v)}$，
  - 出势：$p_{out}(v) = \\sum\\limits_{u \\in V}{c(v, u)}$，
  - 势：$p(v) = min(p_{in}(v), p_{out}(v))$，

其中 $p_{in}(s) = \\infty$ 且 $p_{out}(t) = \\infty$。

顶点的势 $-$ 是能流经该顶点的流量，它等于能流入（$p_{in}$）的量与能流出（$p_{out}$）的量中的最小值。

算法流程：

1.  如果存在顶点 $v$ 使得 $p(v) = 0$，则把它从网络中删除，因为显然不会有流经过它。删除顶点时，所有与它关联的边都会消失，并且需要为某些顶点重新计算 $p_{in}$ 或 $p_{out}$，还可能递归地删除它们。
2.  现在，如果从源点无法到达汇点，那么显然已经找到了阻塞流。
3.  取 $p(v)$ 最小的顶点 $v$。$p(v) \> 0$，因为否则我们在上一步就会把它删除。
4.  从这个顶点向汇点和源点各推送 $p(v)$ 个单位的流。
5.  回到算法的第一步。

下面详细看看第 4 步中向汇点推送流的过程：

1.  引入顶点的流量盈余：设我们的顶点 $v$ 的流量盈余为 $p(v)$，其余所有顶点的盈余为 0。
2.  在所有流量盈余非零的顶点中，选择在拓扑排序中靠前的顶点 $v$。
3.  从这个顶点沿其出边推送盈余流量；这总是可以做到的，因为起始顶点具有最小的势，也就是说任何其他顶点的 $p_{out}$ 都不小于它。当我们沿边 $(v, u)$ 推送流时，减少 $v$ 的盈余并增加 $u$ 的盈余，所有顶点盈余的总和保持不变。
4.  从第一点开始重复，直到被选中的是汇点。由于每次选中的顶点在拓扑排序中的位置严格递增，而拓扑排序中最后一个是汇点，因此算法正确工作。

向源点推送流的方式类似，只不过这次我们反向推送流量亏空，并取拓扑排序中靠后的顶点。

作为练习，请证明：当且仅当 $p_{out}(s) = 0$ 时，汇点从源点不可达，这简化了算法第二步中的这一检查。

让我们估计算法的运行时间。每轮迭代至少会消失一个在第 3 步中选中的顶点。因此总共进行 $O(V)$ 轮迭代。不难验证，该算法的运行时间等于查看过的边数。每轮迭代中，我们从 $O(V)$ 个顶点推送流量盈余（亏空），在此过程中，要么一条边被流完全饱和，之后不再使用它，要么流量盈余（亏空）耗尽。显然，每轮迭代中不会被删除的边数为 $O(V)$，而被删除的边总共有 $O(E)$ 条，因此算法的运行时间为 $O(V^2 + E)$。
