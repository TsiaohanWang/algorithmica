*前缀树*或*字典树*（英文 *trie*）是以树的形式紧凑存储字符串的数据结构，树的边标着字符，某些顶点被标记为*终端*。

说前缀树*接受*字符串 $s$，如果存在这样的终端顶点 $v$：把从根到 $v$ 路径上所有字母依次写出来，得到字符串 $s$。

![](../img/trie.png)

字典树本身可以用于各种题目：

- 存储字符串：如果有很多重复的长前缀，字典树比数组或字符串的 `set` 占的空间小得多。
- 排序字符串：对建好的字典树做 `dfs` 遍历，按字典序输出所有字符串。
- 当作字符串集合：如我们将看到，字典树容易加入和删除单词，也容易做包含检查。

从自动机理论角度看，每个顶点是一个状态，所有合法的单字符追加是自动机中的合法转移。于是字典树就是检查单词是否属于集合的自动机。

### 实现

前缀树最简单的是用相互引用的顶点存储。每个顶点通常存：是否终端、指向子节点的引用，以及取决于题目的额外信息——例如，如果想实现多重集，可以存以该顶点结尾的单词个数。

对拉丁字母表（26 个小写字母）而言，初始空的字典树可以这样实现：

```c++
const int k = 26;

struct Vertex {
    Vertex* to[k] = {0}; // 零指针表示没有转移
    bool terminal = 0;
};

Vertex *root = new Vertex();
```

要向字典树加入单词，从根沿单词的字符走。如果下一个字符没有转移就创建它，否则沿已有转移走。最后别忘了把当前状态标记为终端。

```c++
void add_string(string &s) {
    v = root;
    for (char c : s) {
        c -= 'a'; // 得到 0 到 25 的数
        if (!v->to[c]) 
            v->to[c] = new Vertex();
        v = v->to[c];
    }
    v->terminal = true;
}
```

要检查单词是否在字典树里，同样从根沿单词字符走。如果最后停在终端顶点——则单词在。如果停在非终端顶点，或某时需沿不存在的引用走——则不在。

```c++
bool find(string &s) {
    v = root;
    for (char c : s) {
        c -= 'a';
        if (!v->to[c])
            return false;
        v = v->to[c];
    }
    return v->terminal;
}
```

删除单词可以「懒惰地」做：只需走到它、去掉终端标志。

```c++
bool erase(string &s) {
    v = root;
    for (char c : s)
        v = v->to[c - 'a'];
    v->terminal = false;
}
```

根据题目，这些过程有时需要改动。例如，如果想实现自动补全——按查询找出所有带给定前缀的单词——可以小心地删除那些不导向终端顶点的顶点，这样回答查询时只需从前缀状态出发做 `dfs`，在一切终端顶点输出答案。

### 如何存引用

有时限制不允许简单地用数组存子节点引用。

例如，如果字母表很大——那就没有时间和内存初始化那么多数组，而它们多数会是空的。

除了指针数组，还有很多其他把字符映射到引用的方式：

- 可扩展数组（`std::vector`），
- 二叉树（`std::map`），
- 哈希表（`std::unordered_map`）。

多数时候内存是主要的实际考量。另外在 64 位系统上，可能比 `new` 和指针更划算的做法是在大数组或向量上分配一切，存 4 字节的顶点下标而不是 8 字节的内存指针。

## 数字字典树

有些题目会产生在字典树里像字符串一样存数的想法——这样的结构叫*数字字典树*。

大多数时候数要写成二进制，那样一切很简单；但有些题需要别的进制，比如十进制里不能按字典序比较数（2 > 11）。为消除这个问题，我们假设所有数小于某个 10 的幂，然后给数补前导零：现在 02 < 11。

**题目**。 给定一个数的集合，需要回答三类查询：

1. 加入数 $x$。
2. 删除数 $x$。
3. 找出数组中与 $x$ 的 `xor` 最大的数 $y$。

前两类查询已经会在数字字典树里做，第三类更难。

注意，如果集合中存在 $y$ 使 $y_i \neq x_i$（即在第 $i$ 位不同），那么选它比任何在第 $i$ 位（含）之前前缀等于 $x$ 前缀的数都更划算——因为这样的数与 $x$ 的 `xor` 只含比第 $i$ 位小的位，不会超过与 $y$ 已经能得到的 $2^i$。

于是回答第三类查询时，可以贪心地沿字典树下降，每次都尝试走向第 $i$ 位不等于 $x_i$ 的分支。
