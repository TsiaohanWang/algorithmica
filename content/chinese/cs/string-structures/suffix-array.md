后缀数组、自动机和后缀树统称后缀数据结构。它们用于大量竞赛与实践中出现的问题。

后缀结构常常（但不总是）可互换，而且彼此可在线性时间内转换。后缀数组是最简单的，因此从这里开始。

## 动机

字符串 $s$ 的**后缀数组**（英文 *suffix array*）是它的后缀起始下标的一种排列，给出这些后缀按字典序排序后的顺序。换句话说，构建它需对给定字符串的所有后缀排序。

![对字符串「mississippi$」的所有后缀排序](../img/sa-sort.png)

**它有什么用。** 假设你想再建一个搜索引擎，为拿融资得先做点能跑的东西——至少学会按关键词找出包含它的文档及其出现位置（在 90 年代这已是相当强的 MVP）。用简单算法——[多项式哈希](/cs/hashing)、[z 与前缀函数](/cs/string-searching)、甚至[Aho–Corasick](../aho-corasick)——都做不快，因为每次都要遍历全部数据；而后缀结构可以。

对后缀数组可以这样做：把所有文档字符串用某个非字母字符（`$`）连接，构建后缀数组，然后对每个查询用二分查找找后缀数组中第一个小于该词的与最后一个小于它的后缀。这两者之间的所有后缀都包含该字符串作为前缀。

例如，字符串 `iss` 在示例后缀数组中夹在 `issippi$` 与 `ississippi$` 两个后缀之间，它们的下标是 $2$ 和 $5$，因此恰在这些位置进入原文本。

这个算法运行在 $O(|t| \log |s|)$，之后可优化到 $O(|t| + \log |s|)$，这是最优的搜索算法之一。

现在学构建它。

## 构建后缀数组

为排序后缀，可以取一个 0 到 $n$ 的排列、写一个比较对应下标后缀的比较器、喂给 `std::sort`，运行在 $O(n^2 \log n)$，因为内部比较是 $O(n)$。但若用[哈希](/cs/hashing)比较后缀，就能得 $O(n \log^2 n)$ 的算法。不过这不是最快最方便的。

### 在 $O(n \log n)$ 内构建

为方便，在字符串末尾加一个字典序小于任何其他字符的字符。对标准 ASCII 常选「$」、「#」或零字符（若是 C 字符串；C 中字符串本就以零结尾）。

我们排序的不是后缀，而是*循环移位*。字符串也按循环看——这很方便，因为它们的长度都相同。容易验证这种循环移位的排序等价于后缀排序——只需去掉 $ 之后的一切。

算法由 $\lceil \log n \rceil$ 个阶段组成。第 $k$ 阶段对所有长度为 $2^k$ 的循环子串排序。于是最后阶段对长度 $\geq n$ 的串排序（合法——串是循环的），就得到所需后缀数组。

注意与后缀排序不同，子串排序不总是唯一——两个子串可能相同。因此算法每阶段除下标排列 $p$ 外，还为每个循环子串维护其*等价类*编号 $c_i$。等价类编号按保序给出：字典序更小的子串对应更小的 $c_i$。最后阶段后，等价类数组应给出后缀数组的逆排列。

例子：$s = aaba$。有 3 个阶段：对长度 1、2、4 的子串。

$$
   p_0 = (0, 1, 3, 2) \;\;\; c_0 = (0, 0, 1, 0)
\\ p_1 = (0, 3, 1, 2) \;\;\; c_1 = (0, 1, 2, 0)
\\ p_2 = (3, 0, 1, 2) \;\;\; c_2 = (1, 2, 3, 0)
$$

像真正的程序员，阶段从零编号，所以第零阶段对长度 $2^0 = 1$ 的串，即字符，排序。若字母表小，可用[计数排序](/cs/sorting/counting)在 $O(n)$ 内做。

后续阶段需利用前一阶段信息。像原解，可再建下标排列并用自定义比较器 `std::sort`。

要快速比较两个大小 $2^{k-1}$ 的子串，可用等价类 $c_i$，把每个长度 $2^k$ 的串对应成双字母（两个「字符」的串）。具体说，串 $s[i \ldots i+2^k-1]$ 排序上等价于对 $(c_i, c_{i+2^{k-1}})$。于是可写只看这些对的比较器，$O(1)$ 而非线性遍历。但这仍运行 $O(n \log^2 n)$，因为每阶段 $O(n \log n)$。

*注。这种方法常很快，因为常数小。*

要把每阶段优化到线性，需去掉排序里的对数。归并排序只在不知道排序值时最优——我们这里不是这样。

用[基数排序](/cs/sorting/radix)的思想——先按第二字符排双字母，再按第一字符。从前一阶段已知第二元素的顺序（正是数组 $p$）。现在要按第一字符排序，只需按这个顺序遍历后缀，从每个元素起点减去 $2^{k-1}$ 得到起点下标，再基数排序。于是每阶段 $O(n)$，整个算法 $O(n \log n)$。

```c++
// 字符串是 1 到字母表大小的一列数
vector<int> suffix_array(vector<int> &s) {
    s.push_back(0);  // 在字符串末尾加零字符
    int n = (int) s.size(),
        cnt = 0,  // 辅助变量：排序计数器
        cls = 0;  // 等价类个数
    vector<int> c(n), p(n);
    
    map<int, vector<int>> t;
    for (int i = 0; i < n; i++)
        t[s[i]].push_back(i);
    
    // "第零"阶段
    for (auto &x : t) {
        for (int u : x.second)
            c[u] = cls, p[cnt++] = u;
        cls++;
    }
    
    // 直到所有后缀变唯一
    for (int l = 1; cls < n; l++) {
        vector< vector<int> > a(cls);  // 计数排序数组
        vector<int> _c(n);  // 新等价类
        int d = (1 << l) / 2;
        int _cls = cnt = 0;  // 新类数
        
        for (int i = 0; i < n; i++) {
            int k = (p[i] - d + n) % n;
            a[c[k]].push_back(k);
        }
        
        for (int i = 0; i < cls; i++) {
            for (size_t j = 0; j < a[i].size(); j++) {
                // 若后缀开始新等价类
                if (j == 0 || c[(a[i][j] + d) % n] != c[(a[i][j - 1] + d) % n])
                    _cls++;
                _c[a[i][j]] = _cls - 1;
                p[cnt++] = a[i][j];
            }
        }
        
        c = _c;
        cls = _cls;
    }
    
    return vector<int>(p.begin() + 1, p.end());
}
```

## 最大公共前缀

许多应用需要能求字符串不同后缀的最大公共前缀（英文 *largest common prefix*）。

例如，只比较两个子串，可以求相应后缀的最大公共前缀再看下一个字符——和[哈希](/cs/hashing)常用做法一样。

**命题。** 假设已知后缀数组中相邻后缀的 `lcp`——这是长度 $(n - 1)$ 的数组。则第 $i$ 与第 $j$ 个后缀的公共前缀等于 `lcp` 数组中第 $c_i$ 与第 $c_j$ 个元素之间的最小值（回想 $c_i$ 是等价类——第 $i$ 个后缀在后缀数组中的编号）。

为证明，把 `lcp` 数组看成直方图。$c_i$ 与 $c_j$ 之间区间的最小值对应与它们公共前缀最短的后缀，因此该前缀之前的所有字符且只有它们构成最大公共前缀。

![字符串「BANANA$」的 LCP 数组](../img/lcp.png)

于是有动机算 `lcp` 数组（含相邻后缀的最大公共前缀），再用某种方式算该数组区间最小值（例如用[稀疏表](/cs/range-queries/sparse-table)）。

还需想一个快速算 `lcp` 数组的办法。可用 $O(n \log^2 n)$ 后缀数组构建的思想：用[哈希](/cs/hashing/polynomial/)与二分查找对每对相邻求 `lcp`。这运行 $O(n \log n)$，但不太方便也不流行。

### Kasai、Arimura、Arikawa、Lee、Park 算法

这个算法实际叫什么都有，就是不叫本名（*Kasai 算法*、*五个韩国人算法*等）。用于线性求 $lcp$。作者觉得这个算法思想上有点像 [z 函数](/cs/string-searching/z-function)。

**命题。** 假设已建后缀数组并算 $lcp[i]$。则：

$$
lcp[c[p[i] + 1]] \ge lcp[i] - 1
$$

即：原字符串中下一个后缀的 $lcp$ 至多少一。

**证明。** 若第 $p[i]$ 个后缀与第 $p[i + 1]$ 个后缀有公共部分长度 $lcp[i]$，则第 $(p[i] + 1)$ 个后缀保证与第 $(p[i + 1] + 1)$ 个后缀有公共部分长度 $(lcp[i] - 1)$。

注意这个后缀不必是后缀数组中 $(p[i] + 1)$ 的邻居，但由任意两个后缀的 $lcp$ 性质得 $lcp[c[p[i] + 1]] \ge lcp[i] - 1$。这里想法是：朴素算准确 $lcp$（能增就增），但用这个不等式取起始值。为避免多余比较，按从长后缀到短后缀的顺序算 `lcp` 数组。

算法代码：

```c++
    vector<int> calc_lcp(vector<int> &val, vector<int> &c, vector<int> &p) {
        int n = val.size();
        int l = 0; // 当前元素的 lcp
        vector<int> lcp(n);
        for (int i = 0; i < n; i++) {
            if (c[i] == n - 1)
                continue;
            int nxt = p[c[i] + 1];
            while (max(i, nxt) + l < n && val[i + l] == val[nxt + l])
                l++;
            lcp[c[i]] = l;
            l = max(0, l - 1);
        }
        return lcp;
    }
```

估复杂度：数一下朴素增量的次数。每个 $lcp[i] \le n$，且转移时最多做 $n$ 次减一。于是增量总数为 $O(n)$。故算法运行 $O(n)$。
