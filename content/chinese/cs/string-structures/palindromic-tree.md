回文树（英文 *palindromic tree*、*EERTREE*）是一种数据结构，它用比 $n$ 个回文的大小更强大的格式存储关于所有子回文的信息。它由 Mikhail Rubinchik 于 2014 年夏天在彼得罗扎沃茨克集训中提出。

**引理。** 字符串中不同的子回文至多有 $n$ 个。

**证明。** 设我们每次向字符串追加一个字符，此刻写下了 $r$ 个字符，有最大的后缀回文 $s_{l:r}$。设它又有一个后缀回文 $s_{l':r} = t$。那么 $t$ 在字符串中还有一个更早的出现：$s_{l:l+r-l'} = t$。因此，每新增一个字符，字符串至多产生一个新的回文；如果有的话，它总是最大的后缀回文。

这一事实让我们能给字符串的所有回文构造如下结构：取每个回文的右半部分（例如 $abacaba$ 取 $caba$，$abba$ 取 $ba$；暂时只看偶数回文），把这些半部分都加入一棵前缀树——得到的结构就叫*回文树*。

朴素的建树算法最坏情况下运行在 $O(n^2)$，但可以更高效。

### 线性时间建树

维护最大的后缀回文。当我们追加下一个字符 $c$ 时，需要找到这个回文中能被字符 $c$ 补全的最大后缀——它就是新的最长后缀回文。

为此，类似 [Aho–Corasick 算法](../aho-corasick)：为每个回文维护一条后缀链接 $l(v)$，从 $v$ 指向它最大的后缀回文。追加新字符时，沿后缀链接上升，直到找到能做出所需转移的顶点。

如果在该顶点中这个转移不存在，就要创建新顶点，并为它也需要自己的后缀链接。要找到它，继续沿上一个后缀回文的后缀链接上升，直到找到第二个能用字符 $c$ 补全的位置。

```c++
const int maxn = 1e5, k = 26;

int s[maxn], len[maxn], link[maxn], to[maxn][k];

int n, last, sz;

void init() {
    s[n++] = -1;
    link[0] = 1;
    len[1] = -1;
    sz = 2;
}

int get_link(int v) {
    while (s[n-len[v]-2] != s[n-1])
        v = link[v];
    return v;
}

void add_char(int c) {
    s[n++] = c;
    last = get_link(last);
    if (!to[last][c]) {
        len[sz] = len[last] + 2;
        link[sz] = to[get_link(link[last])][c];
        to[last][c] = sz++;
    }
    last = to[last][c];
}
```

这里我们用普通数组存转移。与任何前缀树一样，也可以用二叉搜索树、哈希表、单向链表等其他结构，通过稍改复杂度来换取内存，或反之。

### 复杂度

证明算法的线性性。考虑字符串的最大后缀回文的长度。每个新字符至多使它增加 2。而每走一条后缀链接都会使它减小，因此找到第一个后缀回文均摊在线性时间。

用对第二个后缀回文长度的类似讨论（其长度也至多增加 2），可得创建新顶点时重算后缀链接也总计在线性时间。
