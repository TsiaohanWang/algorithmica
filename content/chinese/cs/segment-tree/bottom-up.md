线段树用于处理这样的场景：有一个数组，需要处理一些修改，并在连续区间上执行查询。在第一个例子中，查询如下：

1. 修改数组中的元素
2. 求数组某区间上的和

### 完全二叉树

![](../img/segtree-ranges.png)

图中的标记形式为 `node_index: 区间 [L; R)`。最下面一行是 0 索引的数组——也就是树的叶子。假设数组长度是 2 的幂（例如 16），那么我们就得到一棵完全二叉树。顶点 $i$ 的值由顶点 $2i$ 和 $2i+1$ 的值组合得到。因此，如果要求半开区间 `[3; 11)` 上的和，只需要把顶点 19、5、12 和 26（粗体标出）的值相加，而不是范围内全部 8 个叶子。我们来看代码，理解它_为什么_能工作。

```cpp
const int N = 1e5;  // Ограничение на размер
int n;  // истинный размер
int t[2 * N];

void build() {  // Построить дерево отрезков
  for (int i = n - 1; i > 0; --i) t[i] = t[i<<1] + t[i<<1|1];
}

void modify(int p, int value) {  // Присвоить значение в точке
  for (t[p += n] = value; p > 1; p >>= 1) t[p>>1] = t[p] + t[p^1];
}

int query(int l, int r) {  // сумма на полуинтервале [l, r)
  int res = 0;
  for (l += n, r += n; l < r; l >>= 1, r >>= 1) {
    if (l&1) res += t[l++];
    if (r&1) res += t[--r];
  }
  return res;
}

int main() {
  scanf("%d", &n);
  for (int i = 0; i < n; ++i) scanf("%d", t + n + i);
  build();
  modify(0, 1);
  printf("%d\n", query(3, 11));
  return 0;
}
```

**就这些**。一个完整可运行的例子。把那些带 5 个参数的递归函数当作噩梦忘掉吧！

现在来分析一下为什么_这个_能工作，而且工作得如此高效。

1. 从图中可以看出，叶子从索引 `n` 开始连续存放，也就是说编号为 `i` 的元素对应编号为 `n + i` 的顶点。因此，可以直接把值读入线段树的叶子中。

2. 在处理查询之前需要先建树。这个过程很简单，耗时 $O(n)$。由于父顶点的索引小于子顶点的索引，可以按编号递减的顺序遍历所有顶点。如果你觉得位运算像黑魔法，那么 `build()` 中的代码等价于 `t[i] = t[2 * i] + t[2 * i + 1]`。

3. 修改元素同样简单（后续代码可以证明这一点），其运行时间与树高成正比，即 $O(\log n)$。只需要修改该顶点的祖先的值。因此，可以沿树向上走到根，同时记得顶点的祖先 `p` 是 `p / 2`（`p >> 1`），而 `p ^ 1` 把 `2 * i` 变成 `2 * i + 1`，反之亦然，也就是指出另一个儿子。

4. 求和的复杂度同样是 $O(\log n)$。为了更好地理解其逻辑，可以看例子 `[3; 11)`，验证结果恰恰来自顶点 19、26、12、5，并且正是这个顺序。

核心思想如下。如果查询左边界是奇数（即 `l&1`），那么 `l` 是它父节点的右儿子。这意味着区间包含 `l`，但不包含它的父节点。于是把 `t[l]` 加入答案，并把边界向侧上方移动（`l = (l + 1) / 2`）。如果 `l` 是偶数，那么它是左儿子，区间包含它的父节点（当然，只要右边界不碍事），所以可以直接跳到祖先（`l = l / 2`）。对右边界可以作同样的推理。当左右边界重合时算法停止。

**完全没有递归**。不需要计算区间的中点。只是遍历所有受影响的顶点，没有任何多余操作。

### 任意长度的数组

之前我们假设数组长度是 2 的幂，所以线段树是完全二叉树。下面这个事实可能会让你震惊，做好准备。

> *上述代码对任意长度的数组都有效*。

解释这一事实比前面更复杂，所以先来理解这种做法的优势。

1. 线段树恰好使用 $2n$ 内存，而不是某些实现建议的 $4n$（说的就是你，e-maxx！）。

2. 数组元素从索引 $n$ 开始连续存储。

3. 所有操作都非常高效且容易编写。

下一部分可以跳过，直接测试代码验证正确性即可。但如果你还是想要一个解释，来看 $n = 13$ 的例子。

![](../img/segtree-ranges2.png)

现在的线段树不再是单独一棵完全二叉树，而是一片由完全二叉树组成的森林：根 2 高度为 4，根 7 高度为 2，根 13 高度为 1。图中用短划线标出的顶点根本不会参与查询，所以里面放什么都可以。虽然叶子位于不同的高度，但这是可以补救的：在第 13 个顶点之前把树截断，再把右半部分拼到左边。原作者猜想，可以证明得到的结构在操作上与某个更大的完全二叉树的一部分同构，这是算法正确性的主要原因。

这里没有形式化证明，只用一个例子来说明。考虑区间 `[0; 7)`。初始时 `l = 13, r = 20`，`l&1 => add t[13]`，边界移到 `l = 7, r = 10`。再次 `l&1 => add t[7]`，边界移到 `l = 4, r = 5`，两个顶点在同一高度。现在 `r&1 => add t[4 = --r]`，边界变为 `l = r = 2`，算法结束。

### 区间修改、单点查询

如果把查询调换一下，有些人会想到非常复杂的方案，例如

1. 给区间内所有元素加上一个值

2. 查询某个元素的值

但其实只需要交换 `modify` 和 `query` 的实现：

```cpp
void modify(int l, int r, int value) {
  for (l += n, r += n; l < r; l >>= 1, r >>= 1) {
    if (l&1) t[l++] += value;
    if (r&1) t[--r] += value;
  }
}

int query(int p) {
  int res = 0;
  for (p += n; p > 0; p >>= 1) res += t[p];
  return res;
}
```

这段代码的思路是：现在我们存储的是相邻元素之间的变化量，而不是数组本身，因此元素的值就是前缀和。

如果需要查看整个数组，就必须把所有的修改下推到叶子。这样的代码可以在 $O(n)$ 时间内得到所有元素，而不是 $O(n \log n)$，这和使用 `build` 而不是 $n$ 次更新查询一样。

```cpp
void push() {
  for (int i = 1; i < n; ++i) {
    t[i<<1] += t[i];
    t[i<<1|1] += t[i];
    t[i] = 0;
  }
}
```

不过要承认，这类代码只有在单个元素的修改顺序不影响最终结果时才有效。例如，赋值就不满足这个条件。这种情况会在「懒标记」一节中详细讨论。

## 非交换的合并函数

前面只讨论了非常简单的合并函数——加法。它是可交换的，即满足交换律：$a + b = b + a$。乘法、$\gcd$、$\min$、$\max$ 也同样如此，所以只需把所有 `+` 替换成这些函数之一即可正常工作。最重要的是别忘了更换中性元素（单位元）。

但现实世界中有使用非结合合并函数的题目，例如 [380C Sereja and Brackets](https://codeforces.com/contest/380/problem/C)。幸运的是，本实现可以很容易地支持这种改动。为某结构定义结构体 `S` 及其合并函数 `S combine(S, S)`。在 `build` 中只需把 `+` 换成这个函数。在 `modify` 中要注意子节点的正确顺序，并利用左儿子索引为偶数这一事实。在回答查询时，左边界从左往右合并，右边界从右往左合并，代码看起来是这样：

```cpp
void modify(int p, const S& value) {
  for (t[p += n] = value; p >>= 1; ) t[p] = combine(t[p<<1], t[p<<1|1]);
}

S query(int l, int r) {
  S resl, resr;
  for (l += n, r += n; l < r; l >>= 1, r >>= 1) {
    if (l&1) resl = combine(resl, t[l++]);
    if (r&1) resr = combine(t[--r], resr);
  }
  return combine(resl, resr);
}
```

## 懒标记

懒标记让我们可以对区间进行查询，也可以对区间进行修改。首先，引入一些变量：

```cpp
int h = sizeof(int) * 8 - __builtin_clz(n);  // h = log2(n)
int d[N]; 
```

`h` 是树的高度，即 `n` 的最高位所在位置。`d[i]` 是需要下推到顶点 `i` 的子节点的懒操作列表（看完例子会更清楚）。数组大小只需要 `N`，因为叶子没有子节点。最终内存占用为 $3n$。

前面说过，`t[i]` 对应其区间上函数的值。现在就不完全是这样了——需要先应用从顶点 `i` 到根路径上的所有懒操作。我们假设 `t[i]` 已经包含了 `d[i]`，所以路径不是从 `i` 开始，而是从它的直接祖先开始。

回到区间 $[3; 11)$ 的例子，但现在我们要更新区间内的所有元素。为此，修改顶点 19、5、12 和 26 的 `t[i]` 和 `d[i]` 值。此后，如果例如要获取顶点 22 的值，就需要把顶点 5 的修改下推。另外注意，修改操作可能会改变其祖先的 `t[i]` 值：顶点 19 影响顶点 9、4、2 和 1，顶点 5 影响顶点 2 和 1。下面这个事实对渐近复杂度估计至关重要：

> 区间 $[l; r)$ 上的修改只会影响极端叶子（`l+n` 和 `r+n-1`）的祖先的 `t[i]` 值。

证明很简单：移动左边界时，循环中修改的顶点始终是其祖先的右儿子。这意味着之前的所有修改都是在同一个祖先的左儿子子树内完成的，否则我们就会处理该祖先，而不是它的两个儿子。因此，当前这个直接祖先也是叶子 `l+n` 的祖先之一。对右边界的推理类似。

空话少说，上具体例子的代码。

### 区间加、区间求最大值

这可能是最简单的情况。下面这段代码谈不上通用，也不是最有效的，但是一个好的起点。

```cpp
void apply(int p, int value) {
  t[p] += value;
  if (p < n) d[p] += value;
}

void build(int p) {
  while (p > 1) p >>= 1, t[p] = max(t[p<<1], t[p<<1|1]) + d[p];
}

void push(int p) {
  for (int s = h; s > 0; --s) {
    int i = p >> s;
    if (d[i] != 0) {
      apply(i<<1, d[i]);
      apply(i<<1|1, d[i]);
      d[i] = 0;
    }
  }
}

void inc(int l, int r, int value) {
  l += n, r += n;
  int l0 = l, r0 = r;
  for (; l < r; l >>= 1, r >>= 1) {
    if (l&1) apply(l++, value);
    if (r&1) apply(--r, value);
  }
  build(l0);
  build(r0 - 1);
}

int query(int l, int r) {
  l += n, r += n;
  push(l);
  push(r - 1);
  int res = -2e9;  // лучше конечно писать INT_MIN
  for (; l < r; l >>= 1, r >>= 1) {
    if (l&1) res = max(res, t[l++]);
    if (r&1) res = max(t[--r], res);
  }
  return res;
}
```

按函数分析代码。前三个是辅助函数，调用方程序不需要知道它们。

1. 每个顶点有两个值，所以最好写一个函数统一应用（`apply`）对它们的修改。`p < n` 表示 `p` 不是叶子。最大值的一个重要性质：如果区间内所有值都增加某个数，那么最大值也增加这个数。

2. `build` 更新顶点的所有祖先。

3. `push` 从根开始，把顶点的所有祖先的修改下推。这些祖先是 `p` 的二进制表示的前缀，所以计算它们时用到位移运算。

现在来看主要函数。

1. `inc`：用熟悉的循环处理增量查询，然后用 `build` 更新所有剩余部分。

2. `query`：回答查询时沿用之前的循环，但在此之前需要把修改下推到我们将要用到的顶点。和 `build` 一样，只需把从祖先到边界叶子的修改下推即可。

很容易看出所有操作都是 $O(\log n)$ 时间。

这个例子简单，因为

1. 修改的顺序不影响它们的结果（合并函数的可交换性）

2. 更新某个顶点时不需要知道该顶点的区间长度。

下一个例子将展示如何把这些因素都考虑进去。

### 区间赋值、区间求和

这个例子受题目 [Timus 2042](http://acm.timus.ru/problem.aspx?space=1&num=2042) 启发。

又是从辅助函数开始。

```cpp
void calc(int p, int k) {
  if (d[p] == 0) t[p] = t[p<<1] + t[p<<1|1];
  else t[p] = d[p] * k;
}

void apply(int p, int value, int k) {
  t[p] = value * k;
  if (p < n) d[p] = value;
}
```

这只是两个函数：在 $O(1)$ 时间内计算顶点 `p` 的值，以及对它应用懒操作。但有几点需要记住：

1. 假定存在一个永远不会用于修改的值，本例中是 0。如果不存在这样的值，就额外开一个 bool 数组，用它代替 `d[p] == 0` 来判断是否有修改。

2. 多了一个参数 `k`，表示顶点区间的长度。下文代码中的 `k` 都指这个意思。显然，不知道区间长度就无法计算区间和。可以不向函数传递区间长度，比如根据顶点索引即时计算，或者把所有区间长度存到专门的数组里，但这些做法都太费时间或空间。

接下来需要更新 `build` 和 `push`。我们之前有两种版本——一种在 $O(n)$ 时间内遍历整棵树，另一种在 $O(\log n)$ 时间内遍历某个叶子的所有祖先。可以把这两个函数合并，得到更多功能：

```cpp
void build(int l, int r) {
  int k = 2;
  for (l += n, r += n-1; l > 1; k <<= 1) {
    l >>= 1, r >>= 1;
    for (int i = r; i >= l; --i) calc(i, k);
  }
}

void push(int l, int r) {
  int s = h, k = 1 << (h-1);
  for (l += n, r += n-1; s > 0; --s, k >>= 1)
    for (int i = l >> s; i <= r >> s; ++i) if (d[i] != 0) {
      apply(i<<1, d[i], k);
      apply(i<<1|1, d[i], k);
      d[i] = 0;
    }
}
```

两个函数都是 $O( \log(n) + |r-l| )$ 时间。如果需要对树上的某个区间做修改，可以写成类似

```cpp
push(l, r);
...  // делаем что угодно с элементами из промежутка [l, r)
build(l, r);
```

这些函数是怎么工作的？首先把原始区间转到 $[l+n;r+n-1]$，这样才能正确地计算祖先。由于它们按层遍历树，很容易维护区间长度，它始终是 2 的幂。`build` 自底向上遍历，所以初始 $k = 2$（不是 1，因为叶子不需要做任何事），每上一层翻倍。`push` 自上而下遍历，所以 $k = 2^h$（即取决于树的高度），每下一层减半。

上一个例子中的主要函数变化不大，但 `modify` 中：

1. 必须确保从根到需要更新的顶点路径上没有其他修改，因为修改的顺序很重要。这只需像 `query` 中那样调用一次 `push`。

2. 需要维护 `k` 的值。

```cpp
void modify(int l, int r, int value) {
  if (value == 0) return;
  push(l, l + 1);
  push(r - 1, r);
  int l0 = l, r0 = r, k = 1;
  for (l += n, r += n; l < r; l >>= 1, r >>= 1, k <<= 1) {
    if (l&1) apply(l++, value, k);
    if (r&1) apply(--r, value, k);
  }
  build(l0, l0 + 1);
  build(r0 - 1, r0);
}

int query(int l, int r) {
  push(l, l + 1);
  push(r - 1, r);
  int res = 0;
  for (l += n, r += n; l < r; l >>= 1, r >>= 1) {
    if (l&1) res += t[l++];
    if (r&1) res += t[--r];
  }
  return res;
}
```

可以看到 `modify` 代码不够最优：对顶点进行了三次遍历：一次向下（`push`），两次向上。最后一次向上遍历可以省去，但代码会变得难看：

```cpp
void modify(int l, int r, int value) {
  if (value == 0) return;
  push(l, l + 1);
  push(r - 1, r);
  bool cl = false, cr = false;
  int k = 1;
  for (l += n, r += n; l < r; l >>= 1, r >>= 1, k <<= 1) {
    if (cl) calc(l - 1, k);
    if (cr) calc(r, k);
    if (l&1) apply(l++, value, k), cl = true;
    if (r&1) apply(--r, value, k), cr = true;
  }
  for (--l; r > 0; l >>= 1, r >>= 1, k <<= 1) {
    if (cl) calc(l, k);
    if (cr && (!cl || l != r)) calc(r, k);
  }
}
```

两个标志分别表示左侧和右侧是否发生了修改。看一个例子：

![](../img/segtree-ranges-3.png)

对区间 $[4; 13)$ 调用 `modify`：

1. `l = 20, r = 29`，调用 `apply(28)`。
2. `l = 10, r = 14`，调用 `calc(14)`：当前区间右侧的第一个顶点恰好是最后被修改顶点的祖先。
3. `l = 5, r = 7`，先调用 `calc(7)`，再调用 `apply(5)` 和 `apply(6)`。
4. `l = 3, r = 3`，第一个循环结束。

现在明白为什么要做 `--l` 了，因为还需要更新顶点 2、3，然后是 1。退出条件是 `r > 0`，因为第一个循环结束后可能得到 `l = r = 1`，这时必须更新根，但 `--l` 会让 `l = 0`。

与上一版相比，省去了多余的 `calc(10)`、`calc(5)` 调用，但多了一次 `calc(1)` 调用。

### 注意事项

只要你没有试图直接读取树中的值（叶子除外），一切都能正常工作。如果数组长度不是 2 的幂，就不能用 `t[1]` 得到整个数组的答案。必须调用 `query(0, n)` 才行！
