title: 懒标记
weight: 4
---

考虑问题的一个变体。给定大小为 $n$ 的数组，需要回答两种类型的查询：

1. 把区间 $[l, r)$ 上的所有值替换为 $x$（对所有从 $l$ 到 $r$ 的 $k$ 执行 `a[k] = x`）。
2. 输出 $a_i$ 在区间 $[l, r]$ 上的元素之和。

也就是说，现在的更新查询是把某个区间 $[l, r)$ 内的所有元素赋值为 $x$，而不再只是单个元素，同时我们仍然希望以 $O(\log n)$ 时间处理两种查询。

### 核心思想

我们不想下潜到每个需要改和的元素——它们可能非常多。

取而代之，我们要个小聪明：在赋值查询时，尽量去“标记”某些顶点，表示它们及它们的所有子节点都应等于某个数 $d_v = x$，但不再继续往下走、不去实际执行这些赋值。

例如，如果收到一个“把整个数组赋值为 $x$”的查询，那么我们根本不会做任何实际的赋值——只在树根留下标记，表示其中所有元素都等于 $x$。

当我们之后需要这些顶点及其子节点的正确值时，就沿着从根向下的路径“下推”当前顶点的信息：如果带有标记，就重新计算当前区间的和，并把标记传给子节点（不递归进入子节点）。等我们之后需要子节点的字段时，再做同样的事——在它们那里重新计算和并把标记传给它们的子节点，依此类推。这样的操作能保证顶点的数据恰好在我们需要它的时候是正确的。

节省工作的关键在于：当把标记传给一个已有标记的子节点时，旧标记直接被覆盖，我们就不再需要执行旧的赋值的。拖延工作的好处在于，这些被推迟的操作里有一部分将来根本不需要做。

使用这些“滞后”更新不会让渐近复杂度变差——我们只是在路径上的每个顶点多做了 $O(1)$ 次操作来执行一次延迟操作——因此我们依然以 $O(\log n)$ 时间回答所有查询。

### 实现

添加标记字段 `assign`，并创建辅助函数 `push`，它负责把该顶点的信息下推到它的两个儿子。

```cpp
struct Segtree {
    int lb, rb;
    int sum = 0, assign = -1; // "-1" означает, что присвоения делать не нужно
    Segtree *l = 0, *r = 0;
    
    Segtree(int lb, int rb) : lb(lb), rb(rb) {
        if (lb + 1 < rb) {
            int t = (lb + rb) / 2;
            l = new segtree(lb, t);
            r = new segtree(t, rb);
        }
    }
    
    void push() {
        if (assign != -1) {
            sum = (rb - lb) * assign;
            if (l) { // если дети есть
                l->assign = assign;
                r->assign = assign;
            }
        }
        assign = -1;
    }
};
```

在任何查询处理的最开始调用 `push` 方法——它能保证当前顶点中所有值都是正确的，并且子节点中已有足够的信息，使得在递归下潜并对它们调用 `push` 后，这些值也变成正确的。

```cpp
void add(int lq, int rq, int x) {
    push();
    if (lq <= lb && rb <= rq)
        assign = x;
    else if (l && max(lb, lq) < min(rb, rq)) {
        // если есть дети и отрезок запроса хоть как-то пересекается с нашим
        l->add(lq, rq, x);
        r->add(lq, rq, x);
        // ...дальше они сами разберутся
    }
}

int sum(int lq, int rq) {
    push();
    if (lb >= lq && rb <= rq)
        return s;
    if (max(lb, lq) >= min(rb, rq))
        return 0;
    return l->sum(lq, rq) + r->sum(lq, rq);
}
```

这种技术英文叫 *lazy propagation*。这个“所有事都拖到最后再做”的思路不仅适用于线段树，也适用于其他数据结构 ~~和现实生活~~。
