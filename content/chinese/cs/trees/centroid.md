重心分解是把「分治」方法推广到树上的技术。它通常用来解决两类问题：「有多少条路径具有某种性质」和「某条路径是否具有某种性质」。

有时可以不用它，改用 [重链剖分](../heavy-light)（稍微复杂一点），或者用启发式合并（更简单一点）。

![](../img/centroid.jpg)

**定义**。树的*中心*或*重心*（英文 *centroid*）是指这样一类顶点：删除它之后，剩余各连通分量的大小都不超过 $\frac{n}{2}$。

重心一定存在——这可以从寻找它的算法中看出：

```c++
int s[maxn];

int sizes (int v) {
    s[v] = 1;
    for (int u : g[v])
        // для простоты считаем, что дерево корневое
        s[v] += sizes(u);
    return s[v];
}

// второй параметр -- размер дерева
int centroid (int v, int n) {
    for (int u : g[v])
        if (s[u] > n/2)
            return centroid(u, n);
    return v;
}
```

**结论**。`centroid` 确实能找到重心。

**证明：**

* `centroid` 会返回一个所有孩子的大小都不超过 $\frac{n}{2}$ 的顶点（这一点在 `if` 中显式检查了）。
* 我们到达这个顶点时，它的大小大于 $\frac{n}{2}$，这意味着在「相反」方向上最多有 $n - (\frac{n}{2}+1) = \frac{n}{2}-1$ 个顶点。
* 因此，所有邻居的大小都不超过 $n$ 的一半，算法是正确的。

有时重心有两个（例子：1-**2-3**-4），这时算法会返回「下方」的那个重心。

**定义**。*重心分解*是指这样的递归过程：「找出重心，删除它，对剩余各连通分量递归执行」。

**定义**。某重心的*分量*是指：在该重心被删除之前，从它出发能到达的顶点集合。

注意，最终整棵树都会被删除，也就是说每个顶点恰好成为过一次其所在分量的重心。

现在来理解我们做这一切的目的。

**结论**。每个顶点属于 $O(\log n)$ 个分量。

**证明**。重心把树分成的各个分量，大小至少减半。因此，任何一个顶点都不可能「活过」超过 $\lceil \log_2 n \rceil$ 次分割。

**推论**。重心分解（见上面的定义）的时间复杂度为 $O(n \log n)$。

**结论**。对任意路径 $a \leadsto b$，存在唯一一个重心 $c$，使得 $a$ 和 $b$ 都曾在它的分量中。

**证明**。每个顶点都曾成为过重心。路径上的某个顶点最先成为重心，它从此永远把 $a$ 和 $b$ 分隔开。

这些都是非常重要的结论。也就是说，在重心分解的过程中，对每条简单路径都恰好存在一种情况：这条路径包含在某个分量中，并且经过该分量的重心。恰好就在这一刻，我们可以用类似于启发式合并的技术来处理某个查询。

## 统计具有给定性质的路径条数

来看一个具体例子：统计指定长度的路径条数。

我们介入重心分解的过程：对每个重心，在删除它之前，把经过它的、我们感兴趣的路径条数加到答案中。

这样的路径条数可以在当前分量的大小内统计出来：开一个数组 `d`，记录从 0 到分量大小每个距离上的顶点个数。把树-分量以重心为根挂起来，然后从它的直接孩子出发运行 `dfs`，它会返回一个临时数组 `t`——该子树中各个顶点的深度列表。我们可以遍历 `t` 中的每个值 `x`，把 `d[l-x]` 加到答案上，然后把 `t` 中的所有值都加进 `d`。可以验证，这样每条我们感兴趣的路径都恰好被统计一次。

```c++
int l = 179; // нужная нам длина
int ans = 0;

// нам лень явно удалять вершины: заведем массив used -- была ли вершина удалена
bool used[maxn];
int s[maxn]; // размеры поддеревьев

void sizes(int v, int p) {
    s[v] = 1;
    for (int u : g[v])
        if (u != p && !used[u])
            sizes(u, v), s[v] += s[u];
}

int centroid(int v, int p, int n) {
    for (int u : g[v])
        if (u != p && !used[u] && s[u] > n/2)
            return centroid(u, v, n);
    return v;
}

// записывает в t[] глубины вершин
void dfs(int v, int p, int d, vector<int> &t) {
    t.push_back(d);
    for (int u : g[v])
        if (u != p && !used[u])
            dfs(u, v, d + 1, t);
} 

void solve(int v) {
    /* <единственный зависящий от конкретной задачи код> */
    sizes(v);
    vector<int> d(s[v], 0);
    d[0] = 1;
    for (int u : g[v]) {
        if (!used[u]) {
            vector<int> t;
            dfs(u, v, 1, t);
            for (int x : t)
                if (x <= l)
                    ans += d[l-x];
            for (int x : t)
                d[x]++;
        }
    }
    /* </единственный зависящий от конкретной задачи код> */

    used[v] = 1;
    for (int u : g[v])
        if (!used[u])
            solve(centroid(u, v, s[u]));
}
```

**渐近复杂度**为 $O(n \log n)$，因为在重心分解的 $O(\log n)$ 个「层级」中的每一层，我们对 $O(n)$ 个顶点中的每一个都只花费 $O(1)$ 次操作。

## 路径查询——offline

我们在得到一个新分量后，立刻就能求出我们需要的所有东西。如果我们有一批「统计路径上某值」的查询，那么通常可以在 offline 模式下处理它们。

也就是说，我们可以在顶点上挂一个属于它、但尚未回答的查询列表。在处理某个分量的过程中扫描这个列表：如果重心位于该查询的路径上，就回答这个查询并把它从列表中删除，否则直接忽略。

例如，对于路径上的和查询，我们可以在内部 `dfs` 中为每个顶点算出从它的当前重心到该顶点的路径和；如果在处理当前分量时，在另一个分支里遇到了查询的第二端点，只需用它的路径和与已算出的到第一端点的路径和相加即可。

这样一来，每个查询最多被扫描 $O(\log n)$ 次直到被删除，总复杂度为 $O(q \log n + n \log n)$。

## 路径查询——online

另一种做法是：先「建好」重心分解，然后再回答查询。

假设我们要回答路径上的最小值查询，而且不会用倍增法求 LCA。建立一个大小为 $n \times \log n$ 的二维数组 `centroid[][]`，对每个顶点存放它曾经属于过的 $O(\log n)$ 个重心。此外，在同样的数组里存放回答查询所需的信息——本例中，对每个「顶点–重心」对存放对应路径上的最小值。

这样，回答查询时，我们用 $O(\log n)$ 甚至 $O(\log \log n)$ 次操作找到所求路径上的重心（`centroid[v]` 和 `centroid[u]` 有几个初值相同——我们关心的是最后一个），然后用两条到重心的路径上的最小值，取较小者作为答案。

## 当重算更慢时的复杂度

假设我们的「merge」（负责回答查询或统计经过重心的路径的那部分）不是线性时间，而是 $O(n \log n)$——例如在某个地方用了 `set`。这会让时间严重变差吗？

在最坏情况（竹子形树）下，每次分量都会被分成相等的两半。对递归树中的所有操作求和：

$$
\sum_{k=0}^{\log n} n \log \frac{n}{2^k}
= \sum_{k=0}^{\log n} n (\log n - k)
= n \sum_{k=0}^{\log n} k
= \Theta (n \log^2 n)
$$
