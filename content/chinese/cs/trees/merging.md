考虑这样一个问题：给定一棵有根树，顶点被染成各种颜色。对每个顶点，需要统计它子树中不同颜色的数量。

要知道不同颜色的数量，用 std::set 或 std::unordered_set 就够了。我们希望在某个时刻，对每个顶点都能得到这样一个 set。

叶子的答案显然很容易得到。现在假设我们已经有所有孩子对应的答案结构。把它们全都合并起来，就得到了当前顶点的答案结构。但这样合并的总代价是子树大小级别的。我们改用从小到大合并的思想（启发式合并）：选出最大的孩子，把自己的结构复制成它的结构（注意应该保存指向 set 的指针，而不是 set 本身）。然后遍历其他所有孩子的 set 中的元素，把它们加进我们的 set 里。

### 估计运行时间

考虑顶点 $v$。假设它当前位于一个管辖 $k$ 个顶点的结构中。如果我们看到了顶点 $v$，说明当前正把这个结构合并到另一个里，因此 $v$ 所在结构的大小至少是 $2 \* k$，于是同一个顶点被合并的次数不可能超过 $O(log(N))$ 次，其中 $N$ 是整棵树的顶点数。那么显然，总的合并次数为 $O(Nlog(N)$，而根据选择 set 还是 unordered_set，我们得到的复杂度是 $- O(Nlog^2(N))$ 或 $O(Nlog(N))$。
