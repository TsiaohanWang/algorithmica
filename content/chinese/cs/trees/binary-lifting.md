在解决 LCA 问题以及其他问题的背景下，以下方法非常流行。

### 预处理

对每个顶点预处理它的第 1 个祖先、第 2 个祖先、第 4 个祖先，依此类推。把它们存进大小为 $n \times \lceil \log n \rceil$ 的二维数组 `up` 中：`up[v][d]` 存放顶点 $v$ 距离 $2^d$ 的祖先；如果这样的顶点不存在，就存放根。

这个预处理可以在 $O(n \log n)$ 内完成，利用的事实是：距离 $2^{d+1}$ 的祖先，就是「距离 $2^d$ 的祖先」距离 $2^d$ 的祖先：

```c++
int up[maxn][logn];

void dfs(int v) {
    for (int l = 1; l < logn; l++)
        up[v][l] = up[up[v][l-1]][l-1];
    tin[v] = t++;
    for (int u : g[v]) {
        up[u][0] = v;
        dfs(u);
    }
    tout[v] = t;
}
```

预处理总共占用 $O(n \log n)$ 的时间和内存，因为数组 `up` 的大小就是这个量级，而且它的每个元素都可以在常数时间内算出。

### 查询

现在假设收到一个查询 LCA 的顶点对 $(u, v)$：

* 检查其中一个顶点是否另一个顶点的祖先——如果是，那么它就是要找的结果。
* 否则，利用数组 `up`，沿着其中一个顶点的祖先不断向上爬，直到找到「还不是另一个顶点的祖先」的最高顶点。它的下一个祖先就是所求的 LCA。

详细说说第二点。令 $i = \lceil \log n \rceil$，然后不断把这个变量减一，直到 `up[v][i]` 不再是 $u$ 的祖先。当这发生时，把指针移动到 $v$ 的 $2^i$ 祖先处，然后继续：

```c++
int lca(int v, int u) {
    if (a(v, u)) return v;
    if (a(u, v)) return u;
    for (int l = logn-1; l >= 0; l--)
        if (!ancestor(up[v][l], u))
            v = up[v][l];
    return up[v][0];
}
```

指针 `up[v][i]` 一开始是树的根，之后每一轮迭代会下降 $2^i$。当它成为 LCA 的后代时，我们只需要再上升一次，因为连续跳两次 $2^i$ 的距离等价于跳一次 $2^{i+1}$，而后者本可以在上一步完成。

任意一次查询的答案都可以在 $O(\log n)$ 内求出，因为我们实际上是在做二分查找。

### 路径上的查询

假设我们问的不是 LCA，而是例如任意路径上的最小值（所有边上都写有一些数）。

我们可以做与倍增法相同的预处理，但在保存第 $2^d$ 个祖先的编号时，同时保存对应路径上的最小值。

注意，从 $u$ 到 $v$ 路径上的最小值，等于从 $u$ 到 $lca(u, v)$ 路径上的最小值与从 $v$ 到 $lca(u, v)$ 路径上的最小值中较小者。而这两个最小值，又分别是对应到 LCA 的所有倍增段上的最小值。

```c++
int get_min(int v, int u) {
    int res = inf;
    for (int l = logn-1; l >= 0; l--)
        if (!ancestor(up[v][l], u))
            v = up[v][l], res = min(res, mn[v][l]);
    for (int l = logn-1; l >= 0; l--)
        if (!ancestor(up[u][l], v))
            u = up[u][l], res = min(res, mn[u][l]);
    return min({res, mn[v][0], mn[u][0]})
}
```

类似地，还可以计算路径上的和、`gcd`、多项式哈希以及许多其他奇怪函数，但只限于静态情形——即没有更新操作的情况。对于动态情形，存在一个复杂得多的方法，叫做 [重链剖分](../heavy-light)。
