让编译器发挥高性能的第一步是向它提出要求，这通过一百多种不同的编译选项、属性和 pragma 来完成。

### 优化级别

GCC 中用于追求速度的优化级别主要有 4 个*半*：

- `-O0` 是默认级别，不做任何优化（尽管从某种意义上说，它也做了优化：针对编译时间）。
- `-O1`（别名 `-O`）做少量「唾手可得」的优化，几乎不影响编译时间。
- `-O2` 启用所有已知几乎没有负面副作用、且能在合理时间内完成的优化（大多数项目在生产构建中使用这一级别）。
- `-O3` 进行非常激进的优化，几乎启用 GCC 中实现的所有*正确*优化。
- `-Ofast` 做 `-O3` 的全部优化，外加几个可能破坏严格标准符合性的优化标志，但其方式不会对大多数应用造成致命影响（例如，浮点运算可能被重排，导致结果在尾数上差几个比特）。

还有许多其他优化标志甚至连 `-Ofast` 都不包含，因为它们非常讲究场合，默认启用更可能损害性能而不是提升性能——我们将在[下一节](../situational)讨论其中的一部分。

### 指定目标平台

接下来你可能想做的，是告诉编译器更多关于这段代码所预期运行的计算机的信息：平台集合越小越好。默认情况下，编译器会生成能在任何相对较新（2000 年以后）的 x86 CPU 上运行的二进制文件。缩小范围的最简单方法是传入 `-march` 标志来指定精确的微架构：`-march=haswell`。如果你就在将要运行该二进制文件的同一台计算机上编译，可以使用 `-march=native` 进行自动检测。

指令集通常是向后兼容的，所以往往只需使用你需要支持的最老微架构的名称即可。更稳健的做法是列出 CPU 保证具备的特定特性：`-mavx2`、`-mpopcnt`。当你只想为某台特定机器*调优*程序、而不使用任何可能在不兼容 CPU 上导致崩溃的指令时，可以使用 `-mtune` 标志（默认情况下 `-march=x` 也隐含了 `-mtune=x`）。

这些选项也可以通过 pragma 针对某个编译单元指定，而不必使用编译标志：

```c++
#pragma GCC optimize("O3")
#pragma GCC target("avx2")
```

当只需要优化单个高性能过程、又不想增加整个项目的构建时间时，这很有用。

### 多版本函数

有时你可能还想在单个库中提供多个针对特定架构的实现。可以在编译期使用基于属性的语法在多个版本的函数之间自动选择：

```c++
__attribute__(( target("default") )) // fallback implementation
int popcnt(int x) {
    int s = 0;
    for (int i = 0; i < 32; i++)
        s += (x>>i&1);
    return s;
}

__attribute__(( target("popcnt") )) // used if popcnt flag is enabled
int popcnt(int x) {
    return __builtin_popcount(x);
}
```

在 Clang 中，你不能用 pragma 从源代码里设置目标平台和优化标志，但可以像在 GCC 中那样使用属性。
