当编译器能推断出某个变量不依赖于任何用户提供的数据时，它可以在编译期计算出该变量的值，并通过把它嵌入生成的机器代码中将其变成一个常量。

这种优化对性能帮助很大，但它并不是 C++ 标准的一部分，所以编译器并非*必须*这样做。当一次编译期计算要么难以实现、要么非常耗时的时候，编译器可能放弃这个机会。

### 常量表达式

为了获得更可靠的解决方案，在现代 C++ 中你可以把函数标记为 `constexpr`；如果通过传入常量来调用它，就能保证其值在编译期被计算出来：

```c++
constexpr int fibonacci(int n) {
    if (n <= 2)
        return 1;
    return fibonacci(n - 1) + fibonacci(n - 2);
}

static_assert(fibonacci(10) == 55);
```

这些函数有一些限制，比如它们只能调用其他 `constexpr` 函数、不能进行内存分配，但除此之外，它们会「原样」执行。

注意，虽然 `constexpr` 函数在运行时零成本，但它们仍然会增加编译时间，所以至少稍微关心一下它们的效率，别把 NP 完全问题放进去：

```c++
constexpr int fibonacci(int n) {
    int a = 1, b = 1;
    while (n--) {
        int c = a + b;
        a = b;
        b = c;
    }
    return b;
}
```

在更早的 C++ 标准中，限制要多得多，比如你不能在函数内部使用任何形式的状态，只能依赖递归，所以整个过程的感觉更像是在写 Haskell 而不是 C++。自 C++17 起，你甚至可以用命令式风格计算静态数组，这对于预计算查找表非常有用：

```c++
struct Precalc {
    int isqrt[1000];

    constexpr Precalc() : isqrt{} {
        for (int i = 0; i < 1000; i++)
            isqrt[i] = int(sqrt(i));
    }
};

constexpr Precalc P;

static_assert(P.isqrt[42] == 6);
```

注意，当你传入非常量调用 `constexpr` 函数时，编译器可能会、也可能不会在编译期计算它们：

```c++
for (int i = 0; i < 100; i++)
    cout << fibonacci(i) << endl;
```

在这个例子中，虽然从技术上来说我们执行了固定次数的迭代，并用编译期已知的参数调用 `fibonacci`，但从技术上讲，这些参数并不是编译期常量。是否优化这个循环完全取决于编译器——而对于繁重的计算，它常常选择不优化。
