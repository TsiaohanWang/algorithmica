硬件浮点数的舍入方式出奇地简单：当且仅当运算结果无法精确表示时才会发生舍入，默认情况下会舍入到最近的、可表示的数（若恰好居中，则优先选择末位为 0 的那个数）。

请看下面的代码片段：

```c++
float x = 0;
for (int i = 0; i < (1 << 25); i++)
    x++;
printf("%f\n", x);
```

它没有打印出 $2^{25} = 33554432$（数学上应有的结果），而是输出了 $16777216 = 2^{24}$。为什么？

当我们不断递增浮点数 $x$ 时，最终会到达某个点，使 $x$ 变得足够大，以至于 $(x + 1)$ 会被舍入回 $x$。第一个这样的数是 $2^{24}$（尾数位数加 1），因为

$$2^{24} + 1 = 2^{24} \cdot 1.\underbrace{0\ldots0}_{\times 23} 1$$

与 $2^{24}$ 和 $(2^{24} + 1)$ 的距离恰好相等，但根据上面提到的平局裁决规则会被舍入到 $2^{24}$。与此同时，所有比它小的数自增时都能被精确表示，因此一开始根本不会发生舍入。

### 舍入误差与运算顺序

浮点计算的结果可能依赖运算的顺序，尽管它在代数上是正确的。

例如，虽然加法和乘法在纯粹的数学意义上是可交换、可结合的，但它们的舍入误差却并非如此：当我们有三个浮点变量 $x$、$y$、$z$ 时，$(x+y+z)$ 的结果取决于求和的顺序。同样的不可交换性原理也适用于大多数（如果不是全部）其他浮点运算。

编译器不允许产生[不符合规范](/hpc/compilation/contracts/)的结果，因此这个恼人的细节会禁用一些涉及在运算中重排操作数的潜在优化。你可以在 GCC 和 Clang 中用 `-ffast-math` 标志关闭这种严格的符合性要求。如果加上它再重新编译上面的代码片段，程序运行会[快得多](/hpc/simd/reduction)，而且恰好会输出正确的结果 33554432（不过你需要意识到，编译器也可能选择一条精度更低的计算路径）。

### 舍入模式

除了默认模式（也称为银行家舍入）之外，你还可以用 4 种模式[设置](https://www.cplusplus.com/reference/cfenv/fesetround/)其他舍入逻辑：

- 最近舍入（round to nearest），严格平局时总是朝远离零的方向舍入；
- 向上舍入（朝 $+∞$；因此负数结果会朝零的方向舍入）；
- 向下舍入（朝 $-∞$；因此负数结果会远离零舍入）；
- 朝零舍入（对二进制结果做截断）。

例如，如果在运行上面的循环之前调用 `fesetround(FE_UPWARD)`，输出将不是 $2^{24}$，甚至不是 $2^{25}$，而是 $67108864 = 2^{26}$。这是因为当我们到达 $2^{24}$ 时，$(x + 1)$ 开始舍入到下一个最近的可表示数 $(x + 2)$，于是只用一半的时间就到达 $2^{25}$；之后 $(x + 1)$ 向上舍入到 $(x+4)$，我们开始以四倍的速度增长。

备选舍入模式的一个用途是诊断数值不稳定性。如果算法在切换到向正无穷与向负无穷舍入时结果差异显著，就说明它对舍入误差很敏感。

这个测试通常比把所有计算切换到更低精度、再检查结果是否变化过大更好，因为默认的最近舍入策略在足够多的平均后会收敛到正确的“期望”值：一半时间的误差是向上舍入，另一半是向下舍入——因此从统计上看，它们会相互抵消。

### 误差的度量

让执行自然对数、平方根等复杂计算的硬件提供这样的保证似乎令人惊讶，但事实就是如此：所有运算都能保证给出尽可能高的精度。这让我们分析舍入误差变得异常容易，稍后你会看到。

度量计算误差有两种自然的方式：

* 制造硬件或编写符合规范的精确软件的工程师关心的是*末位单位（units in the last place，ulps）*，即精确实数值与实际计算结果之间能容纳多少个可表示数。
* 从事数值算法的人关心的是*相对精度（relative precision）*，即近似误差的绝对值除以真实答案：$|\frac{v-v'}{v}|$。

无论哪种情况，分析误差的常用策略都是假设最坏情况，然后简单地给出上界。

如果你执行单个基本算术运算，那么最坏的情况就是结果舍入到最近的可表示数，这意味着误差不超过 0.5 ulps。要以同样的方式分析相对误差，我们可以定义一个称为*机器精度（machine epsilon）*的数 $\epsilon$，它等于 $1$ 与下一个可表示值之差（即 2 的负尾数位数次幂）。

这意味着，如果一次算术运算后得到结果 $x$，那么真实值位于区间内的某处

$$
[x \cdot (1-\epsilon),\; x \cdot (1 + \epsilon)]
$$

在根据浮点计算的结果做出离散的“是/否”决策时，尤其要记住误差无处不在。例如，下面是这样检查相等性的：

```c++
const float eps = std::numeric_limits<float>::epsilon; // ~2^(-23)
bool eq(float a, float b) {
    return abs(a - b) <= eps;
}
```

`eps` 的值应当取决于应用场景：上面这个——`float` 的机器精度——只适用于不超过一次浮点运算的情况。

### 区间算术

如果一个算法的误差（无论其来源如何）在计算过程中不会显著增大，就称它是*数值稳定（numerically stable）*的。这只有在问题本身是*良态（well-conditioned）*时才会发生，即输入数据发生微小变化时，解也只发生微小变化。

在分析数值算法时，采用实验物理学中常用的方法往往很有用：不去处理未知的真实值，而是处理它们可能位于的区间。

例如，考虑这样一串操作：我们让一个变量连续乘以任意实数：

```cpp
float x = 1;
for (int i = 0; i < n; i++)
    x *= a[i];
```

第一次乘法之后，$x$ 相对真实乘积的值被 $(1 + \epsilon)$ 界定，之后每多乘一次，这个上界就再乘一个 $(1 + \epsilon)$。由归纳可知，$n$ 次乘法后，计算值被 $(1 + \epsilon)^n = 1 + n \epsilon + O(\epsilon^2)$ 界定，下界也类似。

这意味着相对误差为 $O(n \epsilon)$，这还算可以，因为通常 $n \ll \frac{1}{\epsilon}$。

作为数值*不稳定*计算的例子，考虑函数

$$
f(x, y) = x^2 - y^2
$$

假设 $x > y$，这个函数能返回的最大值约为

$$
x^2 \cdot (1 + \epsilon) - y^2 \cdot (1 - \epsilon)
$$

对应的绝对误差为

$$
x^2 \cdot (1 + \epsilon) - y^2 \cdot (1 - \epsilon) - (x^2 - y^2) = (x^2 + y^2) \cdot \epsilon
$$

因此相对误差为

$$
\frac{x^2 + y^2}{x^2 - y^2} \cdot \epsilon
$$

如果 $x$ 和 $y$ 的量级接近，误差将为 $O(\epsilon \cdot |x|)$。

在直接计算中，减法会“放大”平方运算的误差。但可以用下面的公式来修正：

$$
f(x, y) = x^2 - y^2 = (x + y) \cdot (x - y)
$$

对后者，容易证明误差被 $\epsilon \cdot |x - y|$ 界定。它也更快的，因为它只需要 2 次加法和 1 次乘法：与原来的做法相比，多了一次快速的加法，少了一次慢速的乘法。

### Kahan 求和

从前面的例子可以看出，长的操作链并不是问题，问题在于把不同量级的数相加或相减。处理这类问题的通用方法是尽量让大数和大数在一起、小数和小数在一起。

考虑标准的求和算法：

```c++
float s = 0;
for (int i = 0; i < n; i++)
    s += a[i];
```

由于我们做的是求和而不是乘法，它的相对误差不再仅仅被 $O(\epsilon \cdot n)$ 界定，而是严重依赖输入。

在最离谱的情况下，如果第一个值是 $2^{24}$，其余的值都等于 $1$，那么无论 $n$ 是多少，总和都会是 $2^{24}$。执行下面的代码并观察它两次打印出 $16777216 = 2^{24}$ 即可验证：

```cpp
const int n = (1<<24);
printf("%d\n", n);

float s = n;
for (int i = 0; i < n; i++)
    s += 1.0;

printf("%f\n", s);
```

这是因为 `float` 只有 23 个尾数位，所以 $2^{24} + 1$ 是第一个无法精确表示、必须向下舍入的整数，而每次我们试图往 $s = 2^{24}$ 上加 $1$ 时这都会发生。误差确实是 $O(n \cdot \epsilon)$，但这是绝对误差而非相对误差：在上面的例子中，它是 $2$，而且如果最后一个数恰好是 $-2^{24}$，它会一直增长到无穷大。

显而易见的解决办法是换成更大的类型，比如 `double`，但这并非真正可扩展的方法。一个优雅的解法是把没能加进去的部分存到一个单独的变量里，再把它加到下一个变量上：

```c++
float s = 0, c = 0;
for (int i = 0; i < n; i++) {
    float y = a[i] - c; // c is zero on the first iteration
    float t = s + y;    // s may be big and y may be small, losing low-order bits of y
    c = (t - s) - y;    // (t - s) cancels high-order part of y
    s = t;
}
```

这个技巧被称为 *Kahan 求和*。它的相对误差被 $2 \epsilon + O(n \epsilon^2)$ 界定：第一项来自最后一次求和，第二项则是因为我们每一步处理的都是小于 $\epsilon$ 的误差。

当然，一个不限于数组求和的更通用做法是切换到更精确的数据类型，比如 `double`，这也相当于把机器精度平方。此外，它还可以（某种程度地）通过把两个 `double` 变量捆绑在一起来扩展：一个用于存储值，另一个用于存储其无法表示的误差，从而让它们表示值 $a+b$。这种方法称为 double-double 算术，并且可以类似地推广，定义 quad-double 以及更高精度的算术。
