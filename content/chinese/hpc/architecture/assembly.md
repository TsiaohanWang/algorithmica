CPU 由*机器语言*控制，它其实就是一串二进制编码的指令，每条指令指定了

- 指令编号（称为*操作码* opcode），
- 它的*操作数*是什么（如果有的话），
- 以及把*结果*存放在哪里（如果会产生结果的话）。

机器语言还有一种对人类友好得多的表示形式，称为*汇编语言*：它用助记符来表示机器码指令，用符号名来表示寄存器和其他存储位置。

直接上手，下面是在 Arm 汇编中如何将两个数相加（`*c = *a + *b`）：

```nasm
; *a = x0, *b = x1, *c = x2
ldr w0, [x0]    ; load 4 bytes from wherever x0 points into w0
ldr w1, [x1]    ; load 4 bytes from wherever x1 points into w1
add w0, w0, w1  ; add w0 with w1 and save the result to w0
str w0, [x2]    ; write contents of w0 to wherever x2 points
```

同样的操作在 x86 汇编中是这样的：

```nasm
; *a = rsi, *b = rdi, *c = rdx 
mov eax, DWORD PTR [rsi]  ; load 4 bytes from wherever rsi points into eax
add eax, DWORD PTR [rdi]  ; add whatever is stored at rdi to eax
mov DWORD PTR [rdx], eax  ; write contents of eax to wherever rdx points
```

汇编语言非常简单，它与高级编程语言相比并没有多少语法构造。从上面的例子中你可以观察到：

- 程序是一系列指令，每条指令写作它的名字后跟数量不等的操作数。
- `[reg]` 语法用于「解引用」寄存器中存储的指针，而在 x86 上你还需要加上大小信息作为前缀（这里的 `DWORD` 表示 32 位）。
- `;` 符号用于行注释，类似于其他语言中的 `#` 和 `//`。

汇编是一种非常精简的语言，因为它必须如此。它尽可能贴近机器语言，甚至到了机器码与汇编几乎一一对应的程度。事实上，你可以通过称为*反汇编*[^disassembly] 的过程，把任何编译好的程序还原成汇编形式——尽管像注释这类非必要的内容不会被保留。

[^disassembly]: 在 Linux 上，要反汇编已编译的程序，可以调用 `objdump -d {path-to-binary}`。

注意，上面两段代码不只是语法不同。它们都是编译器生成的优化代码，但 Arm 版本用了 4 条指令，而 x86 版本只用了 3 条。`add eax, [rdi]` 这条指令就是所谓的*融合指令*（fused instruction），它把一次加载和一次加法合并成一条指令完成——这是 [CISC](../isa#risc-vs-cisc) 路线所能提供的好处之一。

由于这两种体系结构之间的差异远不止这一点，从本章起以及本书的其余部分，我们将只提供 x86 的例子——这大概也是大多数读者要优化的目标，尽管我们介绍的许多概念是与体系结构无关的。

### 指令与寄存器

出于历史原因，大多数汇编语言中的指令助记符都非常简短。在过去人们手写汇编、反复输入同一组常见指令的年代，少敲一个字符就能离精神错乱远一步。

例如，`mov` 表示「存储/加载一个字」，`inc` 表示「加 1」，`mul` 表示「相乘」，`idiv` 表示「整数除法」。你可以通过指令名在[某个 x86 参考手册](https://www.felixcloutier.com/x86/)中查找其描述，但大多数指令的含义与你猜想的一致。

大多数指令会把结果写入第一个操作数，该操作数也可以参与计算，就像我们之前看到的 `add eax, [rdi]` 例子那样。操作数可以是寄存器、常量值或内存位置。

**寄存器**的名字为 `rax`、`rbx`、`rcx`、`rdx`、`rdi`、`rsi`、`rbp`、`rsp` 以及 `r8`-`r15`，总共 16 个。「带字母」的那些寄存器这样命名是出于历史原因：`rax` 是「累加器」（accumulator），`rcx` 是「计数器」（counter），`rdx` 是「数据」（data）等等——当然，它们并不只能用于这些用途。

还有 32 位、16 位和 8 位的寄存器，名字与之类似（`rax` → `eax` → `ax` → `al`）。它们并不是完全独立的，而是*别名*关系：`rax` 的低 32 位是 `eax`，`eax` 的低 16 位是 `ax`，依此类推。这样做是为了在保持兼容性的同时节省芯片面积，这也是编译语言中基本类型转换通常零开销的原因。

这些还只是*通用*寄存器，除了[某些例外情况](../functions)外，你可以在大多数指令中随意使用它们。此外还有一组用于[浮点运算](/hpc/arithmetic/float)的独立寄存器、一批用于[向量扩展](/hpc/simd)的极宽寄存器，以及少数[控制流](../loops)所需的特殊寄存器，不过我们会在合适的时候讲到它们。

**常量**就是整数或浮点值：`42`、`0x2a`、`3.14`、`6.02e23`。它们更常被称为*立即数*（immediate value），因为它们是直接嵌入机器码里的。由于这可能会大大增加指令编码的复杂度，有些指令不支持立即数，或者只允许使用固定的一部分立即数。某些情况下，你不得不先把常量值加载到寄存器中，然后再用它代替立即数。

除了数值之外，还有字符串常量，例如 `hello` 或 `world\n`，它们有自己的一小部分操作，不过这算是汇编语言中比较冷僻的角落，我们就不在这里探讨了。

### 移动数据

有些指令可能助记符相同，但操作数类型不同，此时它们被视为不同的指令，因为它们执行的操作略有差异、执行时间也不同。`mov` 指令就是一个生动的例子，它有大约 20 种不同形式，都与移动数据有关：要么在内存和寄存器之间移动，要么只在两个寄存器之间移动。尽管名为「move」，它并不是把值*移动*进寄存器，而是*复制*，保留原值。

当用于在两个寄存器之间复制数据时，`mov` 指令实际上会在内部执行*寄存器重命名*（register renaming）——告知 CPU 寄存器 X 所引用的值其实存储在寄存器 Y 中——除了读取和译码指令本身之外，不会造成任何额外延迟。出于同样的原因，交换两个寄存器的 `xchg` 指令也无需任何代价。

正如我们上面看到的融合 `add` 那样，并非每次内存操作都必须用 `mov`：一些算术指令恰好支持把内存位置作为操作数。

### 寻址方式

内存寻址通过 `[]` 运算符完成，但它能做的远不止把寄存器中存储的值重新解释为内存位置。地址操作数最多接受 4 个参数，语法如下：

```
SIZE PTR [base + index * scale + displacement]
```

其中 `displacement` 必须是整数常量，`scale` 只能是 2、4 或 8。它的作用是计算指针 `base + index * scale + displacement` 并解引用它。

<!-- 你可以按任意顺序使用它们：汇编器会自己弄明白。 -->

与直接解引用指针相比，使用复杂寻址[最多慢一个周期](/hpc/cpu-cache/pointers)，当你例如有一个结构体数组、想加载其第 $i$ 个元素的某个字段时，它会很有用。

寻址运算符需要加上大小说明符作为前缀，指明需要多少位数据：

- `BYTE` 表示 8 位
- `WORD` 表示 16 位
- `DWORD` 表示 32 位
- `QWORD` 表示 64 位

还有一种更罕见的 `TBYTE`，用于 [80 位](/hpc/arithmetic/float)，以及 `XMMWORD`、`YMMWORD` 和 `ZMMWORD`，分别用于 [128、256 和 512 位](/hpc/simd)。这些类型不一定要大写，但大多数编译器就是这么输出的。

地址计算本身常常很有用：`lea`（「load effective address」，加载有效地址）指令在一个周期内计算出操作数的内存地址并存进寄存器，而不进行任何实际的内存操作。虽然它本来的用途是计算内存地址，但它也经常被当作算术技巧使用，否则就需要 1 次乘法和 2 次加法——例如，你可以用它乘以 3、5 和 9。

它还经常充当 `add` 的替代品，因为如果需要把结果移到别处，它不需要单独的 `mov` 指令：`add` 只能工作在双寄存器模式 `a += b` 下，而 `lea` 让你可以写 `a = b + c`（如果其中一个是常量，甚至可以写 `a = b + c + d`）。

### 另一种语法

实际上有多种*汇编器*（把汇编翻译成机器码的程序），对应不同的汇编语言，但目前只有两种 x86 语法被广泛使用。它们通常以使用过它们、并在那个时代对编程产生过主导影响的两家公司命名：

- *AT&T 语法*，所有 Linux 工具默认使用。
- *Intel 语法*，嗯，Intel 默认使用。

这两种语法有时也分别被称为 *GAS* 和 *NASM*，取自使用它们的两种主要汇编器的名字（*GNU Assembler* 和 *Netwide Assembler*）。

本章我们使用了 Intel 语法，本书其余部分也会优先使用它。作为对比，下面是同一个 `*c = *a + *b` 例子在 AT&T 汇编中的写法：

```asm
movl (%rsi), %eax
addl (%rdi), %eax
movl %eax, (%rdx)
```

关键差异可以总结如下：

1. 用*最后一个*操作数来指定目的地。
2. 寄存器和常量分别需要加上 `%` 和 `$` 前缀（例如 `addl $1, %rdx$ 使 `rdx` 加 1）。
3. 内存寻址的写法是 `displacement(%base, %index, scale)`。
4. `;` 和 `#` 都可以用作行注释，`/* */` 可以用作块注释。

而且，最重要的是，在 AT&T 语法中，指令名需要加「后缀」（`addq`、`movl`、`cmpq` 等）来指定所操作的操作数大小：

- `b` = 字节（8 位）
- `w` = 字（16 位）
- `l` = 长（32 位整数或 64 位浮点数）
- `q` = 四字（64 位）
- `s` = 单精度（32 位浮点数）
- `t` = 十字节（80 位浮点数）

在 Intel 语法中，这些信息是从操作数推断出来的（这也是为什么你还需要指定指针的大小）。

大多数生成或消费 x86 汇编的工具都支持这两种语法，所以你可以随便选一个自己喜欢的，不必担心。
