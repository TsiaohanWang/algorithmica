作为软件工程师，我们无比热爱构建和使用抽象。

想象一下加载一个 URL 时要发生多少事情。你在键盘上输入一些东西；按键以某种方式被操作系统检测到并发送给浏览器；浏览器解析 URL 并请求操作系统发起网络请求；然后是 DNS、路由、TCP、HTTP 以及所有其他 OSI 分层；浏览器解析 HTML；JavaScript 施展魔法；页面的一种表示被送往 GPU 进行渲染；图像帧被送往显示器……而其中每一步可能还涉及过程中几十个更具体的操作。

抽象帮助我们把所有这些复杂性归结为一个*接口*（interface），它描述某个*模块*能做什么，而不固定具体的实现。这带来了双重好处：

- 从事高层模块开发的工程师只需要知道（小得多的）接口。
- 从事模块本身开发的工程师获得了优化和重构其实现的自由，只要它符合自己的*契约*（contract）。

硬件工程师同样热爱抽象。CPU 的抽象称为*指令集架构*（instruction set architecture，ISA），它从程序员的角度定义计算机应该如何工作。与软件接口类似，它让计算机工程师能够在现有 CPU 设计上持续改进，同时也让它的使用者——也就是我们程序员——确信以前能用东西不会在新芯片上出问题。

ISA 本质上定义了硬件应该如何解释机器语言。除了指令及其二进制编码之外，ISA 还定义了寄存器的数量、大小和用途、内存模型以及输入/输出模型。与软件接口类似，ISA 也是可以扩展的：事实上，它们经常更新，而且大多是向后兼容的，以添加新的、更专门的、能提升性能的指令。

### RISC 与 CISC

历史上，曾有许多相互竞争的 ISA 在使用。但不同于[字符编码和即时通讯协议](https://xkcd.com/927/)，开发和维护一套完全独立的 ISA 代价高昂，因此主流 CPU 设计最终收敛到了两大系列之一：

- **Arm** 芯片，几乎所有移动设备以及其它类似计算机的设备（如电视、智能冰箱、微波炉、[汽车自动驾驶系统](https://en.wikipedia.org/wiki/Tesla_Autopilot)等）都在使用。它们由一家同名的英国公司以及包括苹果和三星在内的一些电子产品制造商设计。
- **x86**[^x86] 芯片，几乎所有服务器和台式机都在使用，少数著名例外包括苹果的 M1 MacBook、AWS 的 Graviton 处理器，以及目前[全球最快的超级计算机](https://en.wikipedia.org/wiki/Fugaku_(supercomputer))，它们全都采用基于 Arm 的 CPU。它们由 Intel 和 AMD 双头垄断设计。

[^x86]: x86 的现代 64 位版本被称为「AMD64」「Intel 64」，或者更中立的叫法「x86-64」或简称「x64」。Arm 的类似 64 位扩展被称为「AArch64」或「ARM64」。在本书中，我们直接用「x86」和「Arm」来指代 64 位版本。

它们之间的主要区别在于体系结构的复杂度，这更像是一种设计哲学，而不是某种严格定义的属性：

- Arm CPU 是*精简*指令集计算机（RISC）。它们通过保持指令集精简且高度优化来提升性能，尽管一些不太常见的操作不得不借助包含多条指令的子程序来实现。
- x86 CPU 是*复杂*指令集计算机（CISC）。它们通过添加许多专门的指令来提升性能，其中有些在实际程序中可能很少用到。

RISC 设计的主要优势是能造出更简单、更小的芯片，这可以转化为更低的制造成本和功耗。市场因此自发地分化也就不足为奇了：Arm 主导着电池供电的通用设备，而把复杂的神经网络和伽罗瓦域计算留给服务器级别的、高度专用的 x86。
