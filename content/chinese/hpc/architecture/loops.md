我们来考虑一个稍微复杂一点的例子：

```nasm
loop:
    add  edx, DWORD PTR [rax]
    add  rax, 4
    cmp  rax, rcx
    jne  loop
```

它计算一个 32 位整数数组的和，就像简单的 `for` 循环那样。

循环的「循环体」是 `add edx, DWORD PTR [rax]`：这条指令从迭代指针 `rax` 处加载数据并加到累加器 `edx` 上。接着，我们用 `add rax, 4` 把迭代指针向前移动 4 字节。然后，稍微复杂一点的事情发生了。

### 跳转

汇编没有高级语言中的 if、for、函数或其他控制流结构。它有的是 `goto`，也就是底层编程世界里所说的「跳转」（jump）。

**跳转**把指令指针移动到其操作数指定的位置。这个位置可以是内存中的绝对地址、相对于当前地址的偏移，甚至是[运行时计算出来的](../indirect)。为了避免直接管理这些地址的麻烦，你可以用「字符串后跟 `:`」的写法给任何指令做标记，然后在转换机器码时用这个字符串作为标签，替换成该指令的相对地址。

标签可以是任意字符串，但编译器并不发挥创意，[通常](https://godbolt.org/z/T45x8GKa5)只是用源代码中的行号和带签名的函数名来选标签名。

**无条件**跳转 `jmp` 只能用来实现 `while (true)` 之类的循环，或者把程序的各个部分缝合起来。一系列的**条件**跳转则用来实现真正的控制流。

很自然地会认为这些条件是在某处作为 `bool` 计算出来、再作为操作数传给条件跳转的：毕竟在编程语言里就是这样工作的。但硬件并不是这样实现的。条件操作使用一个特殊的 `FLAGS` 寄存器，它首先需要通过执行某种检查指令来填充。

在我们的例子中，`cmp rax, rcx` 比较迭代指针 `rax` 和数组末尾指针 `rcx`。这更新了 `FLAGS` 寄存器，现在 `jne loop` 就可以使用它了：它查看其中某个位，判断两个值是否相等，然后要么跳回开头，要么继续执行下一条指令，从而跳出循环。

### 循环展开

你可能会注意到上面的循环有一个问题：处理单个元素有大量开销。每个周期只有一条有用的指令被执行，其余 3 条都是在递增迭代指针、判断是否结束。

我们能做的是*展开*（unroll）循环，把多次迭代归成一组——等价于在 C 中写这样的代码：

```c++
for (int i = 0; i < n; i += 4) {
    s += a[i];
    s += a[i + 1];
    s += a[i + 2];
    s += a[i + 3];
}
```

在汇编中，它大致长这样：

```nasm
loop:
    add  edx, [rax]
    add  edx, [rax+4]
    add  edx, [rax+8]
    add  edx, [rax+12]
    add  rax, 16
    cmp  rax, rsi
    jne  loop
```

现在 4 条有用的指令只需要 3 条循环控制指令了（效率从 $\frac{1}{4}$ 提高到 $\frac{4}{7}$），而且可以继续这样展开，几乎把开销降到零。

在实践中，展开循环并不总是性能所必需的，因为现代处理器并不是真的逐条执行指令，而是维护一个[待执行指令队列](/hpc/pipelining)，这样两条相互独立的操作可以在不互相等待的情况下并发执行。

我们这里也是如此：展开带来的真实加速不会是四倍，因为递增计数器、检查是否结束这些操作与循环体相互独立，可以和它并发调度。不过，[让编译器](/hpc/compilation/situational)在一定程度上展开循环可能仍然是有益的。

### 另一种做法

你并不一定要显式使用 `cmp` 或类似指令才能做条件跳转。许多其他指令也会读取或修改 `FLAGS` 寄存器，有时还顺带启用可选的异常检查。

例如，`add` 总是会设置一组标志位，表示结果是否为零、是否为负、是否发生上溢或下溢等等。编译器利用这种机制，经常生成这样的循环：

```nasm
    mov  rax, -100  ; replace 100 with the array size
loop:
    add  edx, DWORD PTR [rax + 100 + rcx]
    add  rax, 4
    jnz  loop       ; checks if the result is zero
```

这段代码对人类来说有点难读，但在重复执行的部分少了一条指令，这可能会对性能产生实际影响。
