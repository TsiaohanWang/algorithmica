---
title: 内存级并行
weight: 5
---

内存请求可以在时间上重叠：在你等待某个读请求完成的同时，还可以发出几个其他请求，它们会与前者并发执行。这就是为什么[线性迭代](../bandwidth)比[指针跳跃](../latency)快得多的主要原因：CPU 知道接下来需要取哪些内存位置，会提前很久发出内存请求。

并发内存操作的数量很大但有限，而且不同类型的存储，这个数量也不同。在设计算法尤其是数据结构时，你可能会想知道这个数字，因为它限制着你的计算能实现的并行度。

要在理论上算出某种特定存储类型的这个上限，可以把它的延迟（取回一条缓存行的时间）乘以其带宽（每秒取回的缓存行数），这样就得到了进行中的内存操作的平均数量：

![](../img/latency-bandwidth.svg)

L1/L2 缓存的延迟很小，所以不需要很长的待处理请求流水线，但容量更大的存储类型可以承受多达 25-40 个并发读操作。

### 直接实验

让我们通过修改指针追逐基准测试，更直接地测量可用的内存并行度：我们并行地环绕 $D$ 个独立的环循环，而不是只有一个：

```c++
const int M = N / D;
int p[M], q[D][M];

for (int d = 0; d < D; d++) {
    iota(p, p + M, 0);
    random_shuffle(p, p + M);
    k[d] = p[M - 1];
    for (int i = 0; i < M; i++)
        k[d] = q[d][k[d]] = p[i];
}

for (int i = 0; i < M; i++)
    for (int d = 0; d < D; d++)
        k[d] = q[d][k[d]];
```

固定环长度的总和为常数，取几个特定的大小，并尝试不同的 $D$，我们会得到略有不同的结果：

![](../img/permutation-mlp.svg)

正如预测的那样，L2 缓存运行受限于约 6 个并发操作，但容量更大的存储类型都在 13 到 17 之间封顶。你无法利用更多的内存通道，因为逻辑寄存器存在冲突。当通道数少于寄存器数时，每个通道只能发出一条读指令：

```nasm
dec     edx
movsx   rdi, DWORD PTR q[0+rdi*4]
movsx   rsi, DWORD PTR q[1048576+rsi*4]
movsx   rcx, DWORD PTR q[2097152+rcx*4]
movsx   rax, DWORD PTR q[3145728+rax*4]
jne     .L9
```

但当它超过约 15 时，你就不得不使用临时内存存储：

```nasm
mov     edx, DWORD PTR q[0+rdx*4]
mov     DWORD PTR [rbp-128+rax*4], edx
```

你并不总能达到内存并行的最大可能水平，但对大多数应用来说，一打并发请求已经绰绰有余了。
