内存被划分为 64 字节的[缓存行](../cache-lines)，这一事实使得操作跨越缓存行边界的数据字变得困难。当需要取回某个基本类型（例如 32 位整数）时，你确实希望它位于同一条缓存行内——因为取回两条缓存行既需要更多的内存带宽，而且在硬件中拼接结果也需要宝贵的晶体管面积。

这一方面深刻影响着算法设计，也影响着编译器如何选择数据结构的存储布局。

### 对齐分配

默认情况下，当你分配某种基本类型的数组时，可以保证所有元素的地址都是其大小的倍数，这确保它们只跨越一条缓存行。例如，可以保证 `int` 数组的第一个元素及每个元素的地址都是 4 字节（`sizeof int`）的倍数。

有时你需要确保最小对齐更高。例如，许多 [SIMD](/hpc/simd) 应用以 32 字节的块读写数据，而这 32 字节属于同一条缓存行对[性能至关重要](/hpc/simd/moving)。在这种情况下，可以在定义静态数组变量时使用 `alignas` 说明符：

```c++
alignas(32) float a[n];
```

若要动态分配内存对齐的数组，可以使用 `std::aligned_alloc`，它接受对齐值和数组的字节大小，并返回指向所分配内存的指针——就像 `new` 运算符一样：

```c++
void *a = std::aligned_alloc(32, 4 * n);
```

你还可以将内存对齐到[比缓存行更大](../paging)的尺寸。唯一的限制是大小参数必须是对齐值的整数倍。

你也可以在定义 `struct` 时使用 `alignas` 说明符：

```c++
struct alignas(64) Data {
    // ...
};
```

每当分配一个 `Data` 实例时，它都会位于缓存行的开头。缺点是该结构体的有效大小会向上取整到 64 字节的倍数。这样做是必要的，例如在分配 `Data` 数组时，不仅要保证第一个元素正确对齐。

### 结构体内存对齐

当我们需要分配一组类型不统一的元素（即结构体的情况）时，这个问题变得更加复杂。与其像玩俄罗斯方块那样试图重排 `struct` 的成员，使每个成员都位于同一条缓存行内——这并不总是可行，因为结构体本身并不一定要放在缓存行的开头——大多数 C/C++ 编译器同样依赖内存对齐机制。

结构体内存对齐同样保证其所有基本类型成员（`char`、`int`、`float*` 等）的地址都是其大小的倍数，从而自动保证每个成员只跨越一条缓存行。它通过以下方式实现：

- 必要时*填充*每个结构体成员，即插入数量可变的空白字节，以满足下一个成员的对齐要求；
- 将结构体本身的对齐要求设为其所有成员类型对齐要求的最大值，这样当分配该结构体类型的数组，或将其用作另一个结构体的成员类型时，其所有基本类型成员的对齐要求都能得到满足。

为了更好地理解，考虑下面这个简单的例子：

```cpp
struct Data {
    char a;
    short b;
    int c;
    char d;
};
```

如果紧凑存储，这个结构体每个实例总共需要 $1 + 2 + 4 + 1 = 8$ 字节，但即使假设整个结构体的对齐为 4 字节（其最大成员 `int` 的对齐），也只有 `a` 是合适的，而 `b`、`c` 和 `d` 都没有按大小对齐，可能跨越缓存行边界。

为了解决这个问题，编译器插入一些无名成员，使每个后续成员获得正确的最小对齐：

```cpp
struct Data {
    char a;    // 1 byte
    char x[1]; // 1 byte for the following "short" to be aligned on a 2-byte boundary
    short b;   // 2 bytes 
    int c;     // 4 bytes (largest member, setting the alignment of the whole structure)
    char d;    // 1 byte
    char y[3]; // 3 bytes to make total size of the structure 12 bytes (divisible by 4)
};

// sizeof(Data) = 12
// alignof(Data) = alignof(int) = sizeof(int) = 4
```

这可能会浪费空间，但能节省大量 CPU 周期。这种权衡大多是有益的，因此结构体内存对齐在大多数编译器中默认开启。

### 优化成员顺序

填充只在尚未对齐的成员之前或结构体末尾插入。通过改变结构体中成员的顺序，可以改变所需的填充字节数和结构体的总大小。

在前面的例子中，我们可以这样重排结构体成员：

```c++
struct Data {
    int c;
    short b;
    char a;
    char d;
};
```

现在，每个成员无需任何填充即可对齐，结构体的大小仅为 8 字节。结构体的大小乃至其性能竟然取决于成员定义顺序，这看起来有些愚蠢，但这是二进制兼容性所要求的。

经验法则：将类型定义按数据类型从大到小排列——这个贪心算法保证有效，除非你有一些奇怪的、大小不是 2 的幂的类型，例如[10 字节](/hpc/arithmetic/ieee-754#float-formats)的 `long double`[^extended]。

[^extended]: 80 位的 `long double` 至少占用 10 字节，但确切格式由编译器决定——例如，它可能将其填充到 12 或 16 字节以尽量减少对齐问题（64 位 GCC 和 Clang 默认使用 16 字节；你可以通过指定 `-mlong-double-64/80/128` 或 `-m96/128bit-long-double` [选项](https://gcc.gnu.org/onlinedocs/gcc/x86-Options.html)之一来覆盖此设置）。

### 结构体紧凑打包

如果你清楚自己在做什么，可以禁用结构体填充，将数据尽可能紧凑地打包。

这需要请求编译器来完成，因为该功能目前还不是 C 或 C++ 标准的一部分。在 GCC 和 Clang 中，通过 `packed` 属性实现：

```cpp
struct __attribute__ ((packed)) Data {
    long long a;
    bool b;
};
```

这使 `Data` 的实例只占用 9 字节，而不是对齐所要求的 16 字节，代价是读取其元素时可能需要取回两条缓存行。

### 位域

你还可以将打包与*位域*结合使用，位域允许你显式地将成员的大小按位固定：

```cpp
struct __attribute__ ((packed)) Data {
    char a;     // 1 byte
    int b : 24; // 3 bytes
};
```

这个结构体打包时占用 4 字节，填充时占用 8 字节。成员所占的位数不必是 8 的倍数，结构体总大小也不必是 8 的倍数。在 `Data` 数组中，当字节数为非整数时，相邻元素会被「合并」。它还允许你设置超过基本类型宽度的位宽，这起到填充的作用——不过在此过程中会抛出警告。

这个特性并不太常用，因为 CPU 没有 3 字节算术之类的东西，加载时必须进行低效的逐字节转换：

```cpp
int load(char *p) {
    char x = p[0], y = p[1], z = p[2];
    return (x << 16) + (y << 8) + z;
}
```

当存在非整数字节时，开销更大——需要通过移位和与掩码来处理。

这个过程可以通过加载一个 4 字节的 `int`，然后用掩码丢弃其最高位来优化。

```cpp
int load(int *p) {
    int x = *p;
    return x & ((1<<24) - 1);
}
```

编译器通常不会这样做，因为从技术上讲这是不合法的：那第 4 个字节可能位于你不拥有的内存页上，所以即使你打算立即丢弃它，操作系统也不会允许你加载它。
