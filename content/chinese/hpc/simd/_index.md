考虑下面这个小程序，它计算一个整数数组的和：

```c++
const int n = 1e5;
int a[n], s = 0;

int main() {
    for (int t = 0; t < 100000; t++)
        for (int i = 0; i < n; i++)
            s += a[i];

    return 0;
}
```

如果我们用普通的 `g++ -O3` 编译并运行它，整个过程在 2.43 秒内完成。

现在，让我们在最开头加上下面这条神奇的编译指令：

```c++
#pragma GCC target("avx2")
// ...the rest is the same as before
```

在同样的环境下编译并运行，整个过程在 1.24 秒内完成。这几乎快了一倍，而且我们没有改动一行代码，也没有改变优化级别。

这里发生的事情是，我们向编译器提供了一点关于这段代码所运行计算机的信息。具体来说，我们告诉编译器，目标 CPU 支持 x86 指令集的一个名为「AVX2」的扩展。AVX2 是 x86 众多所谓的「SIMD 扩展」之一。这些扩展包含的指令作用于特殊的寄存器，这些寄存器能够采用「单指令多数据」（single instruction, multiple data，SIMD）的方式容纳 128、256 乃至 512 位的数据。SIMD 指令不是处理单个标量值，而是把寄存器中的数据划分为 8、16、32 或 64 位的块，并对它们并行执行相同的操作，从而带来成比例的性能提升[^power]。

[^power]: 在某些 CPU 上，尤其是负载较重的 SIMD 指令会消耗更多能量，因此需要[降频](https://blog.cloudflare.com/on-the-dangers-of-intels-frequency-scaling/)来平衡总功耗，所以实时加速比并不总是成比例的。

![](img/simd.png)

这些扩展相对较新，CPU 对它们的支持是在保持向后兼容的前提下逐步实现的[^avx512]。除了加入更多专用指令之外，它们之间最重要的区别在于逐步引入越来越宽的寄存器。

具体来说，AVX2 提供了处理 256 位寄存器的指令，而 GCC 默认认为除了 128 位的 SSE2 之外没有启用任何更高级的指令集。因此，在告诉优化器它可以利用一次相加 8 个整数（而不是 4 个）的指令之后，性能提升了一倍。

[^avx512]: 从 AVX512 开始，向后兼容性不再被保持：出现了许多针对数据压缩、加密或机器学习等特定需求量身定制的不同「变体」。

![](img/intel-extensions.webp)

编译器通常能很好地用 SIMD 指令重写简单循环，就像上面的例子那样。这种优化被称为[自动向量化](auto-vectorization)，也是使用 SIMD 最流行的方式。

问题在于，它只对某些类型的循环有效，而且即便如此，结果也常常不是最优的。要理解它的局限，我们需要亲自动手，在更低的层次上探索这项技术——这正是本章要做的事。
