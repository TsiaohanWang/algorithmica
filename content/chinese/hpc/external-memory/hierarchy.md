现代计算机的内存高度层级化。它由多个速度和容量各异的*缓存层*构成，其中*较高*的层级通常存放*较低*层级中最常被访问的数据，以降低延迟：每一级通常比下一级快一个数量级，但也更小和/或更贵。

![](../img/hierarchy.png)

抽象地说，各种内存设备都可以描述为这样的模块：它们具有一定的存储容量 $M$，可以按大小为 $B$ 的块（而不是单个字节！）读写数据，并且完成读写所需的时间固定。

从这个角度看，每种内存都有几个重要特性：

- *总容量* $M$；
- *块大小* $B$；
- *延迟*，即取回一个字节所需的时间；
- *带宽*，它可能高于块大小乘以延迟，这意味着 I/O 操作可以「重叠」；
- *成本*，按均摊意义计算，包括芯片的价格、能耗、维护费用等。

下面是 2021 年常见消费级硬件的近似对比表：

| 类型 | $M$      | $B$ | 延迟 | 带宽 | $/GB/mo[^pricing] |
|:-----|:---------|-----|---------|-----------|:------------------|
| L1   | 10K      | 64B | 2ns     | 80G/s     | -                 |
| L2   | 100K     | 64B | 5ns     | 40G/s     | -                 |
| L3   | 1M/core  | 64B | 20ns    | 20G/s     | -                 |
| RAM  | GBs      | 64B | 100ns   | 10G/s     | 1.5               |
| SSD  | TBs      | 4K  | 0.1ms   | 5G/s      | 0.17              |
| HDD  | TBs      | -   | 10ms    | 1G/s      | 0.04              |
| S3   | $\infty$ | -   | 150ms   | $\infty$  | 0.02[^S3]         |

实际上，每种内存都有许多细节，我们接下来逐一介绍。

[^pricing]: 价格信息取自 [Google Cloud Platform](https://cloud.google.com/products/calculator?skip_cache=true)。
[^S3]: 云存储通常分为多个[层级](https://aws.amazon.com/s3/storage-classes/)，你访问数据的频率越低，价格就越便宜。

### 易失性存储器

RAM 层级及以上的所有存储都被称为*易失性存储器*，因为一旦断电或遭遇其他灾难，它们就无法保留数据。它们速度很快，因此被用于在计算机通电期间存储临时数据。

按从快到慢排列：

- **CPU 寄存器**——CPU 用来存放全部中间值的零开销数据单元——也可以看作一种内存类型。它们的数量有限（例如只有 16 个「通用」寄存器），在某些情况下，出于性能考虑，你可能会想把它们全部用上。
- **CPU 缓存**。现代 CPU 有多层缓存（L1、L2，通常还有 L3，偶尔甚至会有 L4）。最底层的缓存由所有核心共享，其大小通常随核心数按比例扩展（例如，10 核 CPU 大约应有 10M 的 L3 缓存）。
- **随机存取存储器**，它是第一种可大规模扩展的内存类型：如今你可以在公有云上租到配备半 TB RAM 的机器。你的大部分工作数据都应存放在这里。

CPU 缓存系统有一个重要的概念——*缓存行*，它是 CPU 与 RAM 之间数据传输的基本单位。在大多数架构上，缓存行的大小为 64 字节，这意味着所有主内存都被划分为 64 字节的块；每当你请求（读或写）一个字节时，无论你是否需要，都会一并取回它所在缓存行中的其余 63 个相邻字节。

CPU 层面的缓存根据缓存行的最近访问时间自动进行。当一条缓存行被访问时，其内容会被放置到最底层的缓存层，之后如果没有及时再次被访问，就会逐渐被逐出到更高的层级。程序员无法显式控制这一过程，但值得深入研究它的工作原理，我们将在[下一章](/hpc/cpu-cache)中详细讨论。

### 非易失性存储器

CPU 缓存和 RAM 中的数据单元只是存放少量几个电子（这些电子会周期性泄漏，需要定期刷新），而*非易失性存储器*类型的数据单元则存储数百个电子。这使数据能够在没有电源的情况下长时间存续，但代价是性能和耐用性——因为电子越多，它们与硅原子碰撞的机会也就越多。

持久化存储数据的方法有很多，但从程序员的角度看，主要有以下几种：

- **固态硬盘**。它们的延迟相对较低，约为 0.1ms（$10^5$ ns），但成本也很高，而且由于寿命有限——每个单元只能被写入有限次数——成本问题被进一步放大。移动设备和大多数笔记本电脑都使用这种存储，因为它体积小且没有机械部件。
- **机械硬盘**比较特殊，因为它们实际上是旋转的物理磁盘，上面装有读写磁头。要读取某个存储位置，你需要等待磁盘旋转到正确的位置，然后非常精确地把磁头移过去。这导致了一些非常奇怪的访问模式：随机读一个字节所花的时间，可能与读接下来 1MB 数据相同——通常是毫秒量级。硬盘是计算机中除散热系统外唯一拥有机械运动部件的部分，因此硬盘经常损坏（数据中心 HDD 的平均寿命约为 3 年）。
- **网络附属存储**，即利用网络上其他设备来存储数据的做法。它有两种不同的类型。第一种是网络文件系统（NFS），这是一种通过网络挂载另一台计算机文件系统的协议。另一种是基于 API 的分布式存储系统，最著名的是 [Amazon S3](https://aws.amazon.com/s3/)，它由公有云的一大批存储优化型机器支撑，内部通常使用廉价的 HDD 或某些更[小众](https://aws.amazon.com/storagegateway/vtl/)的存储类型。如果 NFS 位于同一数据中心，它的速度有时甚至比 HDD 还快；而公有云中的对象存储通常有 50-100ms 的延迟。它们通常高度分布式并做了多副本复制，以保证更高的可用性。

由于 SSD/HDD 比 RAM 慢得多，这一层级及以下的所有存储通常被称为*外部存储*。

与 CPU 缓存不同，外部存储可以被显式控制。这在很多情况下都很有用，但大多数程序员只想把它抽象掉，将其当作主内存的扩展来使用；操作系统通过[虚拟内存](../virtual)机制就能做到这一点。
