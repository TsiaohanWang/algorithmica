把两个数相加需要多长时间？`add` 是最常用的指令之一，执行它本身只需要一个周期。因此，如果数据已经加载到寄存器中，只需要一个周期就够了。

但在一般情况下（`*c = *a + *b`），我们首先需要从内存中取回操作数：

```nasm
mov eax, DWORD PTR [rsi]
add eax, DWORD PTR [rdi]
mov DWORD PTR [rdx], eax
```

当你从内存中获取任何数据时，数据到达之前总会存在一定的延迟。而且，请求并不会直达其最终存储位置，而是首先经过一个复杂的地址转换单元与缓存层系统——这套系统既有助于内存管理，也能降低延迟。

因此，这个问题的唯一正确答案是「看情况」——主要取决于操作数存储在哪里：

- 如果数据存储在主内存（RAM）中，取回它大约需要 ~100ns，也就是约 200 个周期，之后还要再花 200 个周期把它写回。
- 如果它最近被访问过，那么它很可能已被*缓存*，取回它所花费的周期数取决于它有多久没被访问了——最慢的缓存层大约需要 50 个周期，最快的缓存层大约需要 4-5 个周期。
- 但它也可能存储在某种*外部存储*上，例如硬盘；在这种情况下，访问它大约需要 5ms，也就是大约 $10^7$ 个周期（！）。

内存性能之所以有如此大的差异，是因为内存硬件并不遵循 CPU 芯片所遵循的[硅缩放定律](/hpc/complexity/hardware)。内存仍在通过其他方式不断改进，但如果 50 年前内存的时序与指令延迟大致处于同一量级，如今它们已经远远落后了。

![](img/memory-vs-compute.png)

为了不再成为限制因素，现代内存系统正变得越来越[层级化](hierarchy)，其中较高的层级以牺牲一部分容量为代价来换取更低的延迟。由于这些特性在各层级之间可能相差好几个数量级——尤其是在各类外部存储的情况下——对许多内存密集型算法来说，优先优化 I/O 操作已经变得至关重要。

这促使人们创建了一种新的成本模型，称为*外部存储模型*，它的唯一基本操作是块读写，其余一切操作——只要只涉及存储在容量有限的内存中的数据——代价都为零。它催生了一个激动人心的新研究领域——*外部存储算法*，我们将在本章中研究它。
